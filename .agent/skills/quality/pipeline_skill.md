# Pipeline Skill

The single entry point for every quality check, locally and in CI, is `scripts/ci/run-all-checks.sh`. This file is the **only definition of the stages**; every other document links here instead of repeating the table. The gate registry itself is data in `scripts/ci/pipeline.py` (`GATES`, `STAGES`, `COMPOSITE_STAGES`), and `python3 scripts/ci/pipeline.py --list` prints it.

## How a run works

1. `scripts/ci/run-all-checks.sh` calls `scripts/ci/build-and-test.sh`, which builds `docker/Dockerfile.quality` as `hcm-quality:local` (override with `HCM_IMAGE`; extra `docker build` flags from `HCM_DOCKER_BUILD_FLAGS`). With unchanged manifests the build takes seconds.
2. It starts the image as the calling user (`--user $(id -u):$(id -g)`), with `HOME=/tmp/hcm-home`, the repository mounted at the **same absolute path** (so coverage paths match Sonar's) and nothing else from the host. It forwards, by name only (never a value in argv), `PIPELINE_STAGE` (default `all`), `CI`, `GITLEAKS_LOG_OPTS`, `COMMIT_RANGE`, `E2E_SHARD`, `E2E_TIER`, `MAPBOX_PUBLIC_TOKEN` (the site build's URL-restricted `pk.` token; unset means the e2e placeholder) and `SONAR_TOKEN`.
3. Inside, `scripts/ci/in-container.sh` refuses to run unless `HCM_TEST_IMAGE=1` (set only by the image), then runs `python3 scripts/ci/pipeline.py --stage "$PIPELINE_STAGE"`.
4. `pipeline.py` first runs `npm ci --prefer-offline` from the npm cache baked into the image whenever `node_modules/.hcm-install-stamp` does not hold the SHA-256 of `package-lock.json` (delete the stamp to force it). Then it runs every gate of the stage in order, announced as `static 10/42 tsc`, and keeps going after a failure so one run lists every problem.
5. The run ends with `[SUCCESS] stage '<x>' passed (reports/pipeline/green-<x>.json)` (exit 0) or `[FAILURE] stage '<x>' failed: <stage>/<gate>, ...` (exit 1). The green marker records `{stage, head, status_sha256}`, the hash of `git status --porcelain=v1 --untracked-files=all`, which the pre-push hook checks.

## Running it

```bash
mkdir -p reports/pipeline
PIPELINE_STAGE=static bash scripts/ci/run-all-checks.sh > reports/pipeline/run.log 2>&1; echo "EXIT=$?"
grep -E '^\[(SUCCESS|FAILURE)\]|FAILED' reports/pipeline/run.log
```

- Read the verdict from a log file; never pipe the run through `tail` (the pipe's exit status would be `tail`'s).
- Pick the stage by change: docs or tooling only → `static`; TypeScript or Python → `static`, `tests`, `build`; before a push to `master` or a tag → `all`.
- Never edit `scripts/ci/run-all-checks.sh` while a run is in flight: bash reads it by offset and the run dies with an unrelated error.
- `reports/` is git-ignored: `reports/pipeline/green-*.json`, `reports/coverage/ts/` (lcov, json-summary), `reports/coverage/{scripts,pipeline}.xml`, `reports/junit/{vitest,pytest,pipeline}.xml`, `reports/gitleaks.json`, `reports/sonar/scanner.log`.
- `sonar` runs after `tests` inside `all`; run alone with a token, it stops before any upload unless the `tests` reports exist. `deps` and `contract` need the network and fail on drift by design (they open the weekly issues).

## Adding a gate

1. Pin the tool: an exact npm devDependency, an exact line in `scripts/ci/requirements.txt` (plus its transitive pins), or a digest-pinned binary copied in `docker/Dockerfile.quality`.
2. Add `Gate("<name>", (...))` to `GATES` in `scripts/ci/pipeline.py`. npm tools get a `package.json` script and run as `(*NPM_RUN, "<script>")`, so `package.json` stays the one place for their flags.
3. Add the name to the right tuple in `STAGES`: cheapest first, network-bound gates (`npm-audit`, `pip-audit`) last.
4. Run `python3 -m pytest` in the image: the registry tests reject unknown, duplicated or unstaged gates.
5. Update this file (*Stages*), `quality/ci_quality_gates_skill.md`, `docs/CI_PIPELINE.md` and the `quality-pipeline` skill and its mirror, in the same task.

## CI mapping (`.github/workflows/`)

- `ci.yml` (push to `master` and `v*` tags, pull requests to `master`, manual): `build-image` fills the GitHub Actions layer cache (`bash scripts/ci/build-and-test.sh` with `HCM_DOCKER_BUILD_FLAGS` set to the `type=gha` cache flags; the local composite action `.github/actions/quality-image` sets up Buildx and exposes the cache runtime). Every other job runs `PIPELINE_STAGE=<stage> bash scripts/ci/run-all-checks.sh`, whose own build loads the image from that cache: `static`, then `tests` (JUnit check, `coverage` artifact), `e2e` (matrix of `E2E_SHARD` values, `index/total`, forwarded into the container), `build` (`dist` artifact), then `sonarqube` (scan and quality-gate actions, then `scripts/ci/sonar_report.py` in the image; skipped with a notice without `SONAR_TOKEN` or `sonar-project.properties`). The deploy jobs (`deploy-pages`, `deploy-firebase`, `deploy-pipeline-image`) run only on `master` with the repository variable `DEPLOY_ENABLED` set to `true` (M2), through Workload Identity Federation (`GCP_WIF_PROVIDER`, `GCP_DEPLOY_SA`, `GCP_PROJECT_ID`, `GCP_REGION`).
- `release.yml` (`v*` tags): `PIPELINE_STAGE=release`, then the GitHub Release with `docs/releases/vX.Y.Z_github_description.md` as body and the engine and admin bundles attached.
- `deps.yml` and `contract.yml` (weekly, Monday): `PIPELINE_STAGE=deps` / `contract`; on failure the local action `.github/actions/upsert-issue` opens or updates one issue ("Dependency updates available", "Third-party contract drift").
- `codeql.yml`: CodeQL advanced setup, `security-extended`, languages `actions`, `javascript-typescript`, `python`.

No workflow runs a lint or test tool itself. Every action is pinned by full SHA with a `# vX.Y.Z` comment (`action-pins`), every job has `timeout-minutes` (`workflow-timeouts`); every workflow has top-level least-privilege `permissions`, every checkout `persist-credentials: false`, no `pull_request_target` and no `${{ }}` inside a `run:` script (`workflow-policy`). The runner is `ubuntu-24.04`, pinned. Details: `docs/CI_PIPELINE.md`.

## Tool bootstrap and pins

- Node 24.21.0 and npm 11.19.0 come from `node:24-bookworm-slim` (digest in `docker/Dockerfile.quality`); `engines` requires Node 24.12 or later and `.npmrc` sets `engine-strict` and `save-exact`.
- Python 3.14.4 is the GDAL base image's interpreter. CI tools live in the plain venv `/opt/hcm/venv` from `scripts/ci/requirements.txt` (every transitive dependency pinned). The raster pipeline has its own venv, `/opt/hcm/pipeline-venv` (`--system-site-packages` so `osgeo.gdal` is visible, `--without-pip`), filled from `pipeline/poetry.lock` by Poetry 2.5.1 in `/opt/hcm/poetry` (`pipeline/requirements-poetry.txt`); the pipeline's gates use it (`pipeline/README.md`).
- Playwright browsers live in `/ms-playwright`, the Firebase emulator JARs in `/opt/hcm/firebase-emulators`; JDK 21 serves the emulators.
- Every version and digest is listed in `docs/research/M0-handoff.md` → *Toolchain and pins* and summarised in `docs/CI_PIPELINE.md` → *Tool versions*.

## Latest stable dependencies and holds

Every dependency stays on its latest stable release; a deliberate hold is a `HELD` entry with its reason in `scripts/ci/check_dependency_updates.py`, repeated in `docs/CI_PIPELINE.md` → *Held dependencies*. A held pin that is behind is reported and passes; a hold whose version no longer matches its pin, that names no pin, or that is no longer needed fails `deps`, so a bump removes its hold in the same change. Current holds: `typescript@6.0.3` (`typescript-eslint@8.71.1` peers `typescript <6.1.0`; latest is 7.0.2), `@types/node@24.19.2` (follows the Node 24 runtime, not the 26.x line), the `node:24-bookworm-slim` image (the runtime line, with `engines`) and `mando==0.7.1` (`radon` 6.0.1 requires `mando <0.8`). Advisories are fixed with `overrides` in the root `package.json`, never with an allowlist; `deps` leaves the overrides to `npm audit`.

## Local tooling quirks

- Never run a gate with the host's Node 22 or Python: versions differ from the image and results do not count.
- The GDAL base preloads tcmalloc; the quality image sets `LD_PRELOAD=""` because Chromium aborts under it. Keep it.
- A browser crash in the container writes `core.<pid>` into the repository root; `.gitignore` covers `core.[0-9]*`.
- npm 11 warns that `protobufjs` and `re2` (from `firebase-tools`) run install scripts not yet covered by `allowScripts`; approve those two explicitly if a later npm blocks them.
- pytest with `-c pipeline/pyproject.toml` makes `pipeline/` the rootdir and then ignores `testpaths`: the `pipeline-pytest` gate passes `--rootdir .`. `testpaths` is rootdir-relative, `pythonpath` relative to the config file.
- pytest 9's `caplog` captures records even from a logger with `propagate = False`; prove non-propagation with a handler on the root logger instead.
- `python3 -m venv` seeds pip 25.1.1 (12 advisories); a venv that Poetry fills is created `--without-pip`.
- ruff N802 also checks `.pyi` stubs: GDAL's CamelCase API is stubbed as typed callable attributes (`pipeline/typings/osgeo/`), and the fake M2M server is a `wsgiref` app (no `do_POST`).
- Adding a workspace needs its `COPY <dir>/package.json <dir>/` line in `docker/Dockerfile.quality` (and an allowlist line in `.dockerignore` outside `packages/*`), or `npm ci` fails in the image build.
- Prettier 3 prints `<!doctype html>` and self-closing void tags (`<meta ... />`), which html-validate's recommended `doctype-style` and `void-style` rules reject, so no committed `.html` file can pass both `prettier` and `html-validate` today. The fix is `"extends": ["html-validate:recommended", "html-validate:prettier"]` in `.htmlvalidate.json`, an ask-first config edit. Until it is approved no `.html` file is committed: the site pages are generated by `scripts/site/src/page.ts` at build time (and checked with the html-validate library against `.htmlvalidate.json` in `scripts/site/test/page.test.ts`), and the harness pages are fulfilled by their specs (`e2e/specs/harness/`).
- Playwright answers a `page.route` before a `context.route`, and a later route before an earlier one: the firewall fixture is a context route registered first, so every mock wins over it.
- The quality image has a real `sonar-scanner` on `PATH` (`/usr/local/bin`). A test that removes its fake tool from its own `bin/` must also drop the image's directories from `PATH`, or the real tool runs (`scripts/ci/tests/test_sonar_scan.py` → `path_without_scanner`).
- `npm outdated --json --workspaces --include-workspace-root` prints `{}` with npm 11.19: the deps gate runs `npm outdated --json` (root) and `npm outdated --json --workspaces` separately. `npm outdated` exits 1 whenever something is outdated, so its JSON decides, not its status.
- GitHub's "latest release" of `github/codeql-action` is a `codeql-bundle-v2.x` bundle, not the action version: the deps gate reads `git/matching-refs/tags/v` (all `vX.Y.Z` tags, one request) instead.
- Prettier wraps an object entry longer than 140 columns after its key; for the i18n catalogues that breaks the one-line rule of the `i18n` gate. Keep messages short enough for one line.
- Node 24 strips TypeScript types natively, but our sources import `./x.js` and `@material/material-color-utilities` 0.4.0 imports without extensions: the JavaScript CLIs that load TypeScript (`scripts/seed/migrate-legacy.mjs`, `packages/ui/scripts/gen-theme.mjs`) register a `module.registerHooks` resolve hook that retries `.js` as `.ts` and appends `.js` to extensionless relative imports, then import dynamically. For the same reason the colour library is only reachable through the `@hcm/ui/dynamic-color` entry point: Vitest's node projects load npm dependencies with plain Node, and an engine or admin test that imported it through `@hcm/ui` failed with `Cannot find module …/dynamic_color`.
- `sonarjs/super-linear-regex` (ESLint) rejects patterns where two quantifiers can match the same text (`^\s*(\/?)\s*`); scan by hand with `indexOf` instead (`packages/shared/src/migration/html.ts`).
- Node 24 runs the site build and the e2e servers straight from TypeScript with `node --import ./scripts/site/register-ts.mjs <file>.ts` (a `.js` → `.ts` resolve hook); such files must use erasable syntax only (`erasableSyntaxOnly` in `scripts/site/tsconfig.json` and `e2e/tsconfig.json`).
- `sonarjs/code-eval` refuses `vm.runInNewContext`, so the site build reads `config.js` with the TypeScript parser (`scripts/site/src/config-js.ts`) and accepts one literal assignment only.
- A JSDoc comment that contains a glob with `**/` ends the comment at `*/`: write such globs in prose (Prettier then reports a parse error far from the cause).
- axe-core's CSSOM preload (for `css-orientation-lock`) writes `<style>` elements into a scratch document that inherits the page's CSP, so under the city sites' `style-src` it only logs violations: `e2e/support/a11y.ts` runs axe with `preload: false` and that rule off. `AxeBuilder.options()` replaces the run options, so call it before `withTags` and `disableRules`.
- Playwright's `getByRole` from a `role="dialog"` box does not find the dialog's slotted content (light-DOM children of the kit element): scope those queries to the element that renders the content.
- Playwright's default 30 s per test is too short for scenarios that walk several states of a SwiftShader map with eight pages in parallel: `e2e/projects.ts` gives the functional and a11y projects 60 s and the tour 120 s (its 3840 × 2160 frames). Locally (16 cores, 8 workers) the functional tier takes about eight minutes and the tour (309 tests) about nine.
- Node's HTTP server closes an idle keep-alive connection after 5 s; a request Playwright's API client sends on it at that moment fails with `ECONNRESET` ("socket hang up"), which the e2e firewall reports as a blocked request. The mock APIs and the site server set `keepAliveTimeout = 0` (`e2e/mock-apis/server.ts`).
- Chromium logs every failed resource load as a console error, also a callable's by-design 401 or 400 and a Google 404 for a resource not created yet; the e2e console guard takes such errors only as `expectedConsoleErrors` (text and URL, with the reason) or claimed by the spec that causes them (`consoleErrors.takeMatching`).
- The Firebase Functions emulator: every function runs in its own worker process (no shared memory); a v2 scheduled function has the `http` signature, so a Pub/Sub publish to its `firebase-schedule-*` topic does not run it (the e2e world posts to its trigger route, `…/triggers/us-central1-ops-tick-0`, the `-0` being the emulator's trigger generation); the Cloud Tasks emulator ignores a task's delay; without `serviceAccountId` the Admin SDK asks the absent metadata server on every enqueue and waits about 14 s; a rebuilt `functions/dist` is not reloaded reliably, so restart the emulators after a functions build.
- A mock server reused across Playwright runs (`reuseExistingServer` outside CI) keeps each test's partition of the fake upstreams and the consent stand-in's records under the same test id: the admin tier resets both when a test starts.
- The type declarations of the Firebase SDK's Firestore module name `Temporal`; with `skipLibCheck` off the admin's tsconfigs add the `esnext.temporal` lib.
- `Intl.NumberFormat` puts a no-break space (U+00A0) between amount and currency in `ro-RO` (tests compare with `\u00a0`); Prettier reflows long Lit templates, so element tests trim `textContent`; Lit's `live` directive is a dependency Vite optimises on first use (a cold-cache reload, `DECISIONS-for-review.md` §14), so the admin avoids it; `Object.assign` copies a getter's value, so a test double of `document.cookie` needs `Object.defineProperty`.
- A fixture file named `service-account.*.json` trips the repo policy's secret-file rule: name fake Google answers after their API (`cloud-storage/storage-agent.get.json`).
