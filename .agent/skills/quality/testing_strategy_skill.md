# Testing Strategy Skill

How every file of **Historic City Map** reaches 90 % or more per file (lines and branches), and how behaviour is proven from the outside. Background: `docs/research/design-review-testability.md` §3–§4; how to run the tiers: `docs/TESTING.md`.

## Seams and fakes (mock only external boundaries)

- **Map**: the engine core and the admin's editors see only the `MapPort` interface (`packages/ui/src/map/map-port.ts`, the `@hcm/ui/map` entry since CR-M2c-1); `packages/ui/src/map/mapbox-adapter.ts` is the only file that touches Mapbox GL, through the page's global `mapboxgl` and a structural type (`packages/ui/src/map/mapbox-types.ts`), never an import. Core tests drive a recording `FakeMap`, adapter tests a fake `mapboxgl` (`FakeMapboxGl`), both from `@hcm/test-support/fake-map` (`packages/test-support/src/fake-map.ts`, a subpath so `functions/test` without DOM types never loads it), and assert their calls. The drawing tools: the area stores use `FakeMapDraw` (`@hcm/test-support`); the Terra Draw adapter's unit tests a structural stand-in of Terra Draw (`packages/ui/test/map/draw/fake-terra-draw.ts`), and `terra-draw-real.test.ts` the real Terra Draw 1.38.0 and its Mapbox adapter on `FakeMapboxMap` with a real canvas, a linear projection and the handlers Terra Draw switches, driven by real `PointerEvent`s (`DECISIONS-for-review.md` §41b).
- **Viewer elements**: unit tests replace the kit elements with doubles (`packages/ui/test/viewer/doubles.ts`) and drive a `FakeStore`; `packages/ui/test/viewer/kit-integration.test.ts` runs the viewer with the real kit, which is where stacking and focus bugs between the two show. Test photos come from `seed/bucharest/derived/` through the Vitest server, so no test reaches the network.
- **Engine mount**: `packages/engine/src/mount.ts` is DOM-free behind `MountEnvironment`; `packages/engine/test/mount.test.ts` and `mount-browser.test.ts` drive it in node with a fake page.
- **Network**: a recording fake `fetch` passed in (the manifest loader, telemetry, every REST adapter of the functions) and, in e2e, the mock APIs. The upstream answers are one JSON file per call and outcome in `@hcm/test-support/api-fixtures` (`fixture`, `fixtureBody`, `fixtureResponse`; `{{name}}` placeholders; Google-key and access-token shapes assembled at run time). `createFakeFetch(handler)` records every call and rejects an unanswered one like a network failure; `routeTable([route(method, url, operation, answer)])` builds small upstreams for one adapter test; `createUpstreamFakes()` is a whole fake world (Google OAuth, Resource Manager, IAM, Billing, Budgets, Service Usage, Firebase Management, Secret Manager, Cloud Run, Cloud Tasks, Storage, Error Reporting, Mapbox, USGS M2M, Nominatim) with `scenario(name)`, `fail(service, mode)`, `state`, `calls`, `snapshot()`. Over HTTP, `startUpstreamServer` and `createUpstreamExtension()` (`@hcm/test-support/fakes/http`) serve the same world per test partition (`x-hcm-test`) with `/__upstream/…` control endpoints; the Functions emulator reaches them through `functions/src/adapters/emulator-fetch.ts`. Scenario credentials: `GOOGLE_TOKENS`, `MAPBOX_TOKENS`, `USGS_CREDENTIALS`. msw only if a test cannot inject `fetch`. The functions' in-memory port fakes (`createFakeDocumentStore` validating like the adapter, `createFakeAuthAdmin`, `createFakeBlobStore`, `createFakeTaskQueue`, `createFakeImageProcessor`, the Google, Mapbox and USGS ports, `testRuntimeConfig()`; each with `recorder.failNext`) live in `functions/test/support/`; fn-content's folders keep local copies with a movable clock (CR-M2-25, a mechanical follow-up).
- **Cloud services over REST**: Cloud Run Admin v2, Secret Manager, Resource Manager, Firebase Management and Error Reporting are called with `fetch`, never gRPC, so a fake `fetch` covers them; tokens come from a `TokenProvider` port (Resource Manager in `admin.claim` uses the caller's own token instead).
- **Ports** for everything else (`functions/src/ports/`): `DocumentStore`, `AuthAdmin`, `SecretStore`, `GoogleIam`, `FirebaseManagement`, `ErrorReporter`, `TaskQueue`, `BlobStore`, `ImageProcessor`, `MapboxApi`, `UsgsApi`, `Clock`; later `CloudRunJobs` and `Geocoder`. Owned modules are never `vi.mock`ed; owned ports get small fakes passed in. External libraries at the edge (`google-auth-library`, `firebase-functions/logger`) may be replaced with `vi.mock` in the composition root's test.
- **Time**: an injected `Clock`, `vi.useFakeTimers()`, Playwright `page.clock`. No sleeps, no wall clock.
- **Python**: `monkeypatch.setattr`, never global `sys.modules` mocks; the fake USGS M2M server on `127.0.0.1:0` with scenario state and `/__reset`; synthetic GeoTIFFs created per test in `tmp_path`.
- **Logging**: tests capture log output with `createRecordingSink()` from `@hcm/test-support`.

## Network isolation

- Python: `scripts/ci/tests/conftest.py` blocks every non-loopback socket.
- Chromium (Vitest browser and Playwright): `--host-resolver-rules=MAP * ~NOTFOUND, EXCLUDE 127.0.0.1, EXCLUDE localhost`.
- Playwright: a firewall route aborts every host outside the allowlist and fails the test; it proves the viewer never calls `firestore.googleapis.com` and never reaches real Mapbox or Google.
- **Test credentials encode the scenario** and are generated test values, never real ones: USGS `e2e-ok`, `e2e-m2m-pending`, `e2e-bad`; Mapbox `sk.e2e-trial`, `sk.e2e-missing-scopes`; `pk.e2e-fake-token`. They are not JWT-shaped, so gitleaks stays quiet.

## Writing a test

1. Name it `happyPath_<behaviour>` or `badPath_<behaviour>` (TypeScript), `test_happy_path_<behaviour>` or `test_bad_path_<behaviour>` (Python).
2. Assert what the user sees: DOM text, ARIA role and name, a pixel probe on the map, a fake's recorded call. "It did not throw" is not an assertion.
3. Lit components: ``render(html`<hcm-...>`, host)`` in browser mode; locate with `page.getByRole`; check keyboard behaviour, RO and EN strings, window-class variants and reduced motion.
4. Cover a failure branch by causing the failure from outside (a 404 manifest, a revoked token, a 503 from USGS), not by calling a private function.
5. A user-visible behaviour also gets its happy and bad rows in `e2e/scenarios.json` (`quality/e2e_scenario_matrix_skill.md`).
6. A bug the test found goes into `docs/LESSONS.md`.

## The local stack (manual testing)

`npm run dev:stack` (`scripts/dev/dev-stack.sh`, `e2e/stack/`) is the e2e world for a person's browser: the admin and site servers of the e2e tiers behind the stack's routes, the mock APIs, the admin tier's emulators, a world seeded through the specs' own helpers. What it established (2026-10-24):

- **The Claude browser pane cannot register a service worker** ("An unknown error occurred when fetching the script": its network layer refuses the worker's script), **opens a `window.open` popup in place of its page** (the opener, which Google's consent answers, is lost) and, on this machine, **has no WebGL**. So the stack rewrites addresses with an in-page shim, not a worker (`e2e/stack/browser.ts`: `fetch`, `XMLHttpRequest`, `sendBeacon`, the loaders' `src`/`href`/`srcset` as properties and attributes, a prelude prepended to every script blob for Mapbox GL's worker; the servers rewrite the loading tags of the HTML they serve), opens the consent stand-in in a frame over the page (its CSP's `frame-src` gets the mock APIs' origin; the stand-in posts to its parent when it has no opener), and the map items of the manual plan run in Chrome.
- **One partition**: the browser's forwarded requests carry no `x-hcm-test`, so the browser and the Functions emulator share the fake upstreams' partition `''`, and the consent stand-in's grants land there.
- **Signals**: `npm run` does not pass SIGTERM through its shell, so the container runs `e2e/stack/main.ts` directly (`scripts/dev/in-stack.sh` execs it), which stops the emulators with SIGINT and waits for their clean shutdown. Like `run-all-checks.sh`, never edit `scripts/dev/dev-stack.sh` while a stack started from it runs (bash reads it as it goes: a syntax error at its end on stop).
- **Order**: the stack opens its admin and site ports only after the seed, so a browser opened as soon as a port answers (the Claude preview) finds the world ready; `--network host` puts the ports on the host's loopback, while a Playwright run of the pipeline has its own network.
- **The proof** is `bash scripts/dev/dev-stack.sh check` (`e2e/stack/check.ts`): headless Chromium with service workers blocked, like the pane, and a route that aborts and reports every request for a host off the machine.
- **M4's world** (2026-10-24): a scene to buy, an order watched (`usgs.markOrdered` from the seed), a version waiting for points with the stand-in's `suggestions`, and the inbox items of the server's own events; the check opens the scene to buy through the list with Free only off (a scene not ordered yet that the filter hides is not found by its address alone; an ordered one opens whatever the filters) and reads the inbox.
- **M5's world** (2026-10-25): a second city, Iași, made through the server's own `cities.create` and `setup.rotatePublicToken` (`e2e/stack/seed-cities.ts`), after `setup.saveMapbox` with the fake's bootstrap token: the Functions emulator keeps secrets in memory, so without that call no city made in the stack gets a viewer token and its manifest is refused (`city.mapbox.publicToken: validation.required` in `emulators.log`). Never seed Cluj-Napoca: the fake Nominatim finds only that name, which New city's walk needs. The site server answers `/<city>/` for every city of the emulators. The shim forwards an `<a download>` the page clicks itself (the export's signed address is on `storage.googleapis.com`; left alone it would have left the machine), never a link a person follows. Opening another city by its address reloads the admin by itself: a script that reloads too aborts its own navigation (`net::ERR_ABORTED`); wait for the city instead.

## Coverage rules

- **90 % or more per file**, lines and branches (Vitest also functions and statements), scored the Sonar way: `(covered lines + covered conditions) / (lines + conditions)`.
- Vitest's `coverage.include` lists each package's `src` explicitly; Vitest 5 never adds unlisted files.
- Re-export-only files (`packages/*/src/index.ts`) have no executable statements: v8 reports 0 of 0, which passes; the `coverage` gate (`scripts/ci/check_coverage.py`) treats a file with nothing to cover as covered.
- Exclusions only for generated files or files without runtime behaviour; `sonar.coverage.exclusions` stays empty.
- No decorators in Lit code: their helpers show up as uncovered branches.

## Gotchas found so far

- The colour library (`@material/material-color-utilities`, behind `@hcm/ui/dynamic-color`) imports its ES modules without file extensions, which Node refuses: a Node Vitest project that imports it inlines it (`server.deps.inline`, the `create-historic-city` project); the browser projects and Vite's builds resolve it themselves.
- zod 4 reports a missing enum or literal as `invalid_value`, not `invalid_type`: `validate` passes `reportInput: true` and treats an issue whose `input` is `undefined` as `validation.required`.
- Test images are built in memory (`scripts/seed/test/png.ts` writes a grey PNG with `node:zlib`), never committed as binaries.
- Coverage counts every `??`, `||`, `&&` operand and ternary as a branch (and ESLint's `complexity` also counts default parameters): a fallback that cannot happen (a regex group that always matches, the first element of a non-empty array) is an uncovered branch. Use `String(match[1])` or a typed tuple instead of `?? ''`.
- The GDAL base image preloads tcmalloc into every process and Chromium aborts under it; the quality image sets `LD_PRELOAD=""`.
- Lit's Node build shims `customElements`, so modules that register elements also load in node tests; it logs "Lit is in dev mode", which is harmless.
- typescript-eslint's `no-unused-vars` does not exempt `_`-prefixed parameters: omit unused parameters instead.
- A browser crash in the container writes `core.<pid>` into the repository root (git-ignored); delete it.
- The mock serves the Mapbox GL JS release of the installed `mapbox-gl` devDependency (`e2e/mock-apis/router.ts` reads its `package.json`): a bump of the library needs no e2e edit, and a version that must follow a pin is read from the pin, never repeated (`docs/LESSONS.md` #291).
- Mapbox GL 3.32 asks a `mapbox://sprites/…` sprite for `iconset.pbf` as well as `sprite.json`/`.png`, and draws a 256 px raster source at zoom 14 with zoom-15 tiles: the e2e mock answers both (an empty icon set), and specs never assume a tile zoom.
- Playwright's text locators (`getByText`, `hasText`) skip `<noscript>` content; locate a no-script note with CSS (`noscript p[lang="ro"]`).
- Map pixel probes read a screenshot square (`probeArea` in `e2e/support/map.ts`, the per-channel median of 7 × 7 CSS px, so a tile's z/x/y label or an antialiased edge does not decide) against the solid colours of `e2e/fixtures/world.ts`, and poll until the map shows the change (paint updates land one animation frame later). A translucent overlay is the linear blend of the overlay at 100 % and the map without it (`blend`): measure both ends under whatever covers the map (a modal sheet's scrim) and compare the middle. Where a coordinate is drawn comes from the live map (`screenPointOf`), never from hand-computed pixels; Mapbox zoom levels are 512 px tiles (0.4265 m per CSS px at zoom 17 in Bucharest).
- Mapbox GL treats a 404 tile as "no imagery here" and fires no `error` event: a tile outage in a test answers 5xx (the e2e broken tileset answers 503).
- Vitest browser mode's `toHaveTextContent` failed on a live region whose text also held a button label, and never matched a RegExp in the iframe: assert `element.textContent` with `toContain`, or a string.
- On a cold Vite cache a browser project re-optimises dependencies mid-run ("Vite unexpectedly reloaded a test", "Multiple versions of Lit loaded"); `npm ci` empties the cache, so CI always starts cold. `vitest.config.ts` pre-bundles `BROWSER_TEST_DEPS` for both browser projects (`DECISIONS-for-review.md` §14): a new Lit directive or browser-test dependency joins that list in the same change.
- firebase-admin's Google clients probe the GCE metadata server (a network call; `MetadataLookupWarning ... ETIMEDOUT`), which also pushed emulator tests past their 10-second hook timeouts on a busy machine: `scripts/ci/run-emulated-tests.sh` exports `METADATA_SERVER_DETECTION=none`.
- Real sharp on generated images: hand-made PNG headers test the pixel limit (never decoded) and broken pixels; incompressible test data comes from hash output (an LCG modulo 64 compresses well); the Storage emulator ignores `ifGenerationMatch`, so the conflict mapping is unit-tested.
- Prettier's line breaks pushed the fake upstreams past `max-lines-per-function`; a service's routes are built by helper functions.
- The viewer smoke (`S-V16-HAPPY`) fails on any console error, which is how a kit `styleMap` (a CSP violation) and the engine's missing `fonts/` (three 404s) were found: unit tests cannot see the page's CSP or the built `dist/`.
- The `ui` project's `packages/ui/test/map/adapter-env.test.ts` (the engine's browser project's file until CR-M2c-1 moved the map) runs what the Mapbox adapter takes from the page on a real Chromium (animation frames, ResizeObserver, the sprite canvas, the WebGL 2 probe), never a real map: a Mapbox map load is billed, and the e2e tier runs the real `mapbox-gl` behind its firewall.
- The `tools` project gives each test 30 s (`testTimeout`): its tests start Node processes and the admin build copies the 46 MB of legacy originals while every other project runs; in the old standalone `site-unit` run the 5 s default held, in the shared run one test timed out on a busy machine.
- The `shared`, `engine`, `admin` and `functions` projects share one module graph per worker (`isolate: false` through `SHARED_MODULE_GRAPH` in `vitest.config.ts`): no process start and no re-import per file, which took about a third off the `vitest` gate on four CPUs. Checked with every file of a project in one worker in shuffled orders (functions with fresh emulators each time, since its tests leave accounts behind), and with three and fifteen workers. Their tests restore what they change (fake timers in `afterEach`, `vi.unstubAllGlobals`, `vi.unstubAllEnvs`); Vitest restores mocks and resets `vi.setConfig` after each file, so a setting a test needs goes into its project in `vitest.config.ts`, never into a helper module (only the first file of a worker would evaluate it). A `vi.mock` would leak into the next file of the worker: the composition root's test (`functions/test/deps.test.ts`) runs alone in the isolated `functions-deps` project, and a new `vi.mock` elsewhere moves its file there or its project back to isolation.
- Emulator-backed tests get 60 s per test and hook: both functions projects through `EMULATOR_TIMEOUTS` in `vitest.config.ts`, the rules files through `firebase/rules-tests/test/support/world.ts` (the `rules` project is isolated). A first request on a fresh emulator connection takes seconds while the whole stage shares the emulators; `deps.test.ts` and `adapters/firestore.test.ts`, on Vitest's 5 s and 10 s defaults, failed under load and in a cold clone (`docs/LESSONS.md` #51).
- The rules world (`firebase/rules-tests/test/support/world.ts`) seeds through one `withSecurityRulesDisabled` call held open for the whole file (`holdOwner`): each call starts its own Firebase app and connection, which cost more than the write, and the longest rules files are the last to finish in the `vitest` gate. A rules test file ends with `await world.close()`, which ends that call and cleans up the environment.
- Vitest starts the Node projects' files one project after another, in alphabetical order of the project names (its `BaseSequencer`), so the emulator-backed `rules` files start late. Starting them first (a custom sequencer) measured slower, not faster: the Firestore emulator's JVM then competes with the Chromium projects for the CPU (`docs/research/pipeline-baseline.md`, the tests addendum).
- The Firestore emulator's delete-all answers 409 ABORTED ("Transaction lock timeout") while a background function of the previous admin test still holds a lock; the admin tier's reset tries it up to three times (`docs/LESSONS.md` #49).
- A snackbar closes itself 6 s after it shows: a spec that waits for something slow first (the map settling at 4K) focuses its close button at once, which keeps it open; not a hover, whose wait for stable frames can outlast the 6 s on a loaded 4K page (`docs/LESSONS.md` #50).
- The M2e gate (`docs/LESSONS.md` 144–148): a checker that is wrong at an edge is made exact with a unit test of both sides (the legal line's `legalGap`), never quieted; in the shared emulators a spec waits for the state's own signal of having settled (History's "Reconnecting…" gone), not for a value other tests change; and a page over a shared collection asks only its own documents on the server, so other tests cannot change its rows or its "Show more" at all (History's `cityId`, lesson 149); before `setOffline(true)` it waits until the page can do its next step (Save on), and a list answered from the cache offline is never taken as the truth by the code (146); before a new address it waits for the editor's own "Saved", not for the document in the emulator (148). An ad-hoc Playwright run after a `build` or `all` stage first runs `npm run build:site:e2e`: those stages leave the production admin in `packages/admin/dist`, which calls the real Functions host and fails every admin test.
- M6 (the Hosting workstream, 2026-10-25): the e2e projects block service workers (`serviceWorkers: 'block'` in `e2e/playwright.config.ts`); a spec that tests one allows them for itself (`test.use({ serviceWorkers: 'allow' })`, as `e2e/admin/specs/shell/admin-path.spec.ts` does). A page that Hosting serves at another address (the generic city page at `/<city>/`, rewritten to `/city/index.html`) loads its files by absolute path, or the browser asks `/<city>/config.js`; and a page script's fallback address is resolved against its own folder (`new URL(link || start, start)`), never `'/'`, which is the site's root (the push worker opened the public map instead of the admin until a test said so). Two Playwright runs in one tree each need their own `--output`.
- M6 (the installer and the integrator, 2026-10-30): the fake Cloud Build runs no step; a scenario plays each build (`cloud-build.start`, `.finish`, `.<target><Outcome>`) and a success changes the world as a real build would (the functions' `HCM_RELEASE`, the jobs on the image's digest, the site's `/release.json`, served by `followSiteRelease`). Wait for the submitted build (`submittedBuilds`) before moving it on; reopen a card after its step turns done (the page moves on); end a test only once no `setup.recordCloud` is under way (`trackRecords`, `recordsSettled`: a callable cut off holds `setup/status` in the emulator for a minute); seed a published manifest through the real publisher (`seedPublishedMap`), never a hand-written record. The whole Setup with no terminal is `e2e/admin/specs/journey.spec.ts` (S-A30-HAPPY-NO-TERMINAL): the viewer at the e2e Hosting root reads the e2e bucket's city folder, which `servePublishedMap` answers from the Storage emulator's real objects. Several agents running Playwright at once overwrite `reports/test-results`: give an ad-hoc run its own `--output`.
