# Analytics and Crash Reporting Skill

"Full Firebase support for crashes and analytics" (user request, `docs/research/PLAN.md` → *Addendum 2*), within the privacy and cost rules. Architecture summary: `docs/ARCHITECTURE.md` → *Analytics and crashes*.

## Analytics (GA4 for Firebase; Performance Monitoring in the admin only)

- GA4 in both the public viewer and the admin, through the analytics module of the Firebase JS SDK (`firebase` package). Performance Monitoring is not part of the public viewer (below); the admin, whose addresses hold no visitor position, may add it.
- **Loaded only after consent**: an M3 consent banner (RO/EN); Consent Mode v2 defaults denied; `analytics_storage` granted on accept. The decision is stored and can be withdrawn in About.
- The viewer still never reads Firestore: the Firebase app and analytics are lazy-loaded only when the manifest has a `measurementId` **and** the visitor consented. Code: `packages/engine/src/telemetry/` (`consent.ts`: the choice per city under `hcm:<cityId>:consent`, Consent Mode v2 starting denied; `analytics.ts`; `cookies.ts`; `errors.ts`; `telemetry.ts`; `firebase-sdk.ts`, the one lazy chunk with the Firebase app and analytics modules).
- Firebase Analytics refuses to start without the web app's `apiKey`, `appId` and `projectId`; until the manifest carries them (`city.analytics.firebase`, change request CR-9) the engine logs `analytics off` and sends nothing, so the consent banner shows but no GA request follows.
- **The viewer's Firebase app is always the named app `hcm-viewer`**, so an embedding page keeps its default app for its own Firebase (the default app was needed only by Performance Monitoring, `docs/LESSONS.md` #9).
- **Never the hash** (`docs/LESSONS.md` #24, `docs/research/DECISIONS-for-review.md` §18a): GA4 gets `page_location` (origin and path) and `page_path` on its configuration and `page_location` on every event, `send_page_view: false`, and `allow_google_signals` and `allow_ad_personalization_signals` false. Performance Monitoring sends `location.href` up to the first `?` (the whole hash: the map view, after *My location* the visitor's position) and has no setting against it, so it stays out of the public viewer. The GA4 web stream's enhanced measurement of history changes must be off (the viewer rewrites its hash with `history.replaceState` on every move): the provisioner's job (CR-M2-37 in `docs/research/M2-interfaces.md`).
- **Withdrawal expires the cookies** (`docs/LESSONS.md` #25, §18c): a change from granted to denied, with analytics configured, expires every `_ga` and `_ga_*` cookie host-only, for each parent domain and for every path prefix of the page (`cookies.ts`), at once and again after the SDK applied the denial; GA4 starts with the consent as it is when the chunk arrives. A first *Decline* touches no cookie: an embedding page may run its own GA4.
- The ES module build loads the SDK as its own chunk only after consent; the IIFE build inlines it (Rolldown has no code splitting for IIFE), about 24 KB gzip downloaded but not run before consent (CR-10, `docs/research/DECISIONS-for-review.md` §13a). The city pages load `engine.mjs`.
- Events: `page_view`, `layer_toggle`, `year_change`, `photo_open`, `poi_open` (PLAN Addendum 3), `share` (the store's `logShare()` after a completed share or copy, never a cancelled one), `compare_open`; admin flow events for setup steps and imports. Opacity slider moves are not events (too chatty, no product question behind them). **No PII**: no email, no free text, no precise visitor location.
- The `measurementId` is detected by the Setup Assistant card "Analytics and crash reporting" (`setup.analyticsConfig`: Firebase Management `webApps/{id}/config`, `fn-admin@` needs `roles/firebase.viewer`) and written with the web app's public ids to the city doc and the manifest; the admin accepts the GA terms on Google's page.

## Crashes (web equivalent of Crashlytics)

- Global `error` and `unhandledrejection` handlers plus Lit and engine error boundaries.
- After consent: GA4 `exception` events with the fatal flag.
- The reporter never throws, redacts like `createLogger` plus URL queries (a tile URL carries the Mapbox token), sends at most 5 reports per page and one per message per 10 s.
- Always (no PII, rate-limited): `telemetry.reportError`, a public HTTPS function that writes a redacted stack, release, viewport and window class as a structured log with `@type: type.googleapis.com/google.devtools.clouderrorreporting.v1beta1.ReportedErrorEvent`, so **Cloud Error Reporting** groups crashes, alerts on first sight and emails. Its contract (`docs/research/M2-interfaces.md` §3.4; schemas in `packages/shared/src/api/telemetry.ts`): the `Origin` must be a viewer or admin origin (403 otherwise, and the origin decides the service, `viewer` or `admin`), the body at most 16 KiB (413), at most 10 reports per client and 120 per instance per minute (429, counted in memory, never in Firestore), JSON sent as `text/plain` so the browser sends no preflight, validated with `errorReportSchema` (the engine's `ErrorReportPayload`), redacted again with `redactText` of `@hcm/shared`, and `context.reportLocation` always set so Error Reporting also groups Firefox and Safari stacks. The manifest builder puts its URL into every manifest as `analytics.errorEndpoint`, so crash reports work before analytics is set up.
- How the endpoint behaves (`functions/src/telemetry/`, CR-M2-12): a preflight (`OPTIONS`) from an unknown site gets 405, any method but `POST` 405, a foreign `Origin` 403 without CORS headers; every refusal after the origin check carries `Access-Control-Allow-Origin`, so the page can read the status. The per-client key is a salted hash of the last `X-Forwarded-For` hop, held in memory for the current minute only; with `maxInstances: 2` at most 2 × 120 reports a minute reach the logs project-wide. A stack frame's location is parsed **before** redaction (`redactText` drops a frame's `:line:col` together with its URL's query), Firefox and Safari stacks get the error message in front, and the accepted report becomes one structured ERROR entry (`write` of `firebase-functions/logger`), no Firestore write. It runs as `fn-events@` (a log entry needs no role).
- Source maps are uploaded as release artifacts for de-minification.
- Functions and the Cloud Run pipeline report through structured error logs.
- The Setup Assistant's "Crash reports" panel lists the latest Error Reporting groups through the admin callable `telemetry.listGroups` (Error Reporting `groupStats` over REST; `fn-admin@` needs `roles/errorreporting.viewer`): a 403 that names the disabled API answers `apiError.cloud.apiDisabled` with `{api}`, any other 403 `apiError.cloud.permission` with the role, anything else `apiError.errorReporting.unavailable`; every message is redacted again before it leaves.

## Tests

- Consent gating (`e2e/specs/viewer/consent.spec.ts`, V19): no GA or Firebase request before an answer or after "Decline" (the firewall and the mock APIs' record); "Accept" runs the **real** Firebase SDK against the mock APIs: the Firebase web config, Installations and a stand-in gtag.js (`e2e/mock-apis/gtag.ts`) that turns each logged event into a recorded `POST region1.google-analytics.com/g/collect?en=<event>&ep.<param>=…&dl=<page>` while `analytics_storage` is granted and the property is not disabled; withdrawing in About stops them. The manifest of these specs carries generated Firebase app ids (`E2E_FIREBASE_APP` in `e2e/fixtures/world.ts`, the API key assembled at run time so the source holds no Google-key-shaped string).
- Crash reports (`e2e/specs/viewer/crash-reporting.spec.ts`, V20): an error thrown into the page reaches the e2e telemetry endpoint redacted (no hash, query, token or e-mail), a down endpoint changes nothing visible, an error storm is capped at five reports, one per message.
- Privacy (`consent.spec.ts`): every GA4 hit's `dl` is the origin and path even after *My location* (the stand-in falls back to `location.href` like gtag.js, so a forgotten `page_location` would show), no request reaches the Performance Monitoring hosts (`S-V19-BAD-HASH-NEVER-SENT`); the stand-in writes `_ga` and `_ga_<container>` once consent is granted, and a withdrawal expires them while a first *Decline* leaves a page's own `_ga` (`S-V19-HAPPY-COOKIES-EXPIRED`, `S-V19-BAD-DECLINE-KEEPS-PAGE-COOKIES`).
- Unit tests: event payloads with the hash-free page location, the cookie expiry, a withdrawal during the SDK load, the error reporter's redaction and rate limit (`packages/engine/test/telemetry/`).
- The CSP lists the googletagmanager, google-analytics and firebaseinstallations hosts only for these SDKs (`web/web_security_skill.md`); the Performance Monitoring (`firebaselogging`) hosts left the site CSP with CR-M2-36 (`scripts/site/test/csp.test.ts` keeps them out).
- The endpoint: `functions/test/telemetry/` (`@S-A24-HAPPY`, `@S-A24-BAD-FOREIGN-ORIGIN`, `@S-A24-BAD-RATE-LIMITED`, `@S-A24-BAD-TOO-LARGE`, `@S-A24-BAD-INVALID-BODY`) through `.run()`, with the redaction of a frame pinned by `functions/test/telemetry/error-event.test.ts`.
