# Cloud Functions Skill

Firebase Functions v2 in TypeScript, workspace `@hcm/functions` (`functions/`), Node 24 runtime, region `us-central1` (Firestore `nam5`). Plan: `docs/research/PLAN.md` → *Cloud Functions*; contracts: `docs/research/M2-interfaces.md` (ownership, every function, every port, the change requests); testability: `docs/research/design-review-testability.md` §3.4; security: `docs/research/design-review-security-cost.md` §1.1–§1.2.

## Shape

```text
functions/src/index.ts          exports only: one group per registry namespace, built by its folder's factory
                                (`export const admin = adminFunctions(getDeps)` deploys `admin-session`, `admin-claim`, ...)
functions/src/global-options.ts setGlobalOptions({region: 'us-central1', maxInstances: 5, concurrency: 80, serviceAccount: 'fn-events@'});
                                RUNTIME_ACCOUNTS and runAs(name): the service account of every registry name
functions/src/deps.ts           composition root: runtimeConfig(env), privateBucket(env), one adapter per port, created on first use
functions/src/api/              callable plumbing: defineCallable, requireAccess, ApiError, toHttpsError; compact/omit (objects.ts)
functions/src/ports/            interfaces: DocumentStore, AuthAdmin, SecretStore, GoogleIam, FirebaseManagement, ErrorReporter,
                                TaskQueue, BlobStore, ImageProcessor, MapboxApi, UsgsApi, Clock, RuntimeConfig, AdminDirectory,
                                SetupRecords; `Ports` aggregates them, handlers take Pick<Ports, ...>; UpstreamError, InvalidDocumentError
functions/src/<family>/         one file per function: its thin trigger and its pure handler; `index.ts` is the family factory
                                (admin/ holds `admin.*` and `admins.*`; history, telemetry, setup, photos, publish, ops)
functions/src/adapters/*.ts     REST over fetch (Google APIs, Mapbox, USGS), firebase-admin (Firestore, Auth, Storage, task queue),
                                sharp (imported on the first photo); emulator-fetch.ts keeps the Functions emulator off real hosts
```

- **The registry is the contract**: `CALLABLES`, `HTTP_ENDPOINTS` and `BACKGROUND_FUNCTIONS` of `@hcm/shared` (`packages/shared/src/api/registry.ts`) name every function, its owner, its access rule (`signedIn` or `admin`; M5 adds `cityEditor`, `cityOwner` and `projectOwner`, checked after validation against `admins/{uid}.cities`: `docs/research/M5-interfaces.md` §1.3, planned), its App Check mode (`enforce`, or `consume` for ownership and secret pastes), its `maxInstances` and its zod request and response. `defineCallable(name, handler, getDeps)` (`functions/src/api/callable.ts`) builds a callable from it: options (`maxInstances`, `runAs(name)`, App Check from `HCM_APP_CHECK`), access rule, request validation, the pure handler, response validation. `functions/test/index.test.ts` fails unless the exports are exactly the registry's names, each in `us-central1` with its registry cap (or at most 5) and its `RUNTIME_ACCOUNTS` service account.
- **Family factories**: each folder exports a factory that takes `getDeps` (`adminFunctions`, `adminsFunctions`, `historyFunctions`, `telemetryFunctions`, `defineSetupFunctions`, `publishFunctions`, `photosFunctions(getDeps, bucket)`, `opsFunctions`), so a folder compiles against its own `Pick<Ports, …>` and only `index.ts` knows `deps.ts`. A handler is exported only when a test imports it (knip fails on unused exports); tests drive the rest through `.run()`.
- **Service accounts** (security review §1.1, M2-interfaces §4.3): every callable and `ops.*` run as `fn-admin@` (secrets, Auth, Firebase and Error Reporting viewer roles; `ops.tick` retires Mapbox tokens and deletes stale accounts, `DECISIONS-for-review.md` §19b); the Firestore and Storage triggers and the manifest builder run as `fn-events@`; `telemetry.reportError`, the one public endpoint, runs as `fn-crash@`, an account with no project role at all (a log entry needs none; `DECISIONS-for-review.md` §42f), so a flaw in it reaches neither Firestore nor Storage. A trigger spreads `...runAs('<registry name>')` into its options; `fn-admin@` is firebase-tools' shorthand for `fn-admin@<project>.iam.gserviceaccount.com`, so no project id is written. **The shorthand is not enough for a schedule** (the live test of 2026-10-25, `docs/research/manual-test-2026-10-25.md` finding 11): the functions take it, but firebase-tools 15.33.0 copies it unexpanded into the Cloud Scheduler job's `oidcToken.serviceAccountEmail`, which Scheduler refuses (400 `INVALID_ARGUMENT`), so `ops-tick` and `imagery-tick` had no jobs; M6 makes `runAs` return the full address from `GCLOUD_PROJECT`, with a deploy-shape test (`docs/research/M6-interfaces.md` §3.2). Two more facts of that run: the event functions need `roles/run.invoker` for their own account (Eventarc delivers as `fn-events@`; granted by hand on the project, M6 moves it into Provision), and a non-interactive `firebase deploy --only functions` needs `--force` (a function with a failure policy, the image cleanup policy). The global default is `fn-events@`, the account with fewer rights, never the compute default. A new registry name does not compile until `RUNTIME_ACCOUNTS` lists it.
- **Caps**: callables 2–3 (registry), `telemetry.reportError` 2, `photos.onUpload` 5 with concurrency 1 and 1 GiB (2 until 2026-11-12), `publish.buildManifest` and `ops.tick` 1, `ops.onBudget` 3 (`BUDGET_SCALING`: one instance turned a burst of budget alerts into Cloud Run 429s, a Crashes group each; finding 45, DECISIONS §79d), everything else 5; concurrency 80 is stated globally so a later CPU change cannot silently turn it into 1.
- **Errors are codes**: a handler throws `ApiError('apiError.…', params)`; `toHttpsError` turns it into `HttpsError(status, code, {code, params, issues})` (`API_ERRORS` maps every code to its callable status, HTTP status and retryability; the RO/EN messages are `packages/shared/src/i18n/api/`). Adapters throw `UpstreamError(service, failure, {status, retryAfterSeconds, api})` (`functions/src/ports/errors.ts`; `api` names a Google API that answered `SERVICE_DISABLED`, `image` is the sharp service) and handlers map the failures they expect to specific codes (`cloud.apiDisabled {api}` before `cloud.permission {role}`); an unmapped one falls back to a generic code and is logged.
- **Pure handlers + thin triggers**: business logic never imports `firebase-functions`; triggers only authenticate, validate with the shared zod schemas and call the handler. Feature folders never import each other: shared helpers live in `api/` (`compact`, `omit`), shared names in `@hcm/shared` (`FIRESTORE_PATHS.cities`, `DERIVATIVE_WRITTEN_AT`).
- **REST, not gRPC**: Google APIs are called with `fetch`, so a fake `fetch` tests every adapter; tokens come from `TokenProvider` (google-auth-library ADC). `admin.claim` calls tokeninfo and Resource Manager with the **caller's** own OAuth token, never the service account's; tokeninfo is a POST with the token in the `Authorization` header, never in a URL.
- **Secrets are read at runtime** (`versions/latest:access`) with a 5-minute cache that `setup/status.secretsRev` invalidates (`createSecretManagerStore`, `adapters/secret-manager.ts`); a write adds a version and destroys the older enabled ones. Never `defineSecret`, which would need a redeploy after every paste in the Setup Assistant.
- **Every writer validates** with `@hcm/shared` zod schemas: rules do not apply to the Admin SDK. Paths come from `FIRESTORE_PATHS` and `STORAGE_PATHS`; every document carries the `updatedBy`/`updatedAt` stamp (`systemWriter('<family>')` for server writes).

- **M6** (server-bugs, `docs/research/M6-interfaces.md` §3.2): `runAs()` and the global options name a function's account in full, `<account>@<project>.iam.gserviceaccount.com` (the project from `GCLOUD_PROJECT`, else `GOOGLE_CLOUD_PROJECT`; neither is a refusal: an ad-hoc `npx vitest run functions/test/ops/tick.test.ts` outside the pipeline needs `GCLOUD_PROJECT=demo-hcm`, or the file fails to load with no test run), because Cloud Scheduler's job takes the address as it is (finding 11); `functions/test/deploy-shape.test.ts` loads `src/index.ts` and builds every scheduled function's job with firebase-tools' own `jobFromEndpoint`. `ops.onProbe` (the 69th function, `fn-events@`) answers the nonce `setup.selfTest` writes to `ops/probe`, so the `events` check proves Eventarc delivers as the functions' account (finding 17); `Clock` has an optional `sleep` the check polls with. `UpstreamError` carries Google's `googleStatus` and `reason`, and `MappedUpstreamError` logs them (never a secret) before the code reaches the admin (finding 20: `apiError.assist.modelUnavailable` for a model the project cannot use). The server records its release in `HCM_RELEASE` (`.env.<project>`, `functions/build.mjs`), which the installer's cards compare with the admin's; `setup.recordCloud` keeps an install record checked later than the one reported (`record-install.ts`).

## Composition root (`functions/src/deps.ts`)

- `Deps` = every port of `Ports` but `jobs` (`CloudRunJobs` arrives with M3). `getDeps()` creates them once per instance on the first call, never at cold start.
- `runtimeConfig(env)`: `projectId` (`GCLOUD_PROJECT`, required), `region`, `buckets` (`privateBucket(env)` = `FIREBASE_CONFIG.storageBucket`, else `<project>.firebasestorage.app`; public `<project>-public`), `viewerOrigins` (`HCM_VIEWER_ORIGINS`, comma-separated, default `https://ventura8.github.io`), `adminOrigins` and `adminUrl` from the project, `oauthClientIds` (`HCM_OAUTH_CLIENT_IDS`; when empty `admin.claim` asks Identity Toolkit for the Google sign-in client through `FirebaseManagement.googleSignInClientId`, cached per instance, CR-M2b-2), `errorEndpoint` (`https://us-central1-<project>.cloudfunctions.net/telemetry-reportError`), `appCheck` (`HCM_APP_CHECK`: `enforce`, else `monitor`). `index.ts` passes the same `privateBucket` to `photosFunctions`, so the trigger watches the bucket the Storage adapter writes.
- **In the Functions emulator** (`FUNCTIONS_EMULATOR=true`): secrets in the fake Secret Manager over the emulator `fetch` when `HCM_UPSTREAM_BASE` is set (every function runs in its own worker process), in memory (`createMemorySecretStore`) without it; `appOptions(env)` names the task queue's service account (the Admin SDK would wait about 14 s for the absent metadata server); `createCloudTaskQueue(…, {named: false})` drops task ids (the Cloud Tasks emulator dispatches at once and would swallow a debounce window); the REST adapters get `createEmulatorFetch(HCM_UPSTREAM_BASE, fetch)`, which sends `https://` calls to `api.mapbox.com`, `m2m.cr.usgs.gov` and `*.googleapis.com` to `<base>/h/<host><path>` (the fake upstreams; a loopback base only) and refuses everything else like a network error; a placeholder token replaces ADC. The `x-hcm-test` partition is not forwarded yet (CR-M2-22, CR-M2b-3).

## Function families

- `admin.*` (any verified Google account): `session`; `claim` (the project owner becomes the map's owner: tokeninfo of the caller's token, then `testIamPermissions` for `resourcemanager.projects.setIamPolicy`, then `setup/owner` created once); `join` (an invitation for the caller's verified address). `admins.*` (admins): `invite` (stores only the SHA-256 of the lowercase address; no mail in M2), `revoke` (never the owner or oneself; the document goes first, so access stops at once), `list`.
- `history.*`: the five `on…Write` triggers keep the previous version of every audited document (newest 50, listed by `updatedAt desc`, CR-M2-9); `history.revert` restores the client-editable fields of one entry and skips its own echo.
- `setup.*`: `status`, `selfTest`, `recordCloud` (a `scheduler` item still `pending` before the first deploy does not hold the provisioning area back), `createCity` (M2b, CR-M2b-1: the city from the bundled seed in one transaction, once, created published; an existing city answers `{created: false}`), `saveMapbox` (validate the `sk`, derive the user, verify scopes, mint the scoped tiles token and the URL-restricted public tokens; tokens found by id, then by note, so a second save adds none), `saveUsgs` (`login-token` + `permissions` + `logout`; `pending` with `apiError.usgs.accessPending` until the M2M role is approved, re-checked every 6 h; a paste during maintenance is kept as `unavailable`), `rotatePublicToken`, `analyticsConfig`.
- `imagery.deleteVersion` (`cityEditor`; `docs/research/M3-interfaces.md` §7.1, DECISIONS §153, S-A125-*): a version that never reached the map (failed, cancelled, rejected, or a parked archive series ended first through `endWork`) goes with its job, the job's `logs`, `work/{city}/{job}/` and its own `rasters/{city}/{layer}/{version}/` folder, the two documents in a transaction that reads them again (gone → `notFound`, moved on → `versionState`), an archive series' entry of `archives/{a}.jobs` with them so `imagery.archiveImport` takes it again; refused with `deletePublished`, `deleteRunning`, `deleteInUse` or `joinPartHeld`, and never a base version's folder, a delivery, an upload's original or an archive's originals.
- Pause (2026-11-13, `docs/research/M7-local-worker.md` → *Pause*, DECISIONS §216): `imagery.pause` (`cityEditor`) pauses or resumes a job (`paused: {by, at, inRun?}`), every job, or a computer (the worker's `paused: {by, at, until?}`, its running job `releaseRequested`). No new job status: `worker.claim`, the dispatcher (`held`) and the tick's no-computer mark skip a paused job; the runner stops it at its next step boundary; `worker.end` `released` queues a paused computer's job with its attempt given back only while asked (`pause-state.ts`). A worker's own page sends `pause` with `worker.claim` / `worker.end` (`by: 'computer'`); a pause past its `until` is dropped by the next claim. No client writes `paused` or `releaseRequested` (S-A170-BAD-CLIENT-WRITE).
- M20 (`docs/research/M20-import-local.md`): `worker.archiveReport` (the worker's scan report: `archives/{a}` and its `issues`, never a host path; an imported archive is not reported again) and `imagery.archiveImport` (one `archive-series` job per kept series, `runOn: 'local'`, `localOnly`; beyond `dailyRoom` born `daily` with no `countedAt`, released by `releaseDaily` in `imagery.tick`). `imagery.runOn` refuses a `localOnly` job to the cloud; `worker.claim` and the dispatcher never take a `daily` job; the approval holds an `archive` version to `mapThresholdM` and its rights (`rightsAllowPublish`), and Approve refuses unconfirmed rights (`apiError.imagery.rightsUnconfirmed`). `imagery.confirmRights` (`cityOwner`) clears a version still on `needs-confirmation` (licence `permission`, `confirmedBy`, server `confirmedAt`) so Approve is never stranded (DECISIONS §148, S-A120-*-CONFIRM-*). A worker's run may write its version's `source` only as an archive series' `placedCount` and `skipped` (`step-update.ts` `sourceAllowed`, S-P20-BAD-SOURCE-FORGED).
- `telemetry.reportError` (public HTTPS: origin-checked, 16 KiB, rate-limited per instance, redacted, one structured `ReportedErrorEvent` log entry for Cloud Error Reporting) and `telemetry.listGroups` (the crash panel).
- `publish.*` (diff-gated triggers → one serialized, debounced task-queue builder → `manifest.json`, always a full build in M2; `rebuildManifest` for admins), `photos.onUpload` (magic-byte sniff, header-only size check, HEIC refused with `apiError.photo.heicUnsupported`, sharp → WebP 2048 without metadata, the 400 from that WebP so the original is decoded once (1 GiB; DECISIONS §179), SHA-256 duplicate check (two legacy photos, the old site's one image at two spots, are never each other's duplicate), suggestions), `photos.reprocess`, `ops.tick` (every 15 min: guard, nightly rebuild and public-file sweep, Mapbox and USGS health, token retirement, expired invitations, stale accounts), `ops.onBudget`; M3 adds `usgs.*` and `jobs.onCreate`, M4 `assist.*`.

## Tests

- Handlers with fake ports (no `vi.mock` of owned modules; the in-memory fakes live in `functions/test/support/`), or the real Firestore and Auth adapters on the emulators with a fresh named database per test (`functions/test/admin/world.ts`); the `setup.*` tests run the real REST adapters over `createUpstreamFakes()` with a per-test `intercept` (`functions/test/setup/world.ts`); photos, publish and ops use in-memory documents, blobs and tasks with a movable clock and real sharp on generated images. Adapters run against a fake `fetch` and the shared fixtures of `@hcm/test-support`, including faithful failure shapes (USGS HTTP 500 JSON `errorCode`, HTML 403, 503 maintenance; Mapbox 401, 422; Google `SERVICE_DISABLED`).
- A test names the scenario rows it covers with their tag anywhere in the file, usually its title (`it('happyPath_reportReachesErrorReporting @S-A24-HAPPY', …)`; in an `it.each`, inside the case's name): the `e2e-matrix` gate reads `functions/test/` for `@S-…` tags. Rows and tags land together: the gate refuses a tag on an unknown or `planned` row.
- Triggers and callables through the v2 `.run(request)` API (`npm test` runs Vitest under `firebase emulators:exec`, with `METADATA_SERVER_DETECTION=none` from `scripts/ci/run-emulated-tests.sh`); a test that writes a fixed document (`setup/status`) owns it, or uses its own named database (`getFirestore(app, '<name>')`), because test files run in parallel. App Check is enforced on the HTTP path, which `.run()` skips (S-A20-BAD-NO-APP-CHECK waits for the e2e-admin tier). **`firebase-functions-test` is not used** (it needs a `jest` peer and `firebase-admin` 13 or older).
- `functions/test/deps.test.ts` covers the composition root with environments as arguments (emulator and production, the fake-upstream rewrite, a missing project); `functions/test/index.test.ts` imports `index.ts` with `GCLOUD_PROJECT` and `FIREBASE_CONFIG` stubbed (as firebase-tools sets them).
- Reads cost money (`docs/LESSONS.md` 204): to keep a collection under a limit, `DocumentStore.count` (an aggregation, one read per thousand documents) first, then read only what goes; assert the reads a handler makes (`recorder.argsOf('query')`), not only what it leaves. A per-day cap of a third-party service (Nominatim's `GEOCODE_DAILY_CAP`, LESSONS 207) is counted in the same transaction that claims the work.
- A callable answers JSON (`docs/LESSONS.md` 335): a document read with the Admin SDK holds `Timestamp` objects, which a callable's answer would carry as `{_seconds, _nanoseconds}`; convert them first (`toWire`, `functions/src/worker/fields.ts`: `{seconds, nanoseconds}` at any depth). Cloud Tasks names are ids for the queue's life (lesson 336): a second path of the same work (M7's Uploads API, then MTS) continues the first one's numbering (`poll-<n+1>`), never reuses a name. The registry is split by its consumers (lesson 337): the admin imports `ADMIN_CALLABLES` and `CALLABLE_NAMES`; the functions and the tests read `CALLABLES` (`packages/shared/src/api/callables.ts`), which adds the worker's `WORKER_CALLABLES` (`worker-calls.ts`). A new callable the admin never calls goes into a table of its own.
- Pairing (findings 67–68 of 2026-11-02, `DECISIONS-for-review.md` §85c–§85e, lessons 347–349): a callable's row may say `workerToken: true` (the worker's five only); `runCallable` then lets `requireAccess` read a paired worker's custom-token claims (`workerClaims`: `sign_in_provider: 'custom'`, `worker: true`, `city`, `pair`), still requires the owner's membership, and `requireCityRole` holds the token to its `city`. Access `none` (`worker.pair` only) admits a call with no sign-in; such a callable counts its attempts per city before it reads anything and answers one code for every bad credential. Every `worker.*` handler is wrapped in `paired` (`functions/src/worker/pairing.ts`), which finds the caller's pairing standing. A custom token comes from `AuthAdmin.createCustomToken` (fn-admin's own `signBlob`; unsigned in the Auth emulator). `imagery.tick`'s `noWorker` part (`tick-worker.ts`) marks a local job no computer came for once and leaves `job.noWorker`; `imagery.runOn` and `worker.claim` clear the mark.
- Races (`docs/LESSONS.md` 176, 177): check every precondition again inside the transaction that acts on it (`endWork`'s `accept`, the re-georeference's base, the Replace upload's layer), and keep a cap in a document read and written by that transaction (`ops/dispatch`), never in a query before it. The in-memory document store runs concurrent transactions as they come, unlike Firestore: a test of a race queues them (`serialiseTransactions` in `functions/test/imagery/dispatch.test.ts`), and a test of a write runs the triggers the write sets off (`onJobWrite` after `imagery.saveGcps`).
- Lint quirks met here: ESLint `complexity` counts optional chaining (`?.`) and `??`; `sonarjs/super-linear-regex` flags a `Link`-header regex (split the header instead); `sonarjs/no-clear-text-protocols` flags `http://` literals other than loopback (build a test URL and set its `protocol`).

## Build and deploy

- `functions/build.mjs` (Vite 8 SSR, no second bundler) bundles everything (the workspace packages and their own dependencies such as zod) except the npm dependencies of `functions/package.json` (`firebase-admin`, `firebase-functions`, `google-auth-library`, `sharp`), which stay external with their exact pins in `functions/dist/package.json`; it then fails if a bare import of `functions/dist/index.js` is neither a Node built-in nor pinned, and loads the bundle to check that every export carries a deploy manifest (it prints the number of functions, 33). Dynamic imports count too: `adapters/image.ts` loads sharp (native libvips) with `import('sharp')` on the first photo, so the 32 functions that never touch an image do not load it at cold start (`DECISIONS-for-review.md` §22c). `firebase.json` deploys **`functions/dist/`** (`predeploy` builds it); the Functions emulator loads the same artifact (`firebase emulators:exec --project demo-hcm --only functions,firestore,auth,storage,pubsub,tasks` initializes all 33). Still open: a gate refusing `workspace:` or `file:` dependencies.
- **The locked tree** (§22b): `functions/deploy-manifest.mjs` makes the artifact's `package.json` (the external dependencies with their pins, plus the root's advisory `overrides` except `$name` references); `functions/deploy-lock/` holds that `package.json` and its `package-lock.json`. The build fails unless the committed copy equals the one it writes, then copies the lock into `functions/dist/`, so Cloud Build installs with `npm ci`. Refresh after a change to the four dependencies or to the root overrides: `npm run deploy-lock --workspace @hcm/functions` (`functions/deploy-lock.mjs`, `npm install --package-lock-only --ignore-scripts`) in the digest-pinned `node:24-bookworm-slim` image with the network (`docs/SETUP.md` → *npm in a container*); it keeps the locked versions that still satisfy the pins, so delete `functions/deploy-lock/package-lock.json` first to re-resolve everything. The static gate `deploy-lock-audit` audits it. `firebase-tools` resolves `firebase-functions` from `functions/dist` and loads `index.js` there before any functions deploy; from a checkout Node finds the packages in the repository's `node_modules`, so a deploy from anywhere else installs the lock in `functions/dist` first: the installer's server build does it in its `packages` step (`npm ci --omit=dev --ignore-scripts`, finding 30 of 2026-10-31, lesson 300).
- A new npm dependency of the functions goes into `functions/package.json` (exact pin) and the lockfile; the quality image rebuilds because the dependency fields that its `manifests` stage copies from `functions/package.json` changed (a script edit alone does not rebuild it) (`docs/research/M0-handoff.md` → *TODO for the next agents*).
- **Deploy-time configuration** (§22a): `functions/deploy-env.json` maps each real project to its public values, today `HCM_OAUTH_CLIENT_IDS` (the project's auto-created Google web client, which `admin.claim` checks the token's audience against), `HCM_VIEWER_ORIGINS` and `HCM_APP_CHECK` (`monitor`). The build writes each project's as `functions/dist/.env.<project>`, which firebase-tools loads at deploy for that project only; it refuses anything but one-line `HCM_*` values, and `functions/test/deploy-env.test.ts` holds the file to the keys `runtimeConfig` reads and the projects of `.firebaserc`. A committed `.env.*` file would be refused by the `repo-policy` gate and the pre-commit hook (secret-file names), hence the JSON carrier. Secrets never go here: Secret Manager holds them.
- **A missing field that means "migrate me"** (an `admins/{uid}` without `cities` is from before M5) is never written by new code: a handler that makes a document writes the current shape, empty if need be (`admin.claim` writes `cities: {}`; `docs/LESSONS.md` 258).
- **A model Google may retire** (`DECISIONS-for-review.md` §67g): Vertex AI calls go through `withOfferedModel` (`functions/src/api/vertex-models.ts`): the models of `VERTEX_MODEL_IDS` in order, a 404 moving to the next, the choice kept ten minutes per instance; no model offered is `ModelsNotOfferedError` (`apiError.assist.modelUnavailable` naming every model tried, the last 404 kept for the log). The self-test's `ai` check names the model in use (`params.model`).
- `firebase deploy` is **ask first**; CI deploys through Workload Identity Federation (no keys) after a green CI on `master`. `.firebaserc`'s `default` is the real project `bucurestiul-disparut`, so every local emulator command names `--project demo-hcm`.
