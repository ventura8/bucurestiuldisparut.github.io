# Cloud Functions Skill

Firebase Functions v2 in TypeScript, workspace `@hcm/functions` (`functions/`), Node 24 runtime, region `us-central1` (Firestore `nam5`). Plan: `docs/research/PLAN.md` → *Cloud Functions*; contracts: `docs/research/M2-interfaces.md` (ownership, every function, every port, the change requests); testability: `docs/research/design-review-testability.md` §3.4; security: `docs/research/design-review-security-cost.md` §1.1–§1.2.

## Shape

```text
functions/src/index.ts          exports only: one group per registry namespace, built by its folder's factory
                                (`export const admin = adminFunctions(getDeps)` deploys `admin-session`, `admin-claim`, ...)
functions/src/global-options.ts setGlobalOptions({region: 'us-central1', maxInstances: 5, concurrency: 80, serviceAccount: 'fn-events@'});
                                RUNTIME_ACCOUNTS and runAs(name): the service account of every registry name
functions/src/deps.ts           composition root: runtimeConfig(env), privateBucket(env), one adapter per port, created on first use
functions/src/api/              callable plumbing: defineCallable, requireAccess, ApiError, toHttpsError; compact/omit (objects.ts)
functions/src/ports/            interfaces: DocumentStore, AuthAdmin, SecretStore, GoogleIam, FirebaseManagement, ErrorReporter,
                                TaskQueue, BlobStore, ImageProcessor, MapboxApi, UsgsApi, Clock, RuntimeConfig, AdminDirectory,
                                SetupRecords; `Ports` aggregates them, handlers take Pick<Ports, ...>; UpstreamError, InvalidDocumentError
functions/src/<family>/         one file per function: its thin trigger and its pure handler; `index.ts` is the family factory
                                (admin/ holds `admin.*` and `admins.*`; history, telemetry, setup, photos, publish, ops)
functions/src/adapters/*.ts     REST over fetch (Google APIs, Mapbox, USGS), firebase-admin (Firestore, Auth, Storage, task queue),
                                sharp (imported on the first photo); emulator-fetch.ts keeps the Functions emulator off real hosts
```

- **The registry is the contract**: `CALLABLES`, `HTTP_ENDPOINTS` and `BACKGROUND_FUNCTIONS` of `@hcm/shared` (`packages/shared/src/api/registry.ts`) name every function, its owner, its access rule (`signedIn` or `admin`), its App Check mode (`enforce`, or `consume` for ownership and secret pastes), its `maxInstances` and its zod request and response. `defineCallable(name, handler, getDeps)` (`functions/src/api/callable.ts`) builds a callable from it: options (`maxInstances`, `runAs(name)`, App Check from `HCM_APP_CHECK`), access rule, request validation, the pure handler, response validation. `functions/test/index.test.ts` fails unless the exports are exactly the registry's names, each in `us-central1` with its registry cap (or at most 5) and its `RUNTIME_ACCOUNTS` service account.
- **Family factories**: each folder exports a factory that takes `getDeps` (`adminFunctions`, `adminsFunctions`, `historyFunctions`, `telemetryFunctions`, `defineSetupFunctions`, `publishFunctions`, `photosFunctions(getDeps, bucket)`, `opsFunctions`), so a folder compiles against its own `Pick<Ports, …>` and only `index.ts` knows `deps.ts`. A handler is exported only when a test imports it (knip fails on unused exports); tests drive the rest through `.run()`.
- **Service accounts** (security review §1.1, M2-interfaces §4.3): every callable and `ops.*` run as `fn-admin@` (secrets, Auth, Firebase and Error Reporting viewer roles; `ops.tick` retires Mapbox tokens and deletes stale accounts, `DECISIONS-for-review.md` §19b); the Firestore and Storage triggers, the manifest builder and `telemetry.reportError` (a log entry only) run as `fn-events@`. A trigger spreads `...runAs('<registry name>')` into its options; `fn-admin@` is firebase-tools' shorthand for `fn-admin@<project>.iam.gserviceaccount.com`, so no project id is written. The global default is `fn-events@`, the account with fewer rights, never the compute default. A new registry name does not compile until `RUNTIME_ACCOUNTS` lists it.
- **Caps**: callables 2–3 (registry), `telemetry.reportError` 2, `photos.onUpload` 5 with concurrency 1 and 2 GiB, `publish.buildManifest`, `ops.tick` and `ops.onBudget` 1, everything else 5; concurrency 80 is stated globally so a later CPU change cannot silently turn it into 1.
- **Errors are codes**: a handler throws `ApiError('apiError.…', params)`; `toHttpsError` turns it into `HttpsError(status, code, {code, params, issues})` (`API_ERRORS` maps every code to its callable status, HTTP status and retryability; the RO/EN messages are `packages/shared/src/i18n/api/`). Adapters throw `UpstreamError(service, failure, {status, retryAfterSeconds, api})` (`functions/src/ports/errors.ts`; `api` names a Google API that answered `SERVICE_DISABLED`, `image` is the sharp service) and handlers map the failures they expect to specific codes (`cloud.apiDisabled {api}` before `cloud.permission {role}`); an unmapped one falls back to a generic code and is logged.
- **Pure handlers + thin triggers**: business logic never imports `firebase-functions`; triggers only authenticate, validate with the shared zod schemas and call the handler. Feature folders never import each other: shared helpers live in `api/` (`compact`, `omit`), shared names in `@hcm/shared` (`FIRESTORE_PATHS.cities`, `DERIVATIVE_WRITTEN_AT`).
- **REST, not gRPC**: Google APIs are called with `fetch`, so a fake `fetch` tests every adapter; tokens come from `TokenProvider` (google-auth-library ADC). `admin.claim` calls tokeninfo and Resource Manager with the **caller's** own OAuth token, never the service account's; tokeninfo is a POST with the token in the `Authorization` header, never in a URL.
- **Secrets are read at runtime** (`versions/latest:access`) with a 5-minute cache that `setup/status.secretsRev` invalidates (`createSecretManagerStore`, `adapters/secret-manager.ts`); a write adds a version and destroys the older enabled ones. Never `defineSecret`, which would need a redeploy after every paste in the Setup Assistant.
- **Every writer validates** with `@hcm/shared` zod schemas: rules do not apply to the Admin SDK. Paths come from `FIRESTORE_PATHS` and `STORAGE_PATHS`; every document carries the `updatedBy`/`updatedAt` stamp (`systemWriter('<family>')` for server writes).

## Composition root (`functions/src/deps.ts`)

- `Deps` = every port of `Ports` but `jobs` (`CloudRunJobs` arrives with M3). `getDeps()` creates them once per instance on the first call, never at cold start.
- `runtimeConfig(env)`: `projectId` (`GCLOUD_PROJECT`, required), `region`, `buckets` (`privateBucket(env)` = `FIREBASE_CONFIG.storageBucket`, else `<project>.firebasestorage.app`; public `<project>-public`), `viewerOrigins` (`HCM_VIEWER_ORIGINS`, comma-separated, default `https://ventura8.github.io`), `adminOrigins` and `adminUrl` from the project, `oauthClientIds` (`HCM_OAUTH_CLIENT_IDS`; when empty `admin.claim` asks Identity Toolkit for the Google sign-in client through `FirebaseManagement.googleSignInClientId`, cached per instance, CR-M2b-2), `errorEndpoint` (`https://us-central1-<project>.cloudfunctions.net/telemetry-reportError`), `appCheck` (`HCM_APP_CHECK`: `enforce`, else `monitor`). `index.ts` passes the same `privateBucket` to `photosFunctions`, so the trigger watches the bucket the Storage adapter writes.
- **In the Functions emulator** (`FUNCTIONS_EMULATOR=true`): secrets in the fake Secret Manager over the emulator `fetch` when `HCM_UPSTREAM_BASE` is set (every function runs in its own worker process), in memory (`createMemorySecretStore`) without it; `appOptions(env)` names the task queue's service account (the Admin SDK would wait about 14 s for the absent metadata server); `createCloudTaskQueue(…, {named: false})` drops task ids (the Cloud Tasks emulator dispatches at once and would swallow a debounce window); the REST adapters get `createEmulatorFetch(HCM_UPSTREAM_BASE, fetch)`, which sends `https://` calls to `api.mapbox.com`, `m2m.cr.usgs.gov` and `*.googleapis.com` to `<base>/h/<host><path>` (the fake upstreams; a loopback base only) and refuses everything else like a network error; a placeholder token replaces ADC. The `x-hcm-test` partition is not forwarded yet (CR-M2-22, CR-M2b-3).

## Function families

- `admin.*` (any verified Google account): `session`; `claim` (the project owner becomes the map's owner: tokeninfo of the caller's token, then `testIamPermissions` for `resourcemanager.projects.setIamPolicy`, then `setup/owner` created once); `join` (an invitation for the caller's verified address). `admins.*` (admins): `invite` (stores only the SHA-256 of the lowercase address; no mail in M2), `revoke` (never the owner or oneself; the document goes first, so access stops at once), `list`.
- `history.*`: the five `on…Write` triggers keep the previous version of every audited document (newest 50, listed by `updatedAt desc`, CR-M2-9); `history.revert` restores the client-editable fields of one entry and skips its own echo.
- `setup.*`: `status`, `selfTest`, `recordCloud` (a `scheduler` item still `pending` before the first deploy does not hold the provisioning area back), `createCity` (M2b, CR-M2b-1: the city from the bundled seed in one transaction, once, created published; an existing city answers `{created: false}`), `saveMapbox` (validate the `sk`, derive the user, verify scopes, mint the scoped tiles token and the URL-restricted public tokens; tokens found by id, then by note, so a second save adds none), `saveUsgs` (`login-token` + `permissions` + `logout`; `pending` with `apiError.usgs.accessPending` until the M2M role is approved, re-checked every 6 h; a paste during maintenance is kept as `unavailable`), `rotatePublicToken`, `analyticsConfig`.
- `telemetry.reportError` (public HTTPS: origin-checked, 16 KiB, rate-limited per instance, redacted, one structured `ReportedErrorEvent` log entry for Cloud Error Reporting) and `telemetry.listGroups` (the crash panel).
- `publish.*` (diff-gated triggers → one serialized, debounced task-queue builder → `manifest.json`, always a full build in M2; `rebuildManifest` for admins), `photos.onUpload` (magic-byte sniff, header-only size check, HEIC refused with `apiError.photo.heicUnsupported`, sharp → WebP 2048 and 400 without metadata, SHA-256 duplicate check (two legacy photos, the old site's one image at two spots, are never each other's duplicate), suggestions), `photos.reprocess`, `ops.tick` (every 15 min: guard, nightly rebuild and public-file sweep, Mapbox and USGS health, token retirement, expired invitations, stale accounts), `ops.onBudget`; M3 adds `usgs.*` and `jobs.onCreate`, M4 `assist.*`.

## Tests

- Handlers with fake ports (no `vi.mock` of owned modules; the in-memory fakes live in `functions/test/support/`), or the real Firestore and Auth adapters on the emulators with a fresh named database per test (`functions/test/admin/world.ts`); the `setup.*` tests run the real REST adapters over `createUpstreamFakes()` with a per-test `intercept` (`functions/test/setup/world.ts`); photos, publish and ops use in-memory documents, blobs and tasks with a movable clock and real sharp on generated images. Adapters run against a fake `fetch` and the shared fixtures of `@hcm/test-support`, including faithful failure shapes (USGS HTTP 500 JSON `errorCode`, HTML 403, 503 maintenance; Mapbox 401, 422; Google `SERVICE_DISABLED`).
- A test names the scenario rows it covers with their tag anywhere in the file, usually its title (`it('happyPath_reportReachesErrorReporting @S-A24-HAPPY', …)`; in an `it.each`, inside the case's name): the `e2e-matrix` gate reads `functions/test/` for `@S-…` tags. Rows and tags land together: the gate refuses a tag on an unknown or `planned` row.
- Triggers and callables through the v2 `.run(request)` API (`npm test` runs Vitest under `firebase emulators:exec`, with `METADATA_SERVER_DETECTION=none` from `scripts/ci/run-emulated-tests.sh`); a test that writes a fixed document (`setup/status`) owns it, or uses its own named database (`getFirestore(app, '<name>')`), because test files run in parallel. App Check is enforced on the HTTP path, which `.run()` skips (S-A20-BAD-NO-APP-CHECK waits for the e2e-admin tier). **`firebase-functions-test` is not used** (it needs a `jest` peer and `firebase-admin` 13 or older).
- `functions/test/deps.test.ts` covers the composition root with environments as arguments (emulator and production, the fake-upstream rewrite, a missing project); `functions/test/index.test.ts` imports `index.ts` with `GCLOUD_PROJECT` and `FIREBASE_CONFIG` stubbed (as firebase-tools sets them).
- Lint quirks met here: ESLint `complexity` counts optional chaining (`?.`) and `??`; `sonarjs/super-linear-regex` flags a `Link`-header regex (split the header instead); `sonarjs/no-clear-text-protocols` flags `http://` literals other than loopback (build a test URL and set its `protocol`).

## Build and deploy

- `functions/build.mjs` (Vite 8 SSR, no second bundler) bundles everything (the workspace packages and their own dependencies such as zod) except the npm dependencies of `functions/package.json` (`firebase-admin`, `firebase-functions`, `google-auth-library`, `sharp`), which stay external with their exact pins in `functions/dist/package.json`; it then fails if a bare import of `functions/dist/index.js` is neither a Node built-in nor pinned, and loads the bundle to check that every export carries a deploy manifest (it prints the number of functions, 33). Dynamic imports count too: `adapters/image.ts` loads sharp (native libvips) with `import('sharp')` on the first photo, so the 32 functions that never touch an image do not load it at cold start (`DECISIONS-for-review.md` §22c). `firebase.json` deploys **`functions/dist/`** (`predeploy` builds it); the Functions emulator loads the same artifact (`firebase emulators:exec --project demo-hcm --only functions,firestore,auth,storage,pubsub,tasks` initializes all 33). Still open: a gate refusing `workspace:` or `file:` dependencies.
- **The locked tree** (§22b): `functions/deploy-manifest.mjs` makes the artifact's `package.json` (the external dependencies with their pins, plus the root's advisory `overrides` except `$name` references); `functions/deploy-lock/` holds that `package.json` and its `package-lock.json`. The build fails unless the committed copy equals the one it writes, then copies the lock into `functions/dist/`, so Cloud Build installs with `npm ci`. Refresh after a change to the four dependencies or to the root overrides: `npm run deploy-lock --workspace @hcm/functions` (`functions/deploy-lock.mjs`, `npm install --package-lock-only --ignore-scripts`) in the digest-pinned `node:24-bookworm-slim` image with the network (`docs/SETUP.md` → *npm in a container*); it keeps the locked versions that still satisfy the pins, so delete `functions/deploy-lock/package-lock.json` first to re-resolve everything. The static gate `deploy-lock-audit` audits it.
- A new npm dependency of the functions goes into `functions/package.json` (exact pin) and the lockfile; the quality image rebuilds because the dependency fields that its `manifests` stage copies from `functions/package.json` changed (a script edit alone does not rebuild it) (`docs/research/M0-handoff.md` → *TODO for the next agents*).
- **Deploy-time configuration** (§22a): `functions/deploy-env.json` maps each real project to its public values, today `HCM_OAUTH_CLIENT_IDS` (the project's auto-created Google web client, which `admin.claim` checks the token's audience against), `HCM_VIEWER_ORIGINS` and `HCM_APP_CHECK` (`monitor`). The build writes each project's as `functions/dist/.env.<project>`, which firebase-tools loads at deploy for that project only; it refuses anything but one-line `HCM_*` values, and `functions/test/deploy-env.test.ts` holds the file to the keys `runtimeConfig` reads and the projects of `.firebaserc`. A committed `.env.*` file would be refused by the `repo-policy` gate and the pre-commit hook (secret-file names), hence the JSON carrier. Secrets never go here: Secret Manager holds them.
- `firebase deploy` is **ask first**; CI deploys through Workload Identity Federation (no keys) after a green CI on `master`. `.firebaserc`'s `default` is the real project `bucurestiul-disparut`, so every local emulator command names `--project demo-hcm`.
