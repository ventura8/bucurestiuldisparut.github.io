# i18n Skill

**Historic City Map Maker**'s interface speaks 25 languages (`UI_LOCALES` of `packages/shared/src/i18n/locales.ts`; Arabic, Persian and Urdu right to left; `docs/I18N.md`): Romanian and English are bundled and strictly complete, every other language is a file fetched when chosen, a key it lacks shows in English. The admin, the start page and the public viewer speak all 25 (`VIEWER_LOCALES` is `UI_LOCALES`; the viewer is complete in sixteen, `ro en es fr de it pt ru uk pl tr ar hi zh ja ko`, and its nine others show English for what they lack until imported); Romanian is the default. One list and one table of names: never write a locale list or a language name anywhere but `locales.ts` (the Python mirror in `check_i18n.py` is held equal by a test). The catalogues and helpers live in `@hcm/shared`: `packages/shared/src/i18n/ro.ts`, `en.ts`, `<locale>.ts` for the 23 others (and `map-labels/<locale>.ts`; the nine being translated start as `= {};`), `index.ts` (with `LANGUAGE_NAMES`, `intlTag`, `localized`) and `viewer-catalogues.ts` (`VIEWER_CATALOGUES`, every language's texts in one object).

## How it works

- `ro.ts` is the **key source of truth**: it defines the keys (`MessageKey`) and the `Messages` type.
- `en.ts` is typed `Messages`, so a missing or extra English key is a compile error (`tsc` gate).
- `Locale` (`ro | en`, `LOCALES`) is the admin's and a city's own texts' (`{ro, en}`); `ViewerLocale` (`VIEWER_LOCALES`) the viewer's. `resolveLocale(tag)` maps a tag to the admin's two (English stays English, anything else becomes `ro`); `viewerLocaleOf(tag)` to a viewer language by its primary subtag (`de-AT` → `de`, `zh-TW` → `zh`) or undefined, `resolveViewerLocale` with Romanian for anything else.
- **The engine bundles no catalogue** (`docs/research/DECISIONS-for-review.md` §192): its build empties `ro.ts`, `en.ts` and their `map-labels/` (`scripts/site/src/i18n-catalogues.ts`) and writes every language to `i18n/<locale>.json` next to `engine.mjs` (`{engine, locale, messages}`, the main family and the map labels merged). The engine fetches a language when first shown (`packages/engine/src/core/catalogues.ts`: refused unless it names the engine's version and that language) and registers it (`registerCatalogue`); `translate` of a language not here yet gives `''`, never a key. The admin, the start page, the functions and the tests import `ro` and `en` as before; a test of another language registers `VIEWER_CATALOGUES[locale]` first.
- **The other languages** (`docs/I18N.md`): `UiLocale` (`UI_LOCALES`, 25) is the interface's language, `Locale` stays a city's texts' (`contentLocale(ui)`: `ro` for Romanian, `en` for any other). The admin's and the start page's builds write every family of a language to `i18n/<locale>.json` (`scripts/site/src/ui-catalogues.ts`); `packages/admin/src/state/ui-language.ts` fetches it when chosen and registers it; every translator (`catalogueTranslator`, `translateApiError`, `translate`) reads the bundled `ro`/`en`, then the registry, then English (`uiText`, logged once per language). Translations arrive with `scripts/i18n/import_translations.py`, which keeps only what passes the gate.
- `translate(locale, key, params)` fills `{name}` placeholders; an unknown placeholder stays visible so a test can see it.
- Data has its own translations: city, layer, photo, POI and POI category texts are `{ro, en}` maps in Firestore and the manifest; Romanian is required and English optional (the viewer falls back to Romanian: CR-1 of `docs/research/M1-interfaces.md`), so a photo without an English title can be published (scenario `S-A10-BAD-NOT-PUBLISHABLE` lists what blocks publishing).
- The viewer's keys (M1) are all in the catalogues already, by family: `validation.*` (the codes `validate` and `validateManifest` return, so a schema problem is always shown localized), `error.*`, `action.*`, `viewer.*`, `timeline.*`, `layers.*` (with the overlay list's `layers.group.*`, `layers.opacityChanged`, `layers.shown`, `layers.hidden`), `photos.*`, `photo.*`, `poi.*` (the POI details), `license.*`, `lightbox.*`, `share.*`, `about.*`, `theme.*`, `language.*`, `consent.*`, `geolocate.*` (`docs/research/M1-interfaces.md` §7). Counted forms of the viewer have all six plural forms in every viewer catalogue (`photos.count.zero`, `.one`, `.two`, `.few`, `.many`, `.other`), looked up by `Intl.PluralRules(locale).select(n)`; the admin's keep `.one` / `.few` / `.other` (`pluralOf`).

- The backend's error messages are a catalogue of their own, `packages/shared/src/i18n/api/` (`ro.ts` the key source, `en.ts` typed against it): one `apiError.*` key per error code the functions report, filled with `translateApiError(locale, code, params)`. The viewer imports none of it, so the public bundle carries no admin text; the admin's own screens get their own catalogues in `@hcm/shared` too, because its Lit elements live in `packages/ui` (which cannot import the admin): `packages/shared/src/i18n/admin-shell/` (`translateAdminShell`, keys `adminShell.*`) and `packages/shared/src/i18n/admin-setup/` (`translateAdminSetup`, keys `adminSetup.*`), each owned by one admin workstream (`docs/research/M2b-interfaces.md` §1.6); the editors' texts (M2c) are `packages/shared/src/i18n/admin-content/` (`translateAdminContent`, keys `adminContent.<area>.*`), one catalogue shared by four workstreams through **one marked section per area** (`// [section <area>]` … `// [end <area>]`, the same order in `ro.ts` and `en.ts`; append inside your own section only), which `packages/shared/test/i18n-admin.test.ts` checks (`docs/research/M2c-interfaces.md` §10.1, §11.2).
- The viewer's Map labels group has a catalogue of its own, `packages/shared/src/i18n/map-labels/` (`@hcm/shared/map-labels`): the admin bundles the main catalogue and stands at its budget, so words only the viewer shows and that would grow it go there (the tour's leak check reads them too, `e2e/support/i18n.ts`).

## Rules

1. Every UI string goes into **both** catalogues in the same task, Romanian first, with correct diacritics (ă, â, î, ș, ț with comma below, never the cedilla forms ş, ţ).
2. No hard-coded user-visible string in a component (the one exception: the engine's bilingual card when no catalogue could be fetched, `viewer-wordless.ts`); tests assert the translated text in both languages. Code the engine bundles never reads a catalogue object as it loads (`Object.keys(ro)`): the build empties `ro.ts` and `en.ts`, and a page that read one crashed while every unit test passed (`docs/LESSONS.md` 506).
3. Dates and numbers are formatted with `Intl` for the active locale; the timezone of tests is `Europe/Bucharest`. A date the admin **types** reads in the UI language too, never the browser's: `zz.ll.aaaa` in Romanian, `dd/mm/yyyy` in English (British, as the admin's formatted dates), through `packages/ui/src/admin/editing/date-text.ts` and the `adminContent.common.date*` keys; a native date input shows the browser's pattern (`mm/dd/yyyy` under `en-US`, `S-A21-HAPPY-DATES-IN-LANGUAGE` checks it under an American browser).
4. The viewer: RO by default, `?lang=<code>` or the language list in the menu's Settings (Setări; each language by its own name, `LANGUAGE_NAMES`, with its `lang`, in a fixed order) selects one of the 25, the choice persists after reload, `<html lang>` and `dir` follow it (scenario V11). Arabic is right to left: the viewer's CSS is logical (`inset-inline-*`, `margin-inline-*`, `text-align: start`), Left and Right keys follow the screen (`logicalKey` of the kit), `chevron_*` and `arrow_*` icons mirror, the timeline and the sliders fill from the right, while the map's container stays `dir="ltr"`; `translate` isolates each value in a right-to-left language (U+2068 … U+2069), so a catalogue never holds a bidi control. Dates use `intlTag(locale)` (`ar` with Latin digits). A city's own text falls back to English, then Romanian (`localized`, `shownLanguage`), and the element showing it says which (`lang`, and the `content.fallback` note). The admin: every screen in RO and EN; switching keeps form state (A21); its texts are catalogues of `@hcm/shared` the viewer never imports: `admin-shell` (`translateAdminShell`), `admin-setup` (`translateAdminSetup`) and the editors' `adminContent.*` keys, one catalogue folder per area (`admin-content` for the editing kit and the map, `admin-photos`, `admin-pois`, `admin-layers`, `admin-settings`, `admin-ops`), merged by `translateAdminContent` (`packages/shared/src/i18n/admin-content/index.ts`). An area adds keys to its own folder only, inside its marked section and with its prefix; `packages/shared/test/i18n-admin.test.ts` checks the sections, the prefixes and that no key is in two folders. A folder past ESLint's 400 lines splits again by section, never into a nested folder (the `i18n` gate reads one level of folders); the shell reuses the viewer's `language.*`, `theme.*` and `consent.*` keys, and a card shows a server reason through the API catalogue. Its language resolves from `?lang=`, then `hcm:admin:lang` in `localStorage`, then the browser's languages, then Romanian.
5. The tour tier's **leak check** (`e2e/support/i18n.ts`): in a page of one language no text that only another viewer catalogue has, and no raw message id, appears in the DOM or an accessible name. Third-party UI counts too: Mapbox GL's own strings (the canvas's name, the attribution toggle, the logo link) come from the catalogues (`map.title`, `map.toggleAttribution`, `map.logo`) through Mapbox's `locale` option; they are read when the map is created, so a live language switch keeps them until the next map.
6. The `i18n` static gate (`scripts/ci/check_i18n.py`) checks every `packages/*/src/i18n/` folder and every folder directly inside one: one catalogue per locale (the sixteen complete ones, `VIEWER_COMPLETE`, in `packages/shared/src/i18n` and its `map-labels/`, `ro` and `en` elsewhere; any other language of the 25 is optional there, every language but `ro` and `en` is checked for shape whether required or not, with a completeness report; `--strict` / `HCM_I18N_STRICT=1` keeps every check and adds completeness), the same keys, no duplicates, no empty message, the same `{placeholder}` names. In the viewer's folders it also checks what a translation gets wrong: the six plural forms of a counted family, no brace outside a `{word}` placeholder (no ICU syntax), no leading or trailing whitespace, no bidi control, no text left in English (a word both languages spell alike goes into `COGNATES`, checked by a translator), at least 80 % of the letters in the catalogue's script, and Romanian's comma-below ș and ț. Keep each catalogue a flat object literal with one entry per line, or the gate reports the line it cannot read. An entry of `ro` or `en` longer than 140 columns is wrapped by Prettier onto two lines and then fails this gate: shorten the message instead (an imported translation's wrapped entry is read as one) (Prettier leaves the entry on one line only when it fits 140 columns, or when even the wrapped message would not; the M3 contracts' `apiError.imagery.tilesetLimit` grew past the limit twice before it was shortened to fit).
7. Machine translation drafts (M4, `assist.translate`) are drafts: never auto-published.
8. One screen, one language: resolve it once by the documented order (the URL, the stored choice, the configuration, Romanian) and use that result for every text, error cards and their details included.
9. Visitor copy is plain, natural language, not the engine's vocabulary: "porțiuni ale hărții", not "dale" (tiles), a theme that follows the device is "Automată", not "Ca sistemul"; no two lines of one screen say the same thing (a legacy photo's licence names its source, the separate note says its rights are under review). English follows its own conventions (`80%`, no space; Romanian writes `80 %`), the same in every message of a family.
10. **Counts and agreement** (`docs/LESSONS.md` 124, 234): a catalogue without plural forms never puts `{count}` before a noun, a limit included once someone can set it to 1 (Romanian needs "un loc", "2 locuri", "45 de fotografii"; English "1 place"): write "Locuri șterse: {count}" or "locurile selectate ({count})". A parenthesised "(opțional)" agrees with its label ("Descriere (română, opțională)"); a name said after a preposition takes that form ("Modificat de tine", "de server"); a message names an action by the words of its button (deletes say "restaura din Istoric", as History's Restore does) and one concept keeps one word (tiles are "dale"). Empty states name a control every device has (Add photos), not only a drop.
11. **Names in one list stay apart** (`docs/LESSONS.md` 403): a new step, status or tab name never contains a sibling's in either language; the owner reads them as one, and every lookup by text finds two. `packages/shared/test/i18n-admin.test.ts` checks the job steps' names.
12. **Production copy** (`docs/LESSONS.md` 631): a message tells its reader what happened and what to do, never how the app was built or tested. No test or build words ("simulat", mock, emulator, e2e, TODO), no milestone or design-note names (M5, §, DECISIONS), no raw ids a reader cannot act on (an IAM role, an HTTP status, a MIME type, a model id, a uid, a JSON path, a `{code}`), and no English word inside Romanian ("pipeline", "service worker"); name a Setup step, never its letter (the letters are `aria-hidden`). No old text either (`docs/LESSONS.md` 632): no "coming soon" for what is live or never planned (say what the map has today), no GitHub Pages as the map's host (Firebase Hosting), the product is Historic City Map Maker and its repository `ventura8/historic-city-map-maker`. A text that lives in a city's Firestore document (About, credits, privacy) is changed in the seed and, for a live city, by the owner in the admin's Texts: a deploy never rewrites it. The static gate `copy` (`scripts/ci/check_copy.py`, terms in `scripts/ci/check_copy.toml`) enforces the word list.
13. **A new viewer key** goes into the sixteen complete catalogues in the same task (the nine being translated get it from the next import) (Claude translates; Romanian is the source, English the reviewed reference): the type rejects a missing one in every file. Keep the formal register each catalogue uses, the target language's punctuation (French spaces before `:` and `%`, Arabic `،` and `؟`, CJK full-width), and the gamepad's button names as printed (A, B, Y, LB, RB, Start, Back). A `{name}` placeholder cannot decline, so phrase around it ("Sprache des Textes: {language}").
