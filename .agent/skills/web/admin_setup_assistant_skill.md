# Admin and Setup Assistant Skill

The "do-everything" admin `@hcm/admin` (`packages/admin`): it takes a city owner through Google Cloud, Mapbox and USGS with **minimum input**, then runs the daily flows (photos, satellite layers, georeferencing, jobs, settings, admins). It is served from Firebase Hosting on its own origin (`<proj>.web.app`). Since M2b the shell, the admins page and the whole Setup Assistant run end to end against the emulators and the fake upstreams (`e2e/admin/specs/journey.spec.ts`); the daily flows follow in M2c–M4. User-facing guide: `docs/ADMIN_GUIDE.ro.md`, `docs/ADMIN_GUIDE.en.md`. What only the human does: `workflow/human_steps_and_consent_skill.md`.

## Setup Assistant (first screen until green, re-checkable any time)

Every human step happens **inside the app** (user direction, `docs/research/PLAN.md` → *Addendum*). One Setup page with a progress ring and one card per area. Each step shows:

- a status chip detected automatically;
- why the step is needed and what it costs;
- an "Open page" deep link (new tab) to the exact console page;
- "Do it for me" where a server or Claude action exists;
- a paste box with live verification (for secrets: `type=password`, `autocomplete=off`, never kept in state or storage, cleared after the call);
- automatic advance once the step is detected.

| Card | Steps (detection) |
| --- | --- |
| **Google Cloud billing (Blaze) and budget** | Google sign-in with extra OAuth scopes; list billing accounts (`cloudbilling.googleapis.com`); deep link to create one when none exists (the card is entered on Google's page), poll until it appears; one click links it (Blaze) and creates the $5 budget (`billingbudgets.googleapis.com`). |
| **Provision cloud** | One click runs an idempotent provisioner with the admin's OAuth token: APIs, service accounts and IAM bindings, buckets with CORS and lifecycle, the Workload Identity Federation pool for CI, Secret Manager secrets. A re-checkable "doctor" shows per-item status. |
| **Mapbox** | Exit the demo plan (card and address, on Mapbox's page); usage alerts; create the secret token with the listed scopes; paste it once → `setup.saveMapbox` validates it, derives the username, checks scopes, mints a scoped tiles token and **auto-mints URL-restricted public tokens** for the viewer and the admin. Input budget: at most 2 (paste, save). |
| **USGS** | ERS registration; M2M access request (pre-written justification); application token (the paste box opens first, a 60 s countdown is shown); `setup.saveUsgs` verifies with `login-token` and `permissions`; while the role is pending (no download permission, or a login refused with `AUTH_UNAUTHORIZED`) the card shows `apiError.usgs.accessPending`, `ops.tick` re-checks every 6 h and the card turns green on approval. A paste during USGS maintenance or an outage is kept and shown `unavailable`, checked again 6 h later. |
| **Analytics and crash reporting** | Deep link to enable Google Analytics on the project (the admin accepts the GA terms); the `measurementId` is detected through the Firebase Management API and written to the city doc and the manifest; a "Crash reports" panel lists the latest Error Reporting groups. |

`setup/status` (Firestore) is the single non-secret source of truth shared by the bootstrap and the app, one record per card (`SETUP_AREAS`: billing, provision, mapbox, usgs, analytics, crash; states `missing`, `pending`, `ok`, `invalid`, `unavailable`, the reason an error code); secrets go only to Secret Manager through the `setup.*` callables (`firebase/functions_skill.md`). The callables behind the cards (`docs/research/M2-interfaces.md` §3.3; schemas in `packages/shared/src/api/setup.ts`): `setup.status` (the whole screen; ready once billing, provision, Mapbox and USGS are `ok`), `setup.selfTest` (Re-check), `setup.recordCloud` (what the browser-side billing check and the Provision cloud doctor found), `setup.saveMapbox`, `setup.saveUsgs` (with the token's optional expiry), `setup.rotatePublicToken`, `setup.analyticsConfig`, and `telemetry.listGroups` for the crash panel.

## Bootstrap order (M2b)

The contract is `docs/research/M2b-interfaces.md` (routes, auth states, scopes, the step graph, the provisioner, ownership). In short:

- **Bootstrap mode**: Cloud Functions need Blaze and billing is a Setup step, so steps (a) sign-in and ownership, (b) billing and the budget, (c) Provision cloud and (d) the server's deployment run with no deployed function and no Firestore access (rules deny non-admins): Firebase Auth's Google sign-in works on Spark, and the browser calls Google REST APIs with the owner's own token. Step state lives in memory and `sessionStorage` (`hcm:admin:bootstrap:<projectId>`: never a token, an address or a secret).
- **Which mode**: before sign-in the admin probes `admin-session`; any callable error code but `internal`, `unavailable`, `deadline-exceeded` or `not-found` means the server answers (normal mode). A missing function's 404 has no CORS headers, so the SDK reports it as `internal`, like a network failure: the probe alone cannot tell "not deployed" from "down", so the owner check (Resource Manager `testIamPermissions`) and Service Usage (is Cloud Functions enabled?) decide between `bootstrap`, `notOwner` and `backendDown`.
- **The automatic claim** (d2): once the Cloud Functions list shows every registry function `ACTIVE` and the probe answers, the app sends the Google token it already holds to `admin.claim` (no click), refreshes the ID token, creates the city (`setup.createCity`, CR-M2b-1), records the bootstrap results with `setup.recordCloud` and switches to normal mode. Without a live token it costs one click: browsers open a popup only from a click.
- **The steps and their input budgets** are code: `SETUP_STEPS`, `SETUP_STEP_SPECS`, `nextSetupStep`, `setupInputBudget` (`packages/admin/src/setup/steps.ts`): 10 in-app inputs and 4 Google consents for the whole assistant; following a deep link to a provider's page is not counted.
- **Google scopes** (`GOOGLE_SCOPES`, `unsatisfiedScopes` in `packages/admin/src/google/scopes.ts`): read-only Cloud at the bootstrap sign-in, `cloud-billing` for billing, `cloud-platform` for provisioning and the deployment check, `analytics.edit` for the GA4 stream setting, none for daily use; each asked with `GoogleAuthProvider.addScope` when its step runs, the token in memory only for at most an hour, renewed by the re-authentication popup. The consent note before each popup is inline text (a dialog in between would cost a second click) and explains Google's unverified-app screen.
- **The budget** is created in (b) in the billing account's currency with e-mail alerts; its Pub/Sub topic is attached by the `budget-alerts` doctor item in (c), once the Pub/Sub API (billed) is enabled.
- **The Workload Identity condition** uses `assertion.environment=='deploy'`, the environment `ci.yml`'s deploy jobs declare (the security review wrote `production`; `DECISIONS-for-review.md` §23g); the deploy job reads the repository variables `GCP_WIF_PROVIDER`, `GCP_DEPLOY_SA`, `GCP_PROJECT_ID` and `DEPLOY_ENABLED`.
- **Hosting** serves `packages/admin/dist`, completed by `npm run build:admin` (the Vite build, then `scripts/site/build-admin.ts`: `index.html`, `project.json` from `infra/project.json`, the kit's fonts, `legacy/bucharest/`), which `firebase.json`'s Hosting `predeploy` runs; the App Check site key, created in the browser, is to reach the admin through `runtime.json` at deploy (`DECISIONS-for-review.md` §23b, not applied). The predeploy's Vite build empties `packages/admin/dist`, so anything a workflow step writes there before `firebase deploy` is erased: `runtime.json` must be written by `scripts/site/build-admin.ts` itself, from values the deploy step passes in.
- **The legacy import** uploads the originals of `seed/bucharest/photos/` through the normal photo pipeline (idempotent by document id and `legacyId`), not the 1600 px seed derivatives (`DECISIONS-for-review.md` §23d).

## Who is an admin

- In normal mode (the server answers), after Google sign-in the app asks `admin.session`: an admin opens the dashboard (`refreshToken: true` means refresh the ID token once first); a map without an owner offers **Confirm with Google**, which asks Google for the read-only Cloud scope in a popup and sends that access token to `admin.claim` (the server proves ownership with Resource Manager `testIamPermissions` and the caller's own token, so no address is ever configured); a pending invitation offers "Join" (`admin.join`); anyone else is told and signed out.
- `admins.invite` stores only the SHA-256 of the lowercase address and answers the admin link the inviter shares; `admins.revoke` never removes the owner or oneself.
- Every callable failure arrives as an error code: show `translateApiError(locale, code, params)` (`apiErrorFromFailure` reads it from the SDK's error) and, for `apiError.invalidRequest`, each issue at its field. Pasted secrets are checked in the page first where possible (`classifyMapboxToken` explains a `pk.` before any call).

## Daily flows

- **Photos**: drag-and-drop batch; EXIF and filename fill location, year and bearing (EXIF date ignored when later than the filename year); the last pin as fallback; sticky author, source and licence; "click what the camera looked at" sets the bearing, FOV 60° by default; published on save; a rights-review queue for legacy photos.
- **Satellite layers**: "Find imagery" ranks USGS scenes with footprints and browse previews; "Import (free)" for scanned frames; "Buy scan" prepares the EarthExplorer order (Claude never pays); "Upload GeoTIFF"; "Link tileset/XYZ".
- **Georeferencer**: raw crop (OpenSeadragon) against the OSM / Sentinel-2 reference, residual table, transform choice, live overlay, snap to OSM intersections. **Never** Mapbox Satellite as a reference.
- **Jobs** (live progress, retry, cancel), **Settings** (bounds, About RO/EN, credits, seed colour with live M3 preview, basemap), **Admins** (invite by email link, revoke; the owner cannot be revoked; the last admin is protected).
- **Edit anything** (PLAN Addendum 3, M2): photos (texts, years, author, licence, links, location by drag, bearing and FOV by handle, replace the image, publish, delete); layers (texts, attribution, order by drag, default visibility and opacity, live image adjustments through `rasterAdjustmentPaint`, re-georeference, crop, replace, delete); **POIs** drawn and edited on the map behind a `MapDrawPort` (a GL v3 draw library, verified first), bulk GeoJSON import and export, written with `geometryToDoc`; POI categories in Settings (label RO/EN, icon from `POI_ICONS`, colour, default opacity). The default opacity of every overlay is set with the ui-kit's `hcm-overlay-list`, previewed live on the admin map. Every save stamps `updatedBy`/`updatedAt`; a server trigger keeps the previous version in `history` for one-click revert. Contracts: `docs/research/M1-interfaces.md` §3 and §11.

## As built (M2b)

- **Boot** (`packages/admin/src/app/boot.ts`, `config.ts`): `/__/firebase/init.json` (bad or missing: the `configMissing` screen with Reload), the optional `/runtime.json`, and `/project.json` parsed with `parseProjectConfig` (missing: Setup says it is not available and the log says why). `packages/admin/src/index.ts` builds the real ports, registers `@hcm/ui/admin`'s elements and the pages (`registerAdminPage`, a lazy `PageRegistry`), and mounts; `E2E_KIT` (the OAuth stand-in, `auth/stand-in.ts`) exists only in the `e2e` build mode, so the production bundle carries none of it.
- **Auth** (`packages/admin/src/auth/controller.ts`): the probe before sign-in, the 13 states of M2b-interfaces §1.3, the start-up check `auth/ownership.ts` (a Service Usage 403 is `notOwner`, an outage `backendDown`), Google scopes one at a time checked with tokeninfo, the token in memory only (`GoogleAccessStore`), each uid evaluated once (Firebase may announce a popup's user before the popup resolves), `serverReady()` for the automatic claim.
- **The Setup controller** (`packages/admin/src/setup/controller.ts`) runs one flow per step over injected ports (`ports.ts`: `SetupCloud`, the backend callables, the Google consent, the import, the clock, visibility, `sessionStorage`); `createSetupModule` (`module.ts`) follows the shell's auth state and `#/setup/<step>`; `app/setup-wiring.ts` composes google-clients' `createSetupCloud` and `createLegacyImport` (over `app/legacy-photos.ts`) and calls `setup.createCity` with the bundled city. Polls run on the shell's clock and pause while the tab is hidden; a failed check doubles the wait up to four intervals.
- **Rules the integration taught** (`docs/LESSONS.md` 35–41): a button whose scope depends on a detection waits for it (billing is busy while the billing APIs are checked); an automatic navigation that ends after an await never replaces a card the owner opened meanwhile; the consent note follows the card's next popup (`scope`; sign-in and the claim name none, their panels have their own), not the step's state; fields that must survive a layout change live in the controller's state (`draftUsgs`), never the token; the import ignores a `legacyId` shared by several bundled records; a green card that still offers part of its step (analytics before its stream setting) stays open.
- **The bootstrap record** (`setup/bootstrap-record.ts`) is validated when read and refuses any field or parameter that could hold a token, an address or a display name (a value `redactText` would change).
- **Counters for the e2e budget**: each card carries `data-inputs`, `data-input-budget`, `data-consents`, `data-consent-budget`; a reason is `.detail[data-detail=<key>]`, a doctor row `[data-item][data-state]`, an import failure `[data-photo]`, a crash group `[data-group]` (CR-M2b-23).
- **Google REST** (`packages/admin/src/google/`): one `fetch` transport with the bearer token, three retries for 429, 5xx and network failures (1, 2, 4 s or `Retry-After`), paging, long-running operations polled by name only; every failure a `GoogleApiError` whose fields (`kind`, `api`, `role`, `constraint`, …) `googleFailure()` reads and `failureMessage` maps to a key; IAM policies merged with their etag, at most three writes.
- **The provisioner** (`packages/admin/src/provision/`): `planProvision(observed, only)`, `applyProvision(plan, deps, onItem)`, `doctorProvision(deps, only, onItem)`; an item is `{id, after, observe}` whose observation carries its fix; a failing item leaves its dependants `pending` (`adminSetup.provision.waiting`) and the run goes on; a Google 401 stops the run, which resumes idempotently; `scheduler` is `pending` until the first deploy, which does not hold the provisioning area back (`setup.recordCloud`).
- **The legacy import** (`packages/admin/src/import/`): three photos at a time, create, upload the original through the normal upload path, wait for `photos.onUpload`, publish; idempotent by document id and `legacyId`; `detect()` counts without writing.
- **The claim's OAuth client**: `admin.claim` accepts a token issued to `HCM_OAUTH_CLIENT_IDS` when the deploy sets it (`functions/deploy-env.json` sets the real project's auto-created Google web client), else to the project's Google sign-in client, read once per instance from Identity Toolkit (`FirebaseManagement.googleSignInClientId`, CR-M2b-2); the e2e emulators set no client id, so the journey proves that path.
- **Still open** (`docs/research/M2b-interfaces.md` → Change requests): the callable's `x-hcm-test` forwarding (CR-M2b-3), `runtime.json` and the invoker fix (CR-M2b-6, ask first), the browser-side permission message (CR-M2b-32).

## Implementation rules

- The Setup Assistant is a **pure state machine** (`packages/admin/src/setup/`, M2b) driven by ports; the admin logic is DOM-free and tested in Node, its Lit elements live in the `ui` package; unit tests cover every transition, e2e rows A03–A07, A22 and A25–A30 cover it from outside with the mock APIs and an OAuth stand-in page (Google's consent is the only thing mocked in the browser).
- The admin-input budget fixture counts fills, clicks, pastes and file inputs per flow (`setupBudget.inputs(step, allowance)`; a bad path declares its allowance on first use); a flow that needs more input than its budget is a regression.
- Every API error shape becomes an actionable, localized message (missing scopes listed by name, HTML 403 from USGS means a bad token, 503 means maintenance, a demo or trial Mapbox account answers `apiError.mapbox.mintRefused`, a disabled Google API `apiError.cloud.apiDisabled` with its name). A failed save records its reason on the card unless the card already holds a working or pending configuration, which a failed attempt never overwrites.
- Before every write the admin validates with the shared zod schemas: the rules let an optional text that is blank but not empty through, the server's read refuses it (CR-M2-28 in `docs/research/M2-interfaces.md`). Its lists use the composite indexes of `firebase/firestore.indexes.json`; a history is listed by `updatedAt` descending.
- Deep links live in `packages/admin/src/setup/links.json` (verified ones only, `{name}` placeholders with a `sample`) and are verified weekly by `.github/workflows/contract.yml` (`scripts/ci/check_contracts.py`, which also probes the USGS M2M, Mapbox CDN and Earth Search shapes); a broken link is a bug.
- App Check (reCAPTCHA Enterprise) on Firestore and callables; sensitive callables consume the token (`web/web_security_skill.md`).
