# Admin and Setup Assistant Skill

The "do-everything" admin `@hcm/admin` (`packages/admin`): it takes a city owner through Google Cloud, Mapbox and USGS with **minimum input**, then runs the daily flows (photos, satellite layers, georeferencing, jobs, settings, admins). It is served from Firebase Hosting on its own origin (`<proj>.web.app`). Since M2b the shell, the admins page and the whole Setup Assistant run end to end against the emulators and the fake upstreams (`e2e/admin/specs/journey.spec.ts`); the daily flows follow in M2c–M4. User-facing guide: `docs/ADMIN_GUIDE.en.md` (English only). What only the human does: `workflow/human_steps_and_consent_skill.md`.

## Setup Assistant (first screen until green, re-checkable any time)

Every human step happens **inside the app** (user direction, `docs/research/PLAN.md` → *Addendum*). One Setup page with a progress ring and one card per area. Each step shows:

- a status chip detected automatically;
- why the step is needed and what it costs;
- an "Open page" deep link (new tab) to the exact console page;
- "Do it for me" where a server or Claude action exists;
- a paste box with live verification (for secrets: `type=password`, `autocomplete=off`, never kept in state or storage, cleared after the call);
- automatic advance once the step is detected.

| Card | Steps (detection) |
| --- | --- |
| **Google Cloud billing (Blaze) and budget** | Google sign-in with extra OAuth scopes; list billing accounts (`cloudbilling.googleapis.com`); deep link to create one when none exists (the card is entered on Google's page), poll until it appears; one click links it (Blaze) and creates the $5 budget (`billingbudgets.googleapis.com`). |
| **Provision cloud** | One click runs an idempotent provisioner with the admin's OAuth token: APIs, service accounts and IAM bindings, buckets with CORS and lifecycle, the Workload Identity Federation pool for CI, Secret Manager secrets. A re-checkable "doctor" shows per-item status. |
| **Mapbox** | Exit the demo plan (card and address, on Mapbox's page); usage alerts; create the secret token with the listed scopes; paste it once → `setup.saveMapbox` validates it, derives the username, checks scopes, mints a scoped tiles token and **auto-mints URL-restricted public tokens** for the viewer and the admin. Input budget: 1 (the paste saves at once; a typed token goes with Enter or Save). |
| **USGS** | ERS registration; M2M access request (pre-written justification); application token (the paste box opens first, a 60 s countdown is shown); `setup.saveUsgs` verifies with `login-token` and `permissions`; while the role is pending (no download permission, or a login refused with `AUTH_UNAUTHORIZED`) the card shows `apiError.usgs.accessPending`, `ops.tick` re-checks every 6 h and the card turns green on approval. A paste during USGS maintenance or an outage is kept and shown `unavailable`, checked again 6 h later. |
| **Analytics and crash reporting** | Deep link to enable Google Analytics on the project (the admin accepts the GA terms); the `measurementId` is detected through the Firebase Management API and written to the city doc and the manifest; a "Crash reports" panel lists the latest Error Reporting groups. |

`setup/status` (Firestore) is the single non-secret source of truth shared by the bootstrap and the app, one record per card (`SETUP_AREAS`: billing, provision, mapbox, usgs, analytics, crash; states `missing`, `pending`, `ok`, `invalid`, `unavailable`, the reason an error code); secrets go only to Secret Manager through the `setup.*` callables (`firebase/functions_skill.md`). The callables behind the cards (`docs/research/M2-interfaces.md` §3.3; schemas in `packages/shared/src/api/setup.ts`): `setup.status` (the whole screen; ready once billing, provision, Mapbox and USGS are `ok`), `setup.selfTest` (Re-check), `setup.recordCloud` (what the browser-side billing check and the Provision cloud doctor found), `setup.saveMapbox`, `setup.saveUsgs` (with the token's optional expiry), `setup.rotatePublicToken`, `setup.analyticsConfig`, and `telemetry.listGroups` for the crash panel.

## Bootstrap order (M2b)

The contract is `docs/research/M2b-interfaces.md` (routes, auth states, scopes, the step graph, the provisioner, ownership). In short:

- **Bootstrap mode**: Cloud Functions need Blaze and billing is a Setup step, so steps (a) sign-in and ownership, (b) billing and the budget, (c) Provision cloud and (d) the server's deployment run with no deployed function and no Firestore access (rules deny non-admins): Firebase Auth's Google sign-in works on Spark, and the browser calls Google REST APIs with the owner's own token. Step state lives in memory and `sessionStorage` (`hcm:admin:bootstrap:<projectId>`: never a token, an address or a secret).
- **Which mode**: before sign-in the admin probes `admin-session`, unless `runtime.json` says `startUp` (a new map's Hosting-only deploy, `HCM_ADMIN_START_UP=1 npx firebase deploy --only hosting`): then it starts in bootstrap mode without calling the server, as a function that is not deployed answers 404 without CORS headers and the browser logs that whatever the fetch mode; step (d) probes once Google shows every function `ACTIVE`, and a browser that had the server's answer before (`hcm:admin:serverSeen`) probes anyway; any callable error code but `internal`, `unavailable`, `deadline-exceeded` or `not-found` means the server answers (normal mode). A missing function's 404 has no CORS headers, so the SDK reports it as `internal`, like a network failure: the probe alone cannot tell "not deployed" from "down", so the owner check (Resource Manager `testIamPermissions`) and Service Usage (is Cloud Functions enabled?) decide between `bootstrap`, `notOwner` and `backendDown`.
- **The automatic claim** (d2): once the Cloud Functions list shows every registry function `ACTIVE` and the probe answers, the app sends the Google token it already holds to `admin.claim` (no click), refreshes the ID token, creates the city (`setup.createCity`, CR-M2b-1), records the bootstrap results with `setup.recordCloud` and switches to normal mode. Without a live token it costs one click: browsers open a popup only from a click.
- **The steps and their input budgets** are code: `SETUP_STEPS`, `SETUP_STEP_SPECS`, `nextSetupStep`, `setupInputBudget` (`packages/admin/src/setup/steps.ts`): 9 in-app inputs and 4 Google consents for the whole assistant; following a deep link to a provider's page is not counted.
- **Google scopes** (`GOOGLE_SCOPES`, `unsatisfiedScopes` in `packages/admin/src/google/scopes.ts`): read-only Cloud at the bootstrap sign-in, `cloud-billing` for billing, `cloud-platform` for provisioning and the deployment check, `analytics.edit` for the GA4 stream setting, none for daily use; each asked with `GoogleAuthProvider.addScope` when its step runs, the token in memory only for at most an hour, renewed by the re-authentication popup. The consent note before each popup is inline text (a dialog in between would cost a second click) and explains Google's unverified-app screen.
- **The budget** is created in (b) in the billing account's currency with e-mail alerts; its Pub/Sub topic is attached by the `budget-alerts` doctor item in (c), once the Pub/Sub API (billed) is enabled.
- **The Workload Identity condition** uses `assertion.environment=='deploy'`, the environment `ci.yml`'s deploy jobs declare (the security review wrote `production`; `DECISIONS-for-review.md` §23g); the deploy job reads the repository variables `GCP_WIF_PROVIDER`, `GCP_DEPLOY_SA`, `GCP_PROJECT_ID` and `DEPLOY_ENABLED`.
- **Hosting** serves the admin under `/admin/` since M6 (`dist/hosting/admin/`, copied from `packages/admin/dist` by `npm run build:hosting`, Hosting's `predeploy`; the Vite base `/admin/`; the public map at the root: `docs/research/M6-interfaces.md` §2), completed by `npm run build:admin` (the Vite build, then `scripts/site/build-admin.ts`: `index.html`, `project.json` from `infra/project.json`, the kit's fonts, `legacy/bucharest/`), which `firebase.json`'s Hosting `predeploy` runs. Every Hosting ship also runs `npm run build:install` so `/admin/install/<slug>/` holds the Update/Install bundle; without it the `/admin/**` rewrite serves SPA HTML for `manifest.json` and Update the map dies (DECISIONS §149, lesson 554). Check that URL is JSON before calling the deploy done. `scripts/site/build-admin.ts` writes `runtime.json` itself (`scripts/site/src/admin/runtime.ts`: `release` = `<version>+<short commit>` from `HCM_COMMIT`, `GITHUB_SHA` or the checkout's `HEAD`; `startUp` with `HCM_ADMIN_START_UP=1`), since the predeploy's Vite build empties `packages/admin/dist` and anything a workflow step wrote there before `firebase deploy` would be erased; the App Check site key joins it with the deploy milestone (`DECISIONS-for-review.md` §23b). `index.html` names the Subresource Integrity digest of the pinned `mapbox-gl.js` (`<html data-mapbox-integrity>`), which `loadMapboxGl` sets on the script with `crossOrigin` (§34h).
- **The legacy import** uploads the originals of `seed/bucharest/photos/` and, after them, of the old site's 2023 additions `seed/bucharest-2023/photos/` (`SEED_ADDITIONS`, `docs/research/M5-interfaces.md` §12) through the normal photo pipeline (idempotent by document id and `legacyId`), not the 1600 px seed derivatives (`DECISIONS-for-review.md` §23d). A new folder of old photos is migrated with `migrate-legacy.mjs --joins <earlier folder>` so no id repeats, and is diffed against the live old site before it is called complete, the photos already migrated included (`scripts/seed/legacy-corrections.mjs`; `docs/LESSONS.md` 472, 457).

## Who is an admin

- In normal mode (the server answers), after Google sign-in the app asks `admin.session`: an admin opens the dashboard (`refreshToken: true` means refresh the ID token once first); a map without an owner offers **Confirm with Google**, which asks Google for the read-only Cloud scope in a popup and sends that access token to `admin.claim` (the server proves ownership with Resource Manager `testIamPermissions` and the caller's own token, so no address is ever configured); a pending invitation offers "Join" (`admin.join`); anyone else is told and signed out.
- `admins.invite` stores only the SHA-256 of the lowercase address and answers the admin link the inviter shares; `admins.revoke` never removes the owner or oneself.
- Every callable failure arrives as an error code: show `translateApiError(locale, code, params)` (`apiErrorFromFailure` reads it from the SDK's error) and, for `apiError.invalidRequest`, each issue at its field. Pasted secrets are checked in the page first where possible (`classifyMapboxToken` explains a `pk.` before any call).

## Daily flows

- **Photos**: drag-and-drop batch; EXIF and filename fill location, year and bearing (EXIF date ignored when later than the filename year); the last pin as fallback; sticky author, source and licence; "click what the camera looked at" sets the bearing, FOV 60° by default; published on save; a rights-review queue for legacy photos.
- **Satellite layers**: "Find imagery" ranks USGS scenes with footprints and browse previews; "Import (free)" for scanned frames; "Buy scan" prepares the EarthExplorer order (Claude never pays); "Upload GeoTIFF"; "Link tileset/XYZ". As built in M4 (`docs/research/M4-interfaces.md` §1): a scene to buy has the order card (35 USD for one frame, the four EarthExplorer steps, the scene's verified EarthExplorer page in a new tab) and **I ordered it** (`usgs.markOrdered`): the flow's two inputs (`buyScan` in `CONTENT_INPUT_BUDGETS`); then nothing is asked: the daily watch (`imagery.tick`), reminders on days 7 and 12, the import on delivery, the automatic points and the publish under the threshold (behaviour A48 proves the chain). Provision turns on Vertex AI, FCM and FCM registrations, makes the custom role `hcmVertexDrafts` (the drafts' `aiplatform.endpoints.predict` only) before the `iam` item binds it, and the self-test has an `ai` check (`.agents/skills/setup-assistant/SKILL.md`). The 2026-10-24 reviews (`DECISIONS-for-review.md` §57) left the minimum-input rules: an expired order offers Take the mark back, only it counts in Work; an order card says the check waits for USGS's approval of downloads; a photo still titled after its file asks for title suggestions when its pin is set; a draft is offered only for an empty side.
- **What the owner approves** (M12, `docs/research/M12-own-tiles.md`, A73–A75): a version's page draws its own tiles from a signed hour of the private archive (`imagery.previewUrl`, `packages/admin/src/imagery/version-image.ts`) on the page's one map, the city's outline and what it misses shaded, with Actual pixels and See the image; the address stays in that object and the map, never in the area's state; an hour on, a failing tile asks for a new address on its own. A small picture says honestly why (`image-view.ts` → `smallKey`: on its way, never coming, deleted), and `apiError.imagery.tilesGone` offers no Try again (lessons 405–410). The card's cost is in the owner's words (`packages/ui/src/admin/imagery/image-view.ts`); Mapbox's compute units and choices come from the `mapbox-choices` chunk, only for a city with **Publish through Mapbox** on (Settings → Historical imagery). A version's whole page is the `approval-map` chunk.
- **Georeferencer**: scan canvas against the OSM / Sentinel-2 reference, residual table, transform choice, live overlay. Pair and suggestion badges on the map match the scan exactly (`marker-badge.ts` + canvas overlay; DECISIONS §143) — never POI overlays (their labels hid below zoom 16). Map pane: focusable crosshair and arrow nudge like the scan. Context menu on both panes (right-click, 500 ms long press, ContextMenu / Shift+F10): Add a point here, Move / Delete this point within `PAIR_HIT_RADIUS`, Undo; read-only shows one disabled line; the element and its gestures are the lazy `georef-menu` chunk, so `georef` keeps 19 KB (DECISIONS §152; M3-interfaces addendum of 2026-11-12). A pointer handler that means a click checks `event.button` (lesson 562). Linked views (DECISIONS §156): once a fit exists, the scan's `hcm-view` and the map's `move` go through `ViewLink` (lazy `georef-extras`: `toGeo` / `toPixel` plus the fit's local scale, one move a frame, the echo of its own jump dropped, a `move` that leaves the camera unchanged ignored, nothing while a point is dragged); **Link the views** is on by default and lives in the store's memory. An e2e spec that clicks the scan by its whole view opens the georeferencer with the link off (`georeferencerReady`), else a map zoom moves the scan under it. While a half pair waits, nothing moves the other pane (the link pauses): the expected place is the ghost's dashed ring (`ghost.ts` in `georef-extras`; the fit, or two pairs' similarity), never a pan to it (lesson 595). The scan pane keeps the owner's zoom and centre over a size change (`resizedView`, lesson 594), and past the preview's own pixels draws the tiles of `scan-tiles.bin` in view (`scanDetail`). The warp's mesh is the lazy `georef-warp` chunk (DECISIONS §169). **Never** Mapbox Satellite as a reference. The map pane's list **The map shows** offers OSM, Sentinel-2 and the city's published layers on the page's one map (`base-layers.ts`; never a second map, never Mapbox Satellite). The sharper scan is tiles in one file (`scan-tiles.bin`), decoded only where the pane looks (`scan-tiles.ts`, a lazy chunk): never hand the browser one picture larger than the preview. Removing a pair always goes through `removing.ts` (one Undo step, a notice with Undo). Each pane turns (`ScanView.angle`; every pane-to-scan conversion goes through `scan-view.ts`, never its own arithmetic), and with a fit the two turn together (`rotation.ts`). New georeferencer code goes in a lazy chunk or a budgeted group: the `georef` chunk is at its 19 KB (DECISIONS-for-review.md §171, §172).
- **Jobs** (live progress, retry, cancel), **Settings** (bounds, About RO/EN, credits, seed colour with live M3 preview, basemap), **Admins** (invite by email link, revoke; the owner cannot be revoked; the last admin is protected).
- **Edit anything** (PLAN Addendum 3, M2): photos (texts, years, author, licence, links, location by drag, bearing and FOV by handle, replace the image, publish, delete); layers (texts, attribution, order by drag, default visibility and opacity, live image adjustments through `rasterAdjustmentPaint`, re-georeference, crop, replace, delete); **POIs** drawn and edited on the map behind a `MapDrawPort` (a GL v3 draw library, verified first), bulk GeoJSON import and export, written with `geometryToDoc`; POI categories in Settings (label RO/EN, icon from `POI_ICONS`, colour, default opacity). The default opacity of every overlay is set with the ui-kit's `hcm-overlay-list`, previewed live on the admin map. Every save stamps `updatedBy`/`updatedAt`; a server trigger keeps the previous version in `history` for one-click revert. Contracts: `docs/research/M1-interfaces.md` §3 and §11, and for the editors `docs/research/M2c-interfaces.md`: list and detail from 840 px, a full-screen editor on phones; one store per area behind `AdminAppPort.content`; the admin map is the viewer's `MapPort` (moving to `@hcm/ui/map`), always the Standard style, never Satellite; `MapDrawPort` on Terra Draw 1.38.0 (1.37.0 until §53a) with its Mapbox GL adapter 1.5.0 (Mapbox GL Draw was evaluated and not chosen), with the vertex list as the keyboard alternative; drafts preview live on the map and Save is one transaction that refuses a conflicting change; publish on save; deletes ask first and offer Undo through `history.revert`; a layer is deleted by `layers.delete`, whose `layer-delete` job removes the tileset after seven days (M3).

## As built (M2b)

- **Boot** (`packages/admin/src/app/boot.ts`, `config.ts`): `/__/firebase/init.json` (bad or missing: the `configMissing` screen with Reload), the optional `runtime.json` and `project.json` beside the page (`/admin/` since M6: `import.meta.env.BASE_URL`), the latter parsed with `parseProjectConfig` (missing: Setup says it is not available and the log says why). `packages/admin/src/index.ts` builds the real ports, registers `@hcm/ui/admin`'s elements and the pages (`registerAdminPage`, a lazy `PageRegistry`), and mounts; `E2E_KIT` (the OAuth stand-in, `auth/stand-in.ts`) exists only in the `e2e` build mode, so the production bundle carries none of it.
- **Auth** (`packages/admin/src/auth/controller.ts`): the probe before sign-in, the 13 states of M2b-interfaces §1.3, the start-up check `auth/ownership.ts` (a Service Usage 403 is `notOwner`, an outage `backendDown`), Google scopes one at a time checked with tokeninfo, the token in memory only (`GoogleAccessStore`), each uid evaluated once (Firebase may announce a popup's user before the popup resolves), `serverReady()` for the automatic claim.
- **The Setup controller** (`packages/admin/src/setup/controller.ts`) runs one flow per step over injected ports (`ports.ts`: `SetupCloud`, the backend callables, the Google consent, the import, the clock, visibility, `sessionStorage`); `createSetupModule` (`module.ts`) follows the shell's auth state and `#/setup/<step>`; `app/setup-wiring.ts` composes google-clients' `createSetupCloud` and `createLegacyImport` (over `app/legacy-photos.ts`) and calls `setup.createCity` with the bundled city. Polls run on the shell's clock and pause while the tab is hidden; a failed check doubles the wait up to four intervals.
- **Rules the integration taught** (`docs/LESSONS.md` 35–41): a button whose scope depends on a detection waits for it (billing is busy while the billing APIs are checked); an automatic navigation that ends after an await never replaces a card the owner opened meanwhile; the consent note follows the card's next popup (`scope`; sign-in and the claim name none, their panels have their own), not the step's state; fields that must survive a layout change live in the controller's state (`draftUsgs`), never the token; the import ignores a `legacyId` shared by several bundled records; a green card that still offers part of its step (analytics before its stream setting) stays open; in normal mode the step to resume at opens as soon as `setup.status` answers, and the legacy import's detection (it reads every photo) decides only when the import is that step (a card that opened seconds later moved every step below it).
- **Layout** (the user's report of 2026-10-12, `docs/research/layout-a11y-findings.md`): the shell is an app shell where only the page scrolls, so no content is ever under the navigation bar, the rail or the top app bar, and the snackbar is docked below the page; every screen's content is in `<main>`. The tour's checkers run on every admin state (behaviour A31): a new screen or state joins `ADMIN_STATES` with an `expectStateSound` call on its settled state.
- **The bootstrap record** (`setup/bootstrap-record.ts`) is validated when read and refuses any field or parameter that could hold a token, an address or a display name (a value `redactText` would change).
- **Counters for the e2e budget**: each card carries `data-inputs`, `data-input-budget`, `data-consents`, `data-consent-budget`; a reason is `.detail[data-detail=<key>]`, a doctor row `[data-item][data-state]`, an import failure `[data-photo]`, a crash group `[data-group]` (CR-M2b-23).
- **Google REST** (`packages/admin/src/google/`): one `fetch` transport with the bearer token, three retries for 429, 5xx and network failures (1, 2, 4 s or `Retry-After`), paging, long-running operations polled by name only; every failure a `GoogleApiError` whose fields (`kind`, `api`, `role`, `constraint`, …) `googleFailure()` reads and `failureMessage` maps to a key; IAM policies merged with their etag, at most three writes.
- **The provisioner** (`packages/admin/src/provision/`): `planProvision(observed, only)`, `applyProvision(plan, deps, onItem)`, `doctorProvision(deps, only, onItem)`; an item is `{id, after, observe}` whose observation carries its fix; a failing item leaves its dependants `pending` (`adminSetup.provision.waiting`) and the run goes on; a Google 401 stops the run, which resumes idempotently; `scheduler` is `pending` until the first deploy, which does not hold the provisioning area back (`setup.recordCloud`).
- **The legacy import** (`packages/admin/src/import/`): three photos at a time, create, upload the original through the normal upload path, wait for `photos.onUpload`, publish; idempotent by document id and `legacyId`; `detect()` counts without writing. It never undoes the owner's work: a photo whose document is gone and whose `history` has a delete by an account is not created again, and a processed, unpublished photo of which an account changed a published version is not published again; entries stamped `system:…` or with a service account's e-mail (a function, the emulator's admin of the e2e reset, which records `fake-auth-id@gmail.com`) never count (`LegacyPhotoStore.history`; S-A28-BAD-OWNER-EDITS-KEPT, `docs/LESSONS.md` 473). Once some photos are in, the card says how many are missing and offers **Import the missing photos (n)** (S-A28-HAPPY-ADDITIONS). The same click adds the old site's later directions (`legacy-fixes.ts`, `legacy/bucharest/corrections.json`) only to a photo still as migrated that no person aimed, moves its point only if no person moved it, and adds the authors the city's credits lack; the card counts them (**Add the old site's directions (n)**; S-A28-HAPPY-DIRECTIONS, S-A28-BAD-OWNER-DIRECTION-KEPT, `docs/LESSONS.md` 474).
- **The claim's OAuth client**: `admin.claim` accepts a token issued to `HCM_OAUTH_CLIENT_IDS` when the deploy sets it (`functions/deploy-env.json` sets the real project's auto-created Google web client), else to the project's Google sign-in client, read once per instance from Identity Toolkit (`FirebaseManagement.googleSignInClientId`, CR-M2b-2); the e2e emulators set no client id, so the journey proves that path.
- **Revocation while editing** (§35e): a denied write makes the shell ask `admin.session`; not an admin any more while an editor holds unsaved changes, the shell sets `revoked`: the page stays with its draft under a banner (an alert) with Sign out, every editor write is refused at once (`writesRefusedWhen`, `packages/admin/src/content/revoked.ts`) and no further denial asks again; without unsaved changes it is the `notAdmin` panel as before.
- **Theme preview** (CR-M2c-28): Settings' seed colour reaches the shell through `ContentServices.previewTheme`; the whole admin wears it until Save, Discard, leaving Settings or sign-out.
- **Number fields** (§35d): commit on every key (`numberValue` keeps the admin's spelling of the same number) and show their problem once left (`LeftFields`, `packages/ui/src/admin/editing/number-fields.ts`).
- **Still open** (`docs/research/M2b-interfaces.md` → Change requests): the callable's `x-hcm-test` forwarding (CR-M2b-3), the App Check key in `runtime.json` and the invoker fix (CR-M2b-6, ask first), the browser-side permission message (CR-M2b-32).

## As built (M2c: the editors)

- **The seam** (`docs/research/M2c-interfaces.md` §2): one DOM-free store per area (`packages/admin/src/<area>/`: photos, pois, layers, settings, home, admins, history, jobs, crashes), created when its page first opens and destroyed on sign-out; `ContentServices` gives it the city, the `ContentStore` port (Firestore transactions whose version is `updatedAt`, so Save refuses a document another admin changed: `conflict`, `gone`, `denied`, `offline`, `invalid`), the uploads, the callables, the map factory, the clock and `localStorage`; the Lit page reads it through `AdminAppPort.content`, and `packages/admin/test/app/admin-port.test.ts` pins every store to its page's port. Each area is a lazy chunk (`DECISIONS-for-review.md` §34b, §41a): `packages/admin/src/pages/<area>.ts` (the page's elements from `@hcm/ui/admin/areas/<area>`, the store's module) loaded by `routing/area-pages.ts` when the route first opens; a new area adds its chunk file, its line in `AREA_CHUNKS`, its `@hcm/ui/admin/areas/` entry and its budget in `scripts/ci/check_bundle_budget.py` (`ADMIN_CHUNK_BUDGETS`). A chunk that does not load rejects the loader, and the page outlet offers Try again (`S-A29-BAD-CHUNK-LOAD`).
- **Drafts**: an edit is a draft previewed on the page's one map and written only by Save; a draft is the changed fields over the latest snapshot (lesson 71), so a remote save merges or raises the conflict choice. A text field commits on `input` (a click on a disabled Save is no click: lesson 75); a number commits on `change`.
- **The map**: `@hcm/ui/map` (the viewer's `MapPort` and adapter), Standard style only, the admin token from `setup/status` (none: the unavailable map, every field and the list of positions still work), one map per page visit, always in `hcm-admin-map` (it links mapbox-gl.css inside its shadow root, where the page's copy cannot reach Mapbox's logo and attribution, and says why there is no map); drawing through `MapDrawPort` on Terra Draw 1.38.0 (`docs/research/DECISIONS-for-review.md` §34g, §41b, §53a; loaded with the first drawing tools, `loadTerraDraw`): a new shape is drawn by clicks (`click-growth.ts`, so the input budgets hold), Terra Draw's select mode drags the selected shape, a vertex or a midpoint, a click moves a selected point, the list of positions is the keyboard's way; only geometry changes that do not come from the port itself are reported (a selection's marks are a properties change: reported, they moved the photo's pin back, lesson 132). The click-only port is the fallback.
- **What a save publishes reaches the viewer**: the history triggers keep the previous version, the publish trigger asks for a manifest build, the viewer reads the manifest. The admin-to-viewer journeys (behaviour A41, `e2e/admin/specs/flows/`) prove it end to end, the built site naming the project's city `bucharest` (§35b, its `site.json` → `legacyCityId` renames the seed's `bucuresti`). A denied editor write with unsaved changes keeps the page read-only under a banner until sign-out (§35e).
- **The first screen** (§34i, §41c): `app/setup-readiness.ts` watches `setup/status` while an admin is signed in (normal mode) and sets `setupReady` (billing, provisioning, Mapbox, USGS `ok`), remembered per project in `localStorage`; an empty address opens `#/home` once it is true, and Home takes Setup's place on the compact bar. ## Implementation rules

- The Setup Assistant is a **pure state machine** (`packages/admin/src/setup/`, M2b) driven by ports; the admin logic is DOM-free and tested in Node, its Lit elements live in the `ui` package; unit tests cover every transition, e2e rows A03–A07, A22 and A25–A30 cover it from outside with the mock APIs and an OAuth stand-in page (Google's consent is the only thing mocked in the browser).
- The admin-input budget fixture counts fills, clicks, pastes and file inputs per flow (`setupBudget.inputs(step, allowance)`; a bad path declares its allowance on first use); a flow that needs more input than its budget is a regression.
- **Minimum input, the patterns that cut a click** (review of 2026-10-18, `DECISIONS-for-review.md` §38): an unambiguous paste saves itself (the USGS and Mapbox tokens: `insertFromPaste` on a value that classifies right; a typed value still goes with Enter or the button, and an ambiguous paste is only counted and explained); a choice the words already make is pre-made until the admin makes it (a new category's icon follows its label, `guessCategoryIcon`); what is made to be shared goes to the clipboard at once (a new invitation's link; a refusal leaves Copy).
