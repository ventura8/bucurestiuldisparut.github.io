# UI: Material 3 Adaptive Skill

The component kit `@hcm/ui` (`packages/ui`), shared by the engine and the admin: Lit 3 custom elements, Material 3 with M3 Expressive, adaptive to every window size. Since M1 it holds the kit's 19 elements (`packages/ui/src/components/`, all registered by `defineUiKit()`), the theme (`packages/ui/src/theme/`: dynamic colour, `applyTheme`, the system tokens, `BASELINE_THEME`), the window-class layout (`packages/ui/src/layout/window-class.ts`), the self-hosted fonts (`packages/ui/src/fonts/`, `packages/ui/fonts/`) and, under the ownership override, the viewer's elements (`packages/ui/src/viewer/`) and, since M2b, the admin's (`packages/ui/src/admin/`: shell, auth panels, Setup cards). The package guide is `packages/ui/README.md` (elements, theme, fonts, layout, *Decisions*); the component contract is `docs/research/M1-interfaces.md` §5 with change request CR-12.

## Lit without decorators

Decorators are banned by ESLint (their helpers show up as uncovered branches, and Vite 8's transform support is unclear). The pattern, as in `hcm-hello`:

```ts
export const HCM_EXAMPLE_TAG = 'hcm-example';

export class HcmExample extends LitElement {
    static override readonly properties = { label: { type: String } };

    static override readonly styles = css`
        :host {
            display: block;
        }
    `;

    declare label: string;

    constructor() {
        super();
        this.label = '';
    }

    override render(): TemplateResult {
        return html`<span>${this.label}</span>`;
    }
}

/** Registers the element once; calling it again is a no-op. */
export function defineHcmExample(registry: CustomElementRegistry = customElements): void {
    if (registry.get(HCM_EXAMPLE_TAG) === undefined) {
        registry.define(HCM_EXAMPLE_TAG, HcmExample);
    }
}
```

- `static override readonly properties`, `declare` fields, defaults in the constructor (`useDefineForClassFields: true`).
- An idempotent `define…()` function taking the registry (tests pass their own); the element prefix is always `hcm-`; add the tag to `HTMLElementTagNameMap`.
- Styles in a `static override readonly styles` built with Lit's `css` tag (linted by stylelint through `postcss-lit`); colours only from tokens.

## Material 3

- Every element is written in Lit with Google's M3 token values. `@m3e/web` 2.10.0 and `@material/web` 2.5.0 were checked in M1 and not adopted: the contract needs what neither documents (`aria-valuetext` and PageUp/PageDown on the slider, one input event per frame while dragging, sheet heights) and the embed's gzip budget argued against them (`packages/ui/README.md` → *Decisions*).
- **Colour**: `@material/material-color-utilities@0.4.0` (SpecVersion 2025, TonalSpot) generates the light, dark and high-contrast `--md-sys-color-*` tokens (53 per scheme) from the city's seed colour: `themeFromSeed` in `packages/ui/src/theme/dynamic-color.ts`, imported as `@hcm/ui/dynamic-color` (a separate entry point, so the main entry and every node test of the engine and admin never load the colour library) (also `contrastRatio`, `contrastIssues`; an invalid seed falls back to `DEFAULT_SEED_COLOR`). The tokens are precomputed into the manifest (the admin, or `node packages/ui/scripts/gen-theme.mjs --seed '#8B5E3C'`), so the viewer never ships the colour library. Unit tests require WCAG 4.5 for every text pair in the standard schemes and 7 in the high-contrast ones for a set of hard seeds; axe checks contrast per theme in the tour tier.
- The library's ESM files import without file extensions: fine for Vite and Vitest, but plain Node needs the resolve hook the CLI scripts register (`scripts/seed/migrate-legacy.mjs`).
- **Shape and motion**: the M3 shape scale, spring-derived motion curves; `prefers-reduced-motion` disables fly animations.
- **Fonts**: self-hosted Roboto Flex (`latin`, `latin-ext`, weight axis) and a Material Symbols Rounded subset holding only the names of `ICONS` (`packages/ui/src/icons.ts`: the kit's, the viewer's and every `POI_ICONS` name); never Google Fonts (GDPR). The families are namespaced (`HCM Roboto Flex`, `HCM Material Symbols Rounded`: `TEXT_FONT_FAMILY`, `ICON_FONT_FAMILY`) and registered through `document.fonts` by `installFonts(document, baseUrl)`, the kit's only global side effect (an `@font-face` inside a shadow root is ignored, an injected stylesheet would break the CSP). An icon used anywhere is first added to `UI_ICONS`, then `npm run fonts:build --workspace @hcm/ui` rebuilds the subset; the static gate `fonts` (`fonts:check`) fails when the committed files differ or a name does not shape to one glyph. The engine build copies `packages/ui/fonts/` to `dist/fonts/`.
- **Inline styles only through the CSSOM**: never Lit's `styleMap` (ESLint refuses its import) or a `style=${…}` binding (the e2e console guard catches it). Their first render writes a `style` attribute, which the city page's CSP (`style-src` without `'unsafe-inline'`) refuses, so a kit slider or progress bar logged a CSP violation in the viewer smoke. Use the element directive `cssProperties({...})` (`packages/ui/src/components/css-properties.ts`), which sets and removes custom properties with `style.setProperty`. Lit's own styles use adopted stylesheets, which the CSP allows.
- **Stacking**: the viewer sets `--hcm-sheet-z-index` so the kit's modal sheets cover its floating controls; the open FAB menu sits above the consent banner and the snackbar. The modal sheets and the lightbox are positioned against the viewer's modal layer, which ends above the legal bar (the Mapbox logo and attribution, z-index 32), so no modal surface covers them; About uses the native `<dialog>` (top layer) and carries its own copy at its foot. A modal surface over another makes the one beneath inert: under the lightbox the viewer's modal sheets are `inert` (the tour found the photo sheet's image, handle and Close usable beneath it).
- **Floating controls stack with M3's 8 px**: the viewer's strip at the map's foot (`--hcm-map-chrome`, 42 px: Mapbox's collapsed attribution, 24 px at 10 px from the edge, plus 8), then the timeline (`--hcm-timeline-block`, 84 px, which `hcm-timeline` holds whatever the page's font: no `ol` margin), the FAB (`--hcm-fab-size`) and on compact the chip a row above it, each `--hcm-dock-gap` apart; on a short phone the top docks (toast, consent) end before the vertical timeline (`--hcm-timeline-inline`). A dock or popup is a box around what it draws: the menu's and toast's docks and `hcm-fab-menu`'s host take no pointer, only the FAB, the items and the snackbar's surface do (`docs/LESSONS.md` #57, #58). Where the FAB sits beside the taller timeline (medium and up), the open menu's items end `--hcm-fab-menu-gap` (8 px above the timeline, not above the FAB): wider than the FAB, its last item lay on the timeline's thumb at 768 px (the visual audit; the open menu may cover only the map's content and the two top docks).
- **Focus rings on coloured surfaces**: `focusRing` (and the viewer's own `:focus-visible`, and the admin's `adminBase` since CR-M2c-29) draws `--hcm-focus-ring-color`, secondary by default; a surface close to secondary sets it for everything on it (the snackbar: inverse primary; the error card: on-error-container). Mapbox's attribution is white in every theme, so the viewer gives it `light-dark()` of primary and inverse primary (`docs/LESSONS.md` #60). A ring is drawn where nothing clips it: a control that fills or touches the edge of a box that hides its overflow draws its ring inside (the map canvas `outline-offset: -3px`, the sheet's drag handle a round ring inside its 48 px box), and Mapbox's full attribution gets the 3 px its links' offset-free rings need (`docs/LESSONS.md` #68).
- **No `header` inside a component**: a dialog's, sheet's or lightbox's title row is a `div.header`; a `header` outside sectioning content is a page banner, and axe found a second banner under the lightbox and one inside the admin's top bar. A dialog's name comes from its headline (`aria-labelledby`) or `aria-label`; a `nav` always has a name (the lightbox's `lightbox.navigation`).
- **Never lay out on `:host` what a page can undo**: a page's style on the element (`hcm-map-viewer { display: block }`) beats the component's `:host` rule, so a grid or flex layout lives on an inner wrapper (the viewer's `.viewer`); `:host` keeps only what may be overridden (`docs/LESSONS.md` #23).
- **The kit's snackbar positions itself** at the bottom of its positioned container (`:host { position: absolute; bottom: 16px }`): an app that docks it elsewhere sets `position: static` on it from outside (the viewer's top toast dock), or it lands off screen.
- **Text on a fixed backdrop**: the lightbox scrim is dark in every theme, so no theme colour is drawn on it directly: its header and error message sit on `surface-container` with `on-surface` text, its arrows are tonal icon buttons. Colours stay tokens (stylelint forbids hex and named colours). The scrim is opaque (a translucent one let the photo sheet and the menu show around the photo), and the stage's single track is `minmax(0, 1fr)`: an image's percentage `max-block-size` inside an `auto` grid track resolves against its own height, so a landscape photo on a short window was cropped instead of fitted.

## Adaptive layout

- Window classes are measured on the **host element** with container queries and a `ResizeObserver` (which also calls `map.resize()`), not on the viewport: compact below 600, medium 600–839, expanded 840–1199, large 1200–1599, extra-large from 1600 (`'extra-large'`); compact height below 480 for landscape phones (`WINDOW_CLASS_BREAKPOINTS`, `windowClassFor`, `isCompactHeight`, `WindowClassController`).
- Touch targets at least 48 dp (`TOUCH_TARGET_MIN_PX`), safe areas, `dvh`, logical properties. A control drawn smaller (the slider's 4 px handle, the timeline's 40 px thumb, the 40 px icon button and button, the 32 px chip) gets the `touch-target` class and the kit's `touchTarget` styles (a centred 48 × 48 `::after`), and nothing may hide its overflow: `touchTarget` sets `overflow: visible` above the state layer's `.interactive { overflow: hidden }`, which had cut every kit button's ring to its own box (LA-6; `packages/ui/test/components/touch-target.test.ts` hit-tests the ring, as the tour's `targetSizeOf` does); a link of a list is 48 px tall (`detailStyles`); a link inside a sentence is exempt (WCAG 2.5.8).
- Rings never cover rings (LESSONS 69, 70): 40 px buttons in a row keep 8 px apart and 32 px chips' wrapped rows 16 px (`row-gap: 16px`), a short link gets `min-inline-size: 48px`, a check box is M3's (an 18 px box with a 2 px `on-surface-variant` border, `appearance: none`, the class `touch-target`; a native one reaches 1:1), and a file chooser is a `hidden` input opened by a kit button (a visually hidden input inside a label fails non-text contrast and focus obscured). `hcm-toolbar`'s roving `tabindex` sits on its slotted hosts, which hides their shadow buttons from Tab: the tour's Tab round reports them as never reached, so a tool row the user must Tab through is a named `role="group"` of separate stops (the places editor's drawing tools).
- Floating controls carry `data-layout-check="<name>"` (the viewer's timeline, note, chip, menu, consent banner and toast), but the tour no longer depends on the marks: its generic checker finds the kit's floating components itself (`hcm-fab-menu`'s FAB and menu, `hcm-timeline`, `hcm-toolbar`, `hcm-chip`, `hcm-snackbar`, `hcm-consent-banner`, `hcm-sheet`, the admin's navigation and top bar, Mapbox's controls) and checks that no two overlap, that floating touch targets keep 8 px apart on compact and medium, and that every control is on top where it is drawn (`docs/TESTING.md` → *The tour's checkers*). A popup's host must not stay a hit target where nothing of it is drawn: the open FAB menu may cover what is beneath its items, not more. On compact the "photos near this year" chip sits a row above the menu button; on a landscape phone the FAB menu is at most `--hcm-fab-menu-max-block-size` tall and its items continue in a second column (a scrolling menu would not be keyboard-reachable). The menu docks on the leading edge there and sets `--hcm-fab-menu-align: flex-start`, so the FAB and its items line up on that edge: aligned to the end, the wider wrapped menu moved the FAB from under the finger. A control must never move when it is tapped (the tour cannot see this: check the screenshots).
- What the M2d review screenshots taught (`docs/LESSONS.md` 124–127): a list item's leading icon is its own column beside both lines (`.row[data-lead]` of the reorder rows), never inline in the title; a rule spanning several fields (the city's four edges) is said once below them, each field `aria-invalid` and described by that one message (`issueShownAt` of `form-parts.ts`); help text describes only what the screen has.
- What the M2c review screenshots taught (`docs/LESSONS.md` 81–84): a box sized for one state is sized for each (the admin map's box collapses to its note with `[no-map]`); paired RO and EN fields keep two columns (`.fields.pairs`), never `auto-fit` across pairs; a navigation bar's label gets the whole item (no inline padding) and is measured in the kit's own font ("HCM Roboto Flex") by a test that fails on a word split over two lines; a chosen row that holds controls is ringed, never filled, so its fields keep their contrast against the surface.
- What the M2e review screenshots taught (`docs/LESSONS.md` 141–142): an editor with a map brings the item it opens into view once (the photos map session's `reveal`, the places map's `#reveal`: the centre moves, the zoom stays, no animation; a new place with nothing drawn and an edit of the open item move nothing), because a list's items lie anywhere in the city; in a grid of cards the visible card fills its stretched grid item (`.tiles > li { display: flex }` and the tile `flex: 1 1 auto`), or a row's cards differ in height when one label wraps. The tour matrix then found (143, 147): a height class measured on the page area is compact on a 320 × 568 portrait phone while its bar shows, so a landscape-phone layout also asks for a medium width, and a box that is only a note never shrinks (`flex: none`); the bar's labels follow their item's width (`17cqi`) below about 70 px, measured at 320 px too.
- **Large and extra-large** (the review of the 2560 × 1440 screenshots, `DECISIONS-for-review.md` §41d): a form stays at most 840 px wide (M3's readable width) and a list 360 px (412 px from 1600); on an extra-large page a map-centric editor makes its map a supporting pane beside the form instead of a strip above it (`packages/ui/src/admin/editing/wide-layout.ts`: `mapBesideStyles` for a page whose `.detail` holds the map box then the item, the form 480 px; `paneMapBesideStyles` for an editor whose pane holds the map among its groups, the groups 560 px and the map kept in view). The selectors read `hcm-list-detail[split][window-class='extra-large']` (the page's own width class) and apply only to a map that shows (`hcm-admin-map:not([no-map])`). Keep the map first in the DOM where it comes first in the stacked layout, so the Tab order follows what is seen.
- **Dates** are never `<input type="date">`: its pattern follows the browser's language (`mm/dd/yyyy` in an American browser, inside a Romanian page). Use the M3 date input field: a text field with the pattern as its hint and placeholder (`adminContent.common.datePattern`: `zz.ll.aaaa`, `dd/mm/yyyy`), `formatDateInput` and `parseDateInput` of `packages/ui/src/admin/editing/date-text.ts` (day first in both languages, any of `.` `/` `-`, a day that does not exist is no date); `form-parts.ts`' `type: 'date'` does it for the layer editor.
- Romanian labels are long: a control's width comes from its content and its container, never an equal share. `hcm-segmented-button` segments are content-sized (`flex: 1 1 auto`), never wider than their container, and a long label wraps inside a taller segment instead of scrolling the page sideways; at compact width the About dialog drops the theme icons (only the check mark stays). A layout test measures label heights and the container's `scrollWidth` (`packages/ui/test/components/segmented-button.test.ts`). Single words that still do not fit stack one segment per row (`stacked`, decided on the next frame after a resize); only new labels measure them side by side again, so a parent that builds its options in `render` (a new array with the same segments on every update) never flashes the row past the dialog's edge (`docs/LESSONS.md` 295). An element that re-measures on a property change compares what the property draws, not its identity.
- A container query or media query that narrows a component comes after the base rule it overrides: at the same specificity the later rule wins, so a narrow rule written first is dead code that looks applied (the georeferencer's residual table kept its 8 px cell padding on phones until six far pairs scrolled it sideways, `docs/LESSONS.md` 181). A table lets its cells wrap (`nowrap` cells cannot shrink, and a reader's text spacing widens every one); measure it with the longest data it can hold and under the checker's text-spacing sheet (`packages/ui/test/admin/georef/residual-fit.test.ts`).
- Mapbox's attribution is white in every scheme and colours only its links: a map that shows a layer's plain-text credit gives `.mapboxgl-ctrl-attrib-inner` the links' colour (`rgb(0 0 0 / 75%)`), or the dark scheme's light text reads white on white (`docs/LESSONS.md` 182, `packages/ui/src/admin/map/hcm-admin-map.ts`).
- A sibling margin of a shared style (`detailStyles`' `.details li + li`) must not reach a list laid out by a grid or flex `gap`: the margin adds to the gap and pushes every later item down (the POI sheet's second photo thumbnail sat 4 px lower; `docs/LESSONS.md` #22). Reset it in the component and measure the items' edges in a unit test.
- Navigation: bottom sheet and navigation bar on compact, side sheet and rail from medium; no drawer.
- A bottom sheet's drag handle is a 48 × 48 button at the sheet's top edge with the 32 × 4 bar in its middle (M3): a smaller handle's ring rose past the sheet, which hides its overflow, and was cut to 36 px. A segment of `hcm-segmented-button` is at least 48 px wide, so its ring never sticks out of a narrow container (a ring that reaches past a box is scrollable overflow once nothing hides it).
- A docked sheet fills its pane and its body scrolls: every box between the pane and the sheet passes a definite height (the photo list's wrapper is `display: contents`); one auto-height wrapper let the list grow past the pane's hidden overflow (`docs/LESSONS.md` #59). An `hcm-sheet` hides its empty `actions` row.
- A title that may not fit wraps (`overflow-wrap: anywhere`); an ellipsis is a cut label to the tour, and WCAG 1.4.12's text spacing found the lightbox's on a 320 px phone.
- The admin (`packages/ui/src/admin/`, entry `@hcm/ui/admin`, M2b): a navigation bar on compact windows, a collapsed rail from medium, the expanded rail (labels beside the icons, not modal) from large, and on a landscape phone (compact height) a rail with the account button at its foot and no top bar. It is an app shell: the frame is as tall as the window and only the page scrolls (`.scroller` in `<main>`), so nothing ever scrolls under the bar, the rail or the top bar (a focused control there was hidden, WCAG 2.4.11, and a target half covered, `docs/LESSONS.md`); the snackbar is docked below the page in `<main>` and takes no room while empty (it floats only over the frame-less panels); the bar's More sheet covers the frame; every screen's content is in `<main>`; a rail label too wide for the rail wraps inside it. The Setup page is one column below 840 px and list and detail from there (the detail at most 840 px wide); it follows only its own width class and applies a change on the next animation frame, because changing its layout from the `ResizeObserver` callback resized what it observed (`docs/LESSONS.md` 45). A card re-created by a layout change keeps nothing of its own: typed fields live in the controller's state.
- The tour tier (`e2e/tour/viewer.tour.ts`, states in `e2e/tour/states.ts`) checks every state at 11 viewports, light and dark, RO and EN, through the generic layout and accessibility checkers: occlusion, overlap and spacing of floating chrome, edges and cut-off content, Mapbox's legal line, clipped and overlapping text, axe with best practices, 24 px targets everywhere and 48 px on compact and medium, a full Tab round with 3:1 focus rings, non-text contrast in the scheme and in high contrast, landmarks, announcements, text spacing and reflow at 320 px, the i18n leak check, and no box that scrolls sideways inside the page; the admin's states run the same checks at its five projects (the dark scheme among them). A segmented button whose segments cannot fit side by side, even with wrapped labels, stacks them one 48 px row each (`stacked`): the theme choice of the admin's account menu at 360 px and of About at 320 px ran past the dialog, which scrolled sideways.

## Accessibility

- A toggle `hcm-button` sets `.pressed` (true or false), which its inner `<button>` states as `aria-pressed`; ARIA on the host names nothing (the focus is delegated to the inner button). Undefined is no toggle.
- A text button inside an error-container `.alert` reads in `on-error-container` (`editingStyles`); icon buttons on the bulk bar in `on-secondary-container` (an overflow menu's button through its exported part `more-button`): the defaults fail 3:1 or 4.5:1 in high contrast.
- A lazy area chunk defines every element it renders (`<hcm-admin-map>` in the settings chunk: lesson 136); `packages/ui/test/admin/editing/areas.test.ts` checks the map-showing chunks.
- Every interactive element has a role and an accessible name; keyboard order follows the visual order; focus returns to the opener when a dialog or lightbox closes.
- Move the focus before announcing an action: a menu closes and focuses its button, then fires `hcm-select`, because whoever reacts records the focused element as the opener (a vanished menu item left the focus on `<body>`; `docs/LESSONS.md` #12).
- Never disable or remove the control that has the focus without moving the focus first: Chromium drops it to `<body>`, where Esc and the arrow keys no longer reach the dialog (the lightbox's Next button on the last photo; `docs/LESSONS.md` #19).
- `hcm-dialog` keeps 4 px between its scrolling content and its actions, so an action's 48 px touch target never covers the control the content shows at its edge (CR-M2c-29).
- **The editors' number fields** (`packages/ui/src/admin/editing/number-fields.ts`): bind `.value` with `numberValue(text)` (it leaves the admin's own spelling of the same number, and an unfinished one, under the cursor), commit on `input`, and show the problem only for fields in `LeftFields` (left once since the item opened, `@focusout`).
- Every modal (native `hcm-dialog`, a modal `hcm-sheet`, the lightbox) traps Tab with `trapTab`; Shift+Tab on the focused container itself wraps to the last control, so a modal that focuses its container on open is never left backwards.
- A live region exists, empty, before the text it announces: one created together with its text is not announced. `hcm-snackbar` keeps a visually hidden polite region and fills it with the message alone `ANNOUNCE_DELAY_MS` after it shows (`docs/LESSONS.md` #20); the overlay list's region is always rendered.
- Forced colours stay readable; nothing is conveyed by colour alone.
- Tests: Vitest browser mode with `page.getByRole`, keyboard interaction, RO and EN strings, window-class variants, reduced motion (`quality/testing_strategy_skill.md`).
