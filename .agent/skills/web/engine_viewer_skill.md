# Engine Viewer Skill

The public viewer engine `@hcm/engine` (`packages/engine`): a data-driven historical map of one city, embeddable by any city owner. Public contract: `docs/ENGINE_API.md` (config.js, `<hcm-map-viewer>`, the JavaScript API, the URL hash, the City Manifest v1, versioning). The interfaces the M1 workstreams build on (MapPort, the viewer store, telemetry, UI inventory, module ownership, change requests): `docs/research/M1-interfaces.md`. Architecture: `docs/ARCHITECTURE.md` → *Engine (public viewer)*; plan: `docs/research/PLAN.md` → *Engine*. M1 built it; how the parts were joined is `docs/research/M0-handoff.md` §10j.

## Where the code is

- `packages/engine/src/index.ts`: the release facts (`ENGINE_VERSION`, `MAPBOX_GL_VERSION`), `mount`, `defineElements` and the auto-boot, wired to the browser. `packages/engine/src/mount.ts` makes every decision behind a DOM-free `MountEnvironment`, so its node tests drive it with fakes.
- `packages/engine/src/config/load.ts` (configuration, manifest fetch with a 15 s timeout, retries on network errors and 5xx), `packages/engine/src/core/` (the viewer store: `store.ts`, `boot.ts`, `state.ts`, `timeline.ts`, `url-sync.ts`, `map-sync.ts`, `map-specs.ts`, `preferences.ts`), `packages/ui/src/map/` (the MapPort and its Mapbox adapter, the `@hcm/ui/map` entry shared with the admin since CR-M2c-1 of `docs/research/M2c-interfaces.md`), `packages/engine/src/telemetry/` (consent, lazy analytics, crash reports).
- The viewer's Lit elements (`<hcm-map-viewer>`, the timeline, the sheets, the lightbox, About, the error card) live in `packages/ui/src/viewer/` under the ownership override (one owner per tag, next to the kit they are built from). `@hcm/ui` cannot import the engine, so `packages/ui/src/viewer/store-port.ts` mirrors the store's shape and `mount.ts` checks at compile time that the real store satisfies it.

## Contract

- **Build**: `npm run build --workspace @hcm/engine` runs `packages/engine/vite.config.ts` (`dist/engine.iife.js` with the global `window.HistoricCityMap`, `dist/engine.mjs` with its lazy `firebase-sdk-<hash>.js` chunk, `dist/engine.css`), then `fonts:copy` puts the kit's self-hosted fonts and their licences into `dist/fonts/`; a site copies every file of `dist/`. `mapbox-gl` is **external**: the engine reads the page's global `mapboxgl`, which pages load as Mapbox GL JS **3.32.0** from `api.mapbox.com` (`MAPBOX_GL_VERSION`). Never bundle it or import it.
- **Config**: `window.HistoricCityMapConfig = {cityId?, manifestUrl? | manifest?, container?, lang?, engineBase?}`, validated with `engineConfigSchema` from `@hcm/shared` (exactly one of `manifestUrl` and `manifest`; the inline manifest is the starter kit's static mode). Both builds auto-boot into `container` (default `#historic-city-map`; the city pages load `engine.mjs`, CR-6); a missing or invalid config shows an instructive error card (scenario V17). The engine finds its own folder (for `fonts/`) from `import.meta.url`, or from the running script in the IIFE build, where Rolldown empties `import.meta` (`engineBaseOf`).
- **JavaScript API**: `HistoricCityMap.mount(element, config)` returns a controller `{ready, setYear, toggleLayer, setOverlayOpacity, openPhoto, openPoi, setLang, openCompare, setComparePosition, closeCompare, destroy}`; the element `<hcm-map-viewer>` fires `hcm-ready`, `hcm-error`, `hcm-layer-change`, `hcm-overlay-change`, `hcm-photo-open`, `hcm-poi-open`, `hcm-compare-change` (scenarios V21, V06).
- **Data**: the viewer fetches only the static `manifest.json` and the photo WebP files from the public bucket (`gs://<proj>-public/cities/{city}/...`); the Bucharest site reads the bucket's manifest when its build names the bucket (`HCM_PUBLIC_BUCKET`, `site.json` → `publicManifest`, `scripts/site/src/public-manifest.ts`), else it bundles the seed snapshot (`DECISIONS-for-review.md` §51e, §55a). It **never reads Firestore** and loads no Firebase SDK for data. The analytics SDK (GA4 only, never Performance Monitoring) loads lazily, only with a `measurementId` in the manifest **and** the visitor's consent, and never sees the hash (`firebase/analytics_and_crash_skill.md`).
- **Manifest**: City Manifest v1, `manifestSchema` in `packages/shared/src/schemas/manifest.ts`, every object strict. Before the schema, `checkManifestCompat` refuses another `version` and a `city.engine.minVersion` newer than the engine; then `validateManifest` returns `{path, code}` issues whose codes are `validation.*` i18n keys. A failure shows a localized error card, never a blank map (V01); an invalid manifest's card names its first issue (`issuePath: <localized validation message>`, from the error's `issuePath` / `issueCode` params). A configuration error card speaks the address's language first (`?lang=` or `#…&lang=`), then the configuration's.
- **URL hash v1**: `encodeHash` / `decodeHash` in `packages/shared/src/url/hash.ts` (`#zoom/lat/lng[/bearing]&layers=&opacity=&op=&photo=&lang=`), defensive and clamped; the legacy `#zoom/lat/lng/rotation/!a3!p2` opens its view and is rewritten. Decode with the manifest's overlay ids (`HashLimits.overlayIds`) so `op=` entries of unknown overlays are dropped. The old single `opacity=` applies to the visible historical layers only (apply the hash's `layers=` first); `op=` entries win. The store writes the hash at most every 300 ms and never over a hash the address gained in between (a typed link or history navigation wins).
- **Overlays** (PLAN Addendum 3): every historical layer, the photos (`PHOTOS_OVERLAY_ID`) and every POI category is an overlay with `visible` and `opacity`, built and updated only through the pure overlay model of `@hcm/shared` (`packages/shared/src/overlays/model.ts`: `overlaysFromManifest`, `withOverlayOpacity`, `withOverlayVisibility`, `withHashOpacity`, `hashOverlayOpacity`). Paint property names come only from `overlayOpacityPaint` and `rasterAdjustmentPaint` (`packages/shared/src/overlays/paint.ts`). Layer ids, `photos` and category ids are one namespace, enforced by the manifest schema.
- **POIs**: `poiCategories[]` and `pois[]` (GeoJSON Point, LineString or Polygon) in the manifest; the store hands the map only the POIs `poiInYear` keeps for the timeline stop (all at "today"); an icon the engine does not bundle is drawn as `poiIcon`'s default pin; details open in the same sheet as photos.
- **Element**: the viewer is a Lit custom element `hcm-map-viewer`, no decorators, registered by an idempotent `define…()` function (`web/ui_m3_adaptive_skill.md`). The engine sets `mapboxCssUrl` (mapbox-gl.css is linked inside the shadow root), `engineVersion` and `bootError`, and connects the store with `attach(store, controller)`; `mapContainer` is the stable `<div>` the map mounts into. Public events come from store transitions; a slider drag announces once, on release.
- **Store actions the UI uses** (`docs/research/M1-interfaces.md` §6 plus CR-8 and CR-17): `setView` only records the map's view (the `moveend` path), `flyTo(view)` moves the camera ("show my location"), `logShare()` sends the `share` event after a completed share or copy; `destroy()` also destroys the map exactly once and telemetry.

## Map

- **One seam**: the core (state, timeline, controller, manifest → layer specs) talks only to `MapPort` (`packages/ui/src/map/map-port.ts`, M1; the exact interface is `docs/research/M1-interfaces.md` §4). `packages/ui/src/map/mapbox-adapter.ts` is the only file that touches `mapbox-gl`; dependency-cruiser enforces it. The core is tested against `FakeMap`, the adapter in Vitest browser mode against the real `mapbox-gl@3.32.0` (dev dependency, exactly the CDN version) with a local style and synthetic tiles.
- **Basemap**: Mapbox Standard Satellite. Historical rasters go into the `middle` slot; 3D buildings are off while a historical layer is shown, and only when the style has the `basemap` import.
- **Sprites** are drawn on a canvas (`packages/ui/src/map/icons.ts`, nothing fetched): photo markers are 22 CSS px discs with a bearing pointer, clusters 30 px; a POI glyph is drawn with the kit's icon font, whose family is `ICON_FONT_FAMILY` of `@hcm/ui` (`HCM Material Symbols Rounded`), never a hard-coded name (a wrong name silently draws every POI as a dot). A sprite drawn later replaces its placeholder with `updateImage`, which does not repaint an idle map in Mapbox GL 3.32: follow it with `triggerRepaint()`, or a glyph whose font arrives after the map settled stays invisible until the visitor moves the map (`docs/LESSONS.md` #21, `S-V24-BAD-ICON-FONT-LATE`).
- **Settings**: `performanceMetricsCollection: false`; the Mapbox logo and attribution are always visible (also collapsed on compact, scenario V18). Nothing may cover them: while a modal sheet, the lightbox or About covers the map (the frame is `inert` then), the viewer hides Mapbox's bottom controls (`data-legal-mirror` on the frame) and mirrors them in `<hcm-map-attribution>`: the logo of mapbox-gl.css and the text and https links read from Mapbox's own attribution control by a `MutationObserver` (`attribution.ts`), in the legal bar below the modal layer, or at the foot of About (top layer). The layout is an inner grid `.viewer` (never the host, whose `display` a page may set): the frame spans both rows, the modal layer (the sheets' and the lightbox's containing block) fills the first, the bar the second (`viewer-legal.ts`, `viewer-render.ts`; `docs/LESSONS.md` #23). The tour checks one visible logo and one attribution, on top, in every state. Floating controls keep the map's bottom 42 px free (`--hcm-map-chrome`: the collapsed attribution plus M3's 8 px) and stack 8 px apart (`web/ui_m3_adaptive_skill.md`). Mapbox writes its UI strings (the canvas's name, the logo link, the attribution toggle) once, when its controls are created: a language switch reaches them through `MapPort.setLocale`, which rewrites them in the map's container and calls `setLanguage` for the basemap's labels (`relabelMapbox` in `packages/ui/src/map/lifecycle.ts`; CR-22, `S-V11-BAD-MAPBOX-LABELS`).
- **Sources**: `mapbox://` tilesets, `xyz` and later `pmtiles`; each layer has `minzoom`, `maxzoom`, `bounds`, opacity and order from the manifest.
- **One map per view** (cost): Mapbox bills map loads. Swipe compare (M4) creates its second map lazily and destroys it on exit; a compact window hides it for `COMPARE_PARK_MS` (a minute) before destroying it, so a phone turned back and forth reuses it (the 2026-10-24 review, `DECISIONS-for-review.md` §57c); the e2e map-instance counter asserts it. The chooser leaves out what the main side shows (`compareChoices`), keeping the side compared now. Compare is the engine's own (no `mapbox-gl-compare`, `DECISIONS-for-review.md` §52a, built in §55): the store keeps `compare` (`{layerId, position}`, `packages/engine/src/core/state.ts`; the mode follows the window class: `toggle` below 600 px, where `displayedOverlays` swaps the one map's historical layers, else `swipe`), the hash carries `cmp=`/`sw=`, and `packages/engine/src/core/compare-driver.ts` fetches the lazy chunk (`packages/engine/src/compare/compare.ts` → `compare-<hash>.js`, budget `ENGINE_CHUNK_BUDGETS` of `scripts/ci/check_bundle_budget.py`) once the map is ready. The chunk's session (`packages/engine/src/compare/session.ts`) puts `<hcm-compare>` (`@hcm/ui/viewer/compare`, never `@hcm/ui`'s root) after the map's container and, in swipe mode, mounts the second map in it (inert, pointer-transparent, clipped right of the divider), drawn by its own `MapSync` from `comparedState`, its camera linked by MapPort's `move` (`packages/engine/src/compare/camera-sync.ts`). The legal line stays the viewer map's (its controls sit above the second map; the bar credits the compared layer). `packages/engine/vite.config.ts` keeps what the chunks share in `engine.mjs` (`preserveEntrySignatures: 'allow-extension'`; Vite's library default split a third chunk). Contract: `docs/research/M4-interfaces.md` §3 and CR-M4-16; `docs/ENGINE_API.md` → *Compare*; tests: `packages/engine/test/compare/`, `packages/ui/test/viewer/compare/`, `e2e/specs/viewer/compare.spec.ts`, the tour's journey `compare` (`e2e/tour/compare-states.ts`).
- **No WebGL**: `mapboxgl.supported()` false or a lost context shows a fallback card; the photo list still works (scenario V02).
- **Error card and visitor copy**: an M3 error container (`error-container`, `on-error-container` text and icon) with Retry as a filled tonal button with the refresh icon. Errors a visitor can meet say what happened and what to do in plain words, never "manifest", "WebGL", "JSON", "engine" or "tiles"; only `error.config.*` (a misconfigured page) speaks to the city owner (`docs/LESSONS.md` #26; `S-V01-HAPPY-ERROR-CARD`, `S-V01-BAD-PLAIN-WORDS`).
- **Skip link and lists**: the skip link is the first Tab stop and shows at the map pane's corner, past a docked leading pane, never over its heading (`S-V14-HAPPY-SKIP-LINK-CLEAR`). A photo list row is an M3 list item: title body-large, date body-medium supporting text (14 px) that wraps (`S-V07-HAPPY-LIST-DATES`).
- The service worker (if any) never caches `api.mapbox.com` or `*.tiles.mapbox.com` (Mapbox Product Terms).

## Features (scenario ids in `e2e/scenarios.json`)

- Boot, errors and retry (V01); layer toggles with attribution (V03); timeline year scrubber with the photo year filter (V04; a city without layers shows the note `timeline.empty` instead of a timeline: Bucharest until M3); opacity (V05); raster image adjustments (V25); swipe compare (V06, M4: the second map only from 600 px wide, a toggle below).
- Live opacity of every overlay (V22), overlay opacities in the URL hash (V23), points of interest with the year filter and the detail sheet (V24); the e2e fixture manifest adds the POI set `scripts/seed/e2e-pois.json` (`docs/research/M1-interfaces.md` §10).
- Photos: clustered camera icons rotated by bearing, view cones from zoom 17 (`conePolygon` from `@hcm/shared`; a photo without a bearing gets no cone), bottom sheet on compact and side sheet from medium, lightbox, "photos near this year" (`isPhotoNearYear` and `PHOTO_YEAR_WINDOW` of `@hcm/shared`, one rule for the map and the chip), the rights holder under the licence (V07, V08).
- URL hash state (v1: the view, `layers=`, `opacity=`, `op=`, `photo=`, `lang=`; the legacy hash too), share, geolocate (V09, V10). A hash id must match `^[A-Za-z0-9_-]{1,40}$` and is looked up in a `Map`, never put into a selector. The hash is shared with the visitor: the debounced writer remembers the hash it last wrote or adopted and never overwrites one the address gained since, and a `hashchange` wins (`docs/LESSONS.md` #16).
- The city page (`scripts/site/src/page.ts`) is one `main` landmark with a visually hidden level-one heading (the site's title, `hcm-visually-hidden` of `packages/engine/src/engine.css`) around the mount point, so all the viewer draws is inside a landmark (axe's `landmark-one-main`, `page-has-heading-one`, `region`; `docs/ENGINE_API.md` → *The three files of a city*).
- About, credits and privacy notice in RO and EN (V13); language and theme (V11, V12); keyboard and screen reader (V14); responsive at every window class (V15); privacy and cost (V16); starter kit (V17); legal (V18); consent (V19), crash reporting (V20) and the embed API (V21).

## Rules

- Rendering: Lit templates and `textContent` only; Mapbox popups use `setDOMContent`; About and privacy are rendered by walking `parseMarkdown(...).paragraphs` into DOM nodes (`web/web_security_skill.md`). Inline styles only through the CSSOM (`cssProperties`, `web/ui_m3_adaptive_skill.md`): the city page's CSP refuses a `style` attribute.
- Every string in `@hcm/shared` i18n catalogues, RO and EN (`web/i18n_skill.md`).
- Logging through `createLogger('engine', …)`; no `console`.
- A user-visible change edits its scenario rows (`quality/e2e_scenario_matrix_skill.md`).
