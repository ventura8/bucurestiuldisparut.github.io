# Web Security Skill

Security rules for the viewer, the admin and every page they load. Background and exact policies: `docs/research/design-review-security-cost.md` §1.

## No HTML from data (hard rule)

- Render with Lit templates (auto-escaping) and `textContent` only; Mapbox popups use `setDOMContent`.
- ESLint bans `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `setHTML`, `setHTMLUnsafe`, `document.write`, `eval`, `new Function`, and the Lit `unsafeHTML` / `unsafeSVG` / `unsafeMathML` directives (`eslint.config.js`, plus `eslint-plugin-no-unsanitized`). Never relax these.
- Legacy data contains HTML anchors (`seed/bucharest/photos.legacy.geojson`): the migrator (`packages/shared/src/migration/html.ts`, a linear scanner, no DOM, no backtracking regex) turns them into structured `links: [{url, label}]` (https kept; http upgraded only for `facebook.com`, `flickr.com`, `costingheorghe.ro`; anything else dropped) plus plain text; `<script>`/`<style>` content is discarded. No HTML is stored.
- Rich "About" and privacy text and POI descriptions are a minimal Markdown subset (bold, italic, https links, `\` escapes) parsed by `parseMarkdown` (`packages/shared/src/text/markdown.ts`) into a node tree that is rendered into DOM nodes, never HTML. A non-https link makes the manifest invalid (`validation.markdownLink`); markup in a POI description shows as text (S-V24-BAD-MARKUP-IS-TEXT).
- Mapbox GL parses a source's `attribution` as HTML (it keeps `<a href>` and writes the result with `innerHTML`): the engine escapes `&`, `<` and `>` of the manifest's plain-text attribution first (`attributionText`, `packages/ui/src/map/rasters.ts`; S-V03-BAD-ATTRIBUTION-MARKUP-IS-TEXT). Any new Mapbox source with data in its `attribution` goes through it.
- POI category icons are Material Symbols names (`^[a-z0-9_]{1,64}$`) mapped onto the bundled set (`poiIcon`), never a URL or an SVG from data; colours are `#rrggbb` only.
- Untrusted strings shown as text only: EXIF fields, USGS metadata and HTML error bodies, Nominatim results, AI drafts, Mapbox job errors.

## URLs, ids, uploads

- zod accepts `https:` URLs only (no `user:password@`); image URLs are https or relative to the manifest (no `..`, no `//host`); external links get `rel="noopener noreferrer nofollow ugc"`. Every schema object is strict, so `__proto__` and any unknown key are rejected. Theme token values cannot contain `;`, braces, quotes, `:` or `url(`, so a value never leaves its CSS declaration. The manifest accepts only a `pk.` Mapbox token.
- `#photo=<id>` must match `^[A-Za-z0-9_-]{1,40}$` and is looked up in a `Map`, never used in a selector.
- No SVG upload, ever; the server sniffs magic bytes (never the name or the client's content type), measures the pixel count from the header before decoding, refuses HEIC/HEIF with `apiError.photo.heicUnsupported` (sharp's prebuilt libvips cannot decode it; `docs/research/DECISIONS-for-review.md` §20b) and strips metadata from public derivatives.

## CSP and headers

- **One Hosting origin, two policies** (M6, `docs/research/M6-interfaces.md` §2.2): the public map is the Hosting site's root and the admin lives under `/admin/`; `firebase.json` sends the admin's policy, Trusted Types report-only and COOP as headers on `/admin/**` only, and no CSP anywhere else, so each viewer page keeps its own meta policy and no page gets two (`scripts/site/test/admin-hosting.test.ts` resolves the rules over probe paths; `S-A58-BAD-CSP-PER-PATH` in the e2e). A path of a new kind under the root needs its meta policy, never a header rule.
- **Admin** (Firebase Hosting site `bucurestiul-disparut`, headers in `firebase.json` on `/admin/**`): `script-src 'self'` plus Mapbox GL's CDN folder, Google sign-in (`apis.google.com`), reCAPTCHA and GA4; a narrow `connect-src` and `img-src`; `frame-src` only `'self'`, the auth domains `bucurestiul-disparut.web.app` and `.firebaseapp.com`, Google sign-in and reCAPTCHA; `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`, `frame-ancestors 'none'`, Trusted Types in report-only first, `Cross-Origin-Opener-Policy: same-origin-allow-popups` for popup sign-in, `Referrer-Policy: strict-origin-when-cross-origin`, `nosniff`, a Permissions-Policy. `firebase/rules-tests/test/firebase-config.test.ts` pins them (no inline code or eval, Mapbox only from its versioned folder).
- **Public site** (Firebase Hosting's root since M6, and GitHub Pages; meta CSP only, generated by `scripts/site/src/csp.ts` into each page as its first resource-governing element; the generic city page and the Hosting site's own small pages, `404.html`, the start-up root and the Pages redirect page, have theirs too): `default-src 'none'`; `script-src 'self' https://api.mapbox.com/mapbox-gl-js/ 'wasm-unsafe-eval'` (required by the Standard style) plus GA4's script host; `style-src 'self' https://api.mapbox.com/mapbox-gl-js/`; `img-src` and `connect-src` for `'self'`, Mapbox, the consent-gated GA4/Firebase hosts and exactly the origins the site's manifest and `config.js` name (an https manifest, photo or tile host, the crash endpoint: `scripts/site/src/origins.ts`); `worker-src blob:` and `child-src blob:` (Mapbox's workers); `font-src`/`manifest-src 'self'`; `base-uri`, `form-action`, `object-src 'none'`; no `'unsafe-inline'`, no `upgrade-insecure-requests` (it breaks the http e2e origin). Mapbox GL JS and its CSS load with `integrity` (sha384 of the pinned npm release) and `crossorigin`; `<meta name="referrer" content="strict-origin-when-cross-origin">`. The e2e spec `S-V16-BAD-INLINE-SCRIPT` proves an injected inline script and an unknown image host are refused.
- **A site's `config.js`** is read by the build without running it (`scripts/site/src/config-js.ts`, the TypeScript parser): exactly one `window.HistoricCityMapConfig = …` (or `globalThis.…`) of literal data; a call, a variable, a spread or a computed key is refused, then the data is validated with `engineConfigSchema`.
- Analytics hosts (googletagmanager, google-analytics, firebaseinstallations) are added to the CSP only for the consent-gated SDK; the public viewer no longer loads Performance Monitoring, so its firebaselogging hosts are not in the site CSP (CR-M2-36, `scripts/site/src/csp.ts`).
- No inline `<script>`; a third-party city that loads the engine from jsDelivr pins an exact version with `integrity` and `crossorigin`.
- **The admin's Mapbox GL JS** is added by its first map (`loadMapboxGl`), never by the page: the admin's site build names the digest of the pinned `mapbox-gl.js` in `<html data-mapbox-integrity>` and the loader sets it as the script's `integrity` with `crossOrigin` (`DECISIONS-for-review.md` §34h), so a changed file on the CDN is refused there too.
- **Swipe compare loads no plugin** (V06, M4; the user's decision, `DECISIONS-for-review.md` §52a): it is the engine's own lazy chunk served from the page's origin with the engine, so it needs no CSP source and no Subresource Integrity of its own (the `mapbox-gl-compare` loader and its digests are gone). A third-party script added later would need both, as mapbox-gl has (`scripts/site/src/sri.ts`). A third-party city that pins the engine with `integrity` covers only that file: `engine.mjs` fetches its chunks without one, so such a page loads `engine.iife.js`, which carries them inline (`docs/ENGINE_API.md`; `DECISIONS-for-review.md` §57i).
- **M4's untrusted text** (`docs/research/M4-interfaces.md` §4, §5, §9): Nominatim's names, Gemini's drafts and the notification events' parameters are plain text, length-limited by their schemas (`sanitizeDraft` strips control and invisible formatting characters) and rendered with Lit or `textContent`; Vertex AI is called server-side only (never the Firebase AI Logic client SDK, whose public key would be a billing-abuse vector); FCM push needs the browser's own permission, after the admin turns it on. A draft may keep the source's Markdown links but never add or change one (`draftKeepsLinks`, `apiError.assist.linksChanged`: the viewer renders a description's links; `docs/LESSONS.md` 206). What a browser remembers for an admin names that admin (the push record `{uid, deviceId}`), and sign-out and `admins.revoke` undo what it registered (LESSONS 205). Vertex AI is called with the custom role `hcmVertexDrafts` (`aiplatform.endpoints.predict` only), never `roles/aiplatform.user` (LESSONS 215).
- Nothing compiles code at run time: zod runs `jitless` (`z.config({ jitless: true })` in `packages/shared/src/schemas/primitives.ts`), else it probes `Function('')` and every page view raises a `securitypolicyviolation` that never reaches the console. The e2e CSP specs record violation events, not only console errors (`docs/LESSONS.md` #14).

## Tokens and secrets in the browser

- Mapbox **public** tokens only, URL-restricted to their origin (viewer: the server's `viewerOrigins`, since M6 `<proj>.web.app`, `<proj>.firebaseapp.com` and `https://ventura8.github.io` while Pages stays, re-minted by `ops.tick` when they change, `functions/src/ops/viewer-tokens.ts`; admin `<proj>.web.app` and `<proj>.firebaseapp.com`), scopes `styles:read styles:tiles fonts:read`. Never `no-referrer` or `same-origin` referrer policies (the restriction needs the origin).
- Secret tokens (Mapbox `sk`, USGS app token) never live in the browser beyond the paste box: they go straight to a `setup.*` callable and Secret Manager.
- Google OAuth access tokens (the admin's bootstrap and provisioning steps, `docs/research/M2b-interfaces.md` §2) live in memory only, for at most an hour: never in Firestore, web storage, IndexedDB, a cookie, a URL, a log line or an error report (`redactText` strips `ya29.`); the only places they travel are Google's APIs and, once, `admin.claim`. No refresh token exists in the browser.
- The Firebase web config is never committed; the admin reads `/__/firebase/init.json` on Hosting, and `project.json` beside its page (`/admin/project.json` since M6; a copy of the public `infra/project.json`, written by the admin's site build) names the only project its provisioner may touch.
- **Shared origin, shared storage** (M6): the origin's IndexedDB, `localStorage` and cookies are readable from every viewer page, so the admin's Firebase sign-in lives in its tab's `sessionStorage` (`initializeAuth` with `browserSessionPersistence`, `packages/admin/src/firebase/app.ts`; one sign-in per tab, `DECISIONS-for-review.md` §73a; S-A58-BAD-VIEWER-READS-NO-SIGN-IN), and the admin's `hcm:admin:*` keys are preferences read through fixed parsers, never authority; the viewer's keys are `hcm:<cityId>:*` and the admin's `hcm:admin:*`, and `admin` and `city` are reserved city ids, so they never collide; the admin's GA4 cookies carry the prefix `hcm_admin` and its withdrawal expires only those; the push worker's scope is `/admin/`, and a root-scope worker a pre-M6 admin registered is unregistered before the admin registers its own; a crash report's page decides its service and a page off its `Origin` is refused. `admin-redirect.js` and the Pages redirect page navigate only to a build value (`/admin/`, `<html data-target>`), never to an address taken from the URL.
- The admin's CSP is defined in TypeScript (`scripts/site/src/admin/csp.ts`) and `scripts/site/test/admin-csp.test.ts` keeps `firebase.json`'s header equal to it; the e2e Hosting server sends the same policy (on `/admin/**`) minus `upgrade-insecure-requests`, plus the emulators' and mock APIs' origins, and a test proves those are the only differences. The page has no meta CSP and no inline code.
- App Check (reCAPTCHA Enterprise) protects Firestore and callables in the admin; the public viewer needs none (no Firebase SDK for data).

## Consent and privacy

- GA4 loads only after consent (Consent Mode v2 defaults denied); the decision is stored and can be withdrawn in About, which expires GA4's cookies. GA4 never receives the URL hash (the visitor's view or position), and the public viewer has no Performance Monitoring, which would send it (`firebase/analytics_and_crash_skill.md`).
- No PII in events, logs or error reports; the logger redacts secret-looking keys (`token`, `secret`, `password`, `authorization`, `signature`, `apiKey`) and the query part of signed URLs; free text that leaves a device or a function (a crash report, a log line built from outside data) goes through `redactText` of `@hcm/shared` (`packages/shared/src/text/redact.ts`: URL queries and fragments, `pk.`/`sk.` tokens, `AIza` keys, `ya29.` access tokens, JSON Web Tokens such as Firebase ID and App Check tokens, `token=` parameters, e-mail addresses).
- Self-hosted fonts, no Google Fonts.
