# The interface's languages

Every text of the interface (the viewer, the admin, the Setup Assistant, the start page and the API's error messages) can be shown in 25 languages: `ro`, `en`, `fr`, `de`, `es`, `it`, `pt`, `pl`, `ru`, `uk`, `tr`, `ja`, `zh`, `ko`, `ar`, `hi`, `nl`, `hu`, `id`, `vi`, `bn`, `bg`, `el`, `fa`, `ur` (the owner, 2026-11-12). Arabic, Persian and Urdu are written right to left. Romanian is the default and the source of every key; English is the fallback of every key a language lacks. The rules for writing a text are `.agent/skills/web/i18n_skill.md`; the decision is `docs/research/DECISIONS-for-review.md` §160.

## The languages

`UI_LOCALES` of `packages/shared/src/i18n/locales.ts` is the one list: each language's own name (`UI_LANGUAGE_NAMES`), its direction (`directionOf`), the pickers' order (`UI_LOCALES_BY_NAME`, by the root collation of the names, the same in every language). `scripts/ci/check_i18n.py` holds the same list (a test keeps the two equal) and `scripts/i18n/import_translations.py` accepts only its codes.

- The viewer speaks its sixteen (`VIEWER_LOCALES`, translated and complete, `docs/ENGINE_API.md` → Language); a language of the 25 outside them is added to `VIEWER_LOCALES` once its viewer catalogue is complete.
- The admin, the Setup Assistant (inside the admin's shell), the start page and the API's errors speak all 25. A city's own texts (`{ro, en}`) stay Romanian and English: a reader of any other language sees the English text (`contentLocale`).

## Loading

Romanian and English are bundled. Every other language is a file of the build, never code: the admin's build writes `i18n/<locale>.json` next to `admin.mjs` (Hosting's `/admin/i18n/`), the start page's next to `start.mjs`, each `{"locale", "messages"}` with every catalogue family of that language merged (`scripts/site/src/ui-catalogues.ts`). The page fetches the file the first time the language is chosen (`packages/admin/src/state/ui-language.ts`), adds it to `@hcm/shared`'s registry (`registerCatalogue`), which every translator reads, and only then switches. A first language from the address, the stored choice or the browser shows English until its file is here. A file that cannot be fetched keeps the page's language and says so (`adminShell.language.unavailable`, `start.languageUnavailable`). The viewer's engine fetches its own `i18n/<locale>.json` the same way (DECISIONS §159).

No bundle grows with a language: the files are data beside the bundles, as the viewer's are.

## Fallback

A key the language's file lacks shows in English (`uiText` of `packages/shared/src/i18n/index.ts`); the first such key of a language is logged once per page (`[i18n] a text is missing in this language: English shown instead`). A language with no file at all is all English. The viewer's own sixteen languages are complete, so the viewer shows no text before its file arrives rather than English.

## The pickers

- The admin: the account menu's Language, the 25 by their own names (`UI_LANGUAGE_OPTIONS` of `packages/ui/src/components/language-options.ts`), remembered in `localStorage` (`hcm:admin:lang`, every read and write in try/catch) once the language has taken; `?lang=<code>` chooses one for a visit. `<html lang>` and `dir` follow it.
- The Setup Assistant is a page of the admin's shell: the same menu.
- The start page: a native list in its header (`<hcm-start-language>`), remembered for the session (`hcm:start:lang`); `?lang=<code>` too.
- The viewer: Settings' list of its sixteen, in the URL as it always was (`#…&lang=`).

## Right to left

`dir="rtl"` on `<html>` for Arabic, Persian and Urdu. The kit's styles are logical (`inset-inline-*`, `margin-inline-*`, `text-align: start`); what cannot be logical mirrors under `:dir(rtl)`: the side sheet's entrance (`sheet.ts`) and the indeterminate linear progress (`progress.ts`). The tour checks one right-to-left state of the admin (`admin.shell.language-rtl`, Arabic) and one of the start page (`admin.start.language-rtl`, Urdu).

## The gate

`scripts/ci/check_i18n.py` (the `i18n` static gate):

- Romanian and English stay strictly complete in every folder, one entry per line; the viewer's folders require its sixteen.
- Any other language's file is optional and checked for shape: no key the source lacks, every message non-empty, the same `{placeholder}` names, braces only around them, no edge whitespace, no bidi control, no HTML tag the source lacks. A translation's entry too long for one line may be wrapped by Prettier after its key.
- Once a translation is under way the gate logs each language's completeness (`fr 1648/2806 (58 %)`).
- `--strict` (or `HCM_I18N_STRICT=1`) requires every language of the 25 in every folder with every key: the owner switches it on once the translations are complete.

## Importing translations

A local model writes one file per family and language in the catalogues' layout (`<folder>/<locale>.ts`, `.` for the viewer's main family). To import them:

```bash
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp/hcm-home -v "$PWD:$PWD" -v /path/to/i18n-out:/i18n-out:ro -w "$PWD" hcm-quality:local \
  bash -c 'mkdir -p $HOME && python3 scripts/i18n/import_translations.py /i18n-out [--locale fr] [--dry-run] \
  && npx prettier --write packages/shared/src/i18n && python3 scripts/ci/check_i18n.py'
```

Each entry passes the gate's checks for an optional language or is left out and listed (its key keeps showing in English); what passes is merged with the language's file already there, in the source's key order, typed `Readonly<Partial<Record<Key, string>>>`. The viewer's own sixteen languages in its folders are never overwritten. The first import (2026-11-12) brought the 13 French families the model had written: 1,463 texts, 93 refused (keys of another family's, from an older source).
