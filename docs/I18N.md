# The interface's languages

Every text of the interface (the viewer, the admin, the Setup Assistant, the start page and the API's error messages) can be shown in 25 languages: `ro`, `en`, `fr`, `de`, `es`, `it`, `pt`, `pl`, `ru`, `uk`, `tr`, `ja`, `zh`, `ko`, `ar`, `hi`, `nl`, `hu`, `id`, `vi`, `bn`, `bg`, `el`, `fa`, `ur` (the owner, 2026-11-12). Arabic, Persian and Urdu are written right to left. Romanian is the default and the source of every key; English is the fallback of every key a language lacks. The rules for writing a text are `.agent/skills/web/i18n_skill.md`; the decision is `docs/research/DECISIONS-for-review.md` §219.

## The languages

`UI_LOCALES` of `packages/shared/src/i18n/locales.ts` is the one list: each language's own name (`UI_LANGUAGE_NAMES`), its direction (`directionOf`), the pickers' order (`UI_LOCALES_BY_NAME`, by the root collation of the names, the same in every language). `scripts/ci/check_i18n.py` holds the same list (a test keeps the two equal) and `scripts/i18n/import_translations.py` accepts only its codes.

- The viewer speaks all 25 too (`VIEWER_LOCALES` is `UI_LOCALES`, and `LANGUAGE_NAMES` is `UI_LANGUAGE_NAMES` in the pickers' order: one table of names, `docs/ENGINE_API.md` → Language). Sixteen are translated and complete (`VIEWER_COMPLETE` of `check_i18n.py`); the other nine (`nl hu id vi bn bg el fa ur`) have a catalogue file each in the viewer's folders, empty until their texts are imported, and show every text they lack in English.
- The admin, the Setup Assistant (inside the admin's shell), the start page and the API's errors speak all 25. A city's own texts (`{ro, en}`) stay Romanian and English: a reader of any other language sees the English text (`contentLocale`).

## Loading

Romanian and English are bundled. Every other language is a file of the build, never code: the admin's build writes `i18n/<locale>.json` next to `admin.mjs` (Hosting's `/admin/i18n/`), the start page's next to `start.mjs`, each `{"locale", "messages"}` with every catalogue family of that language merged (`scripts/site/src/ui-catalogues.ts`). The page fetches the file the first time the language is chosen (`packages/admin/src/state/ui-language.ts`), adds it to `@hcm/shared`'s registry (`registerCatalogue`), which every translator reads, and only then switches. A first language from the address, the stored choice or the browser shows English until its file is here. A file that cannot be fetched keeps the page's language and says so (`adminShell.language.unavailable`, `start.languageUnavailable`). The viewer's engine fetches its own `i18n/<locale>.json` the same way (DECISIONS §218); a language still being translated says so in its file (`"fallback": "en"`, written by the build when it lacks a key of Romanian), and the engine then fetches English with it before it switches.

A page has one language switch where the latest choice wins (`latestLanguage` of `ui-language.ts`, as the viewer's `LocaleSwitch`): French chosen on a slow network, then English, stays English when the French file arrives, and the boot's fetch of the stored language never undoes a choice made in the picker meanwhile. A superseded switch shows, remembers and reports nothing.

No bundle grows with a language: the files are data beside the bundles, as the viewer's are.

## Fallback

A key the language's file lacks shows in English (`uiText` of `packages/shared/src/i18n/registry.ts`); the first such key of a language is logged once per page (`[i18n] a text is missing in this language: English shown instead`). A language with no file at all is all English. The viewer shows no text before its language's file arrives (never a flash of English), then English for each key the file lacks.

An English fallback says it is English (WCAG 3.1.2, so a screen reader reads it with an English voice): the admin's page area carries `lang="en"` until the language's file holds that page's family (`pageLanguage` of `packages/ui/src/admin/shell/text.ts`, by the family's key prefix, `familyLanguage`), each navigation label, the page's title, the signed-in line and Sign out carry the language their own text shows in (`shellLanguage`, `textLanguage`), and the start page's `<main>`, its title and its language label carry `en` until a file holds the `start.*` texts. `<html lang>` stays the chosen language, which sets `dir`. A single English text inside a translated page family (a key the file lacks) is not marked, nor is the viewer's: both are short-lived, the gate reports each language's completeness.

Placeholder values are isolated (U+2068 … U+2069) in every right-to-left sentence: the viewer's `translate`, every admin family's translator and the API's errors fill through `fillPlaceholders(text, params, locale)`, so a Latin city or layer name keeps its order inside Arabic, Persian or Urdu.

## The pickers

- The admin: the account menu's Language, the 25 by their own names (`UI_LANGUAGE_OPTIONS` of `packages/ui/src/components/language-options.ts`), remembered in `localStorage` (`hcm:admin:lang`, every read and write in try/catch) once the language has taken; `?lang=<code>` chooses one for a visit. `<html lang>` and `dir` follow it.
- The Setup Assistant is a page of the admin's shell: the same menu.
- The start page: a native list in its header (`<hcm-start-language>`), remembered in `localStorage` (`hcm:start:lang`, try/catch inside the store: the choice outlives the tab, as the admin's does; the run's plan stays in the session); `?lang=<code>` too.
- The viewer: Settings' list of all 25, in the URL as it always was (`#…&lang=`); a language still being translated shows English for what it lacks.

## Right to left

`dir="rtl"` on `<html>` for Arabic, Persian and Urdu. The kit's styles are logical (`inset-inline-*`, `margin-inline-*`, `text-align: start`); what cannot be logical mirrors under `:dir(rtl)`: the side sheet's entrance (`sheet.ts`) and the indeterminate linear progress (`progress.ts`). The tour checks one right-to-left state of the admin (`admin.shell.language-rtl`, Arabic) and one of the start page (`admin.start.language-rtl`, Urdu), each read as the language it is: the i18n leak check skips what is marked `lang="en"` and counts English as a language's own text for each key its catalogue lacks (`e2e/support/i18n.ts`). The viewer's Persian (`S-V11-HAPPY-TRANSLATING-FALLS-BACK`) runs the same check.

## The gate

`scripts/ci/check_i18n.py` (the `i18n` static gate):

- Romanian and English stay strictly complete in every folder, one entry per line; the viewer's folders require its sixteen complete languages.
- Every other language's file, required or optional, is checked for shape: no key the source lacks, every message non-empty, the same `{placeholder}` names, braces only around them, no edge whitespace, no bidi control, no HTML tag the source lacks. In the viewer's folders a language being translated is also checked for text left in English and for its script's share (not yet for all six plural forms). A translation's entry too long for one line may be wrapped by Prettier after its key; a language with nothing yet may be `= {};`.
- Once a translation is under way the gate logs each language's completeness (`fr 1648/2806 (58 %)`).
- `--strict` (or `HCM_I18N_STRICT=1`) keeps every check of the default mode and adds completeness: every language of the 25 in every folder with every key (and all six plural forms in the viewer's). The owner switches it on once the translations are complete. A test proves strict reports everything the default mode does.

## Importing translations

A local model writes one file per family and language in the catalogues' layout (`<folder>/<locale>.ts`, `.` for the viewer's main family). To import them:

```bash
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp/hcm-home -v "$PWD:$PWD" -v /path/to/i18n-out:/i18n-out:ro -w "$PWD" hcm-quality:local \
  bash -c 'mkdir -p $HOME && python3 scripts/i18n/import_translations.py /i18n-out [--locale fr] [--dry-run] \
  && npx prettier --write packages/shared/src/i18n && python3 scripts/ci/check_i18n.py'
```

QA is mandatory (the owner, 2026-11-12): translations are always QA'd on local models, no exceptions. The local tool (`ltrans.py`) writes a string into `<locale>.ts` only once it has passed its validators (placeholders and ICU structure, kept names, punctuation, capitalisation, length, glossary, untranslated text) and a back-translation check (the laptop's `qwen3.5:9b` back-translates, then judges whether the translation adds or omits information or changes the meaning; a failing string is re-translated with the reasons up to twice, then goes to a second judge, `qwen3.8:27b` on the 5090, once that GPU is free of translation work); a string that fails is held for a human and left out. Every file comes with `<locale>.ts.qa.json` (`status: pass`, a `validators+back-translation/` policy, the file's SHA-256 and a verdict per string). The import refuses a file without a matching passing report, and an entry the report does not list as passed with that very text. Incremental runs (new or changed English strings) go through the same QA.

Each entry passes the gate's checks for an optional language or is left out and listed (its key keeps showing in English); what passes is merged with the language's file already there, in the source's key order, typed `Readonly<Partial<Record<Key, string>>>`. The entries already there are checked again against today's Romanian: one whose key is gone or whose placeholders changed is dropped and listed as stale; a new text for a key already there is counted as replaced. The viewer's sixteen complete languages in its folders are never overwritten; its nine others are imported like any family. The first import (2026-11-12) brought the 13 French families the model had written: 1,463 texts, 93 refused (keys of another family's, from an older source). Those came before the QA rule and have no report: the import does not remove them, so each is replaced as its family's QA'd file arrives, and the families still unreported are listed in DECISIONS §221 for the owner. The first QA'd import (2026-11-12) brought `admin-georef` and `start` in French, Arabic and Japanese: 565 texts, none refused (the strings QA held never reach the file); `map-labels` was skipped, as those three are among the viewer's sixteen.
