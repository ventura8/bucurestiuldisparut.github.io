## 0. What this contract decides

1. **Minimum admin input** (§1): a free scene is *search → one click Import → automatic georeferencing → published on
   its own* when its checkpoint error is under the city's threshold, or *one click Approve* when it is not. The
   georeferencer is the fallback, never the path.
2. **Layer versions** (§2.2): `cities/{city}/layerVersions/{version}` (id = the id of the job that made it) holds each
   georeferenced rendition on its way to a layer: its scan, reference, points, output files, estimate, guard verdict,
   approval and Mapbox ids. A layer document exists only once it has tiles (its first version published, or a tileset
   linked); replacing, re-georeferencing or cropping a layer makes a new version and the layer keeps its tiles until that
   version is published (`S-A14-HAPPY-REPLACE-SOURCE`).
3. **The job model** (§2.3, §4): jobs are created by callables and triggers only (the client keeps Cancel); the
   dispatcher `imagery.onJobWrite` starts one Cloud Run execution per queued pipeline job; the pipeline holds a lease with
   a heartbeat, records each step's outputs and exits while it waits; `imagery.tick` (every 5 minutes) resumes, re-dispatches
   lost and out-of-memory executions, polls Mapbox, runs deferred publishes, due layer deletions and the monthly harvest.
   **New status `awaiting_gcps`** (done): the scan is ready but has no georeference.
4. **Pipeline steps** (§5): `fetch`, `extract`, `stitch`, `inspect`, `locate`, `reference`, `georef`, `warp`, `export`,
   `register`, each idempotent and resumable, run in order by `python -m hcm_pipeline run`; the reference is OSM data
   (Overpass) plus Sentinel-2 L2A (a public STAC), **never Mapbox Satellite**; automatic GCPs (OpenCV, multi-scale,
   RANSAC, held-out checkpoints) are part of M3.
5. **Shared georeferencing mathematics** (§6): one convention (scan pixels, EPSG:3857 fits, residuals in ground metres),
   implemented in TypeScript for the georeferencer's live preview and in numpy for the pipeline, held to the same answers
   by golden cases (`pipeline/tests/contracts/georef-cases.json`, done).
6. **Publishing runs in functions** (§7): after approval, `imagery.publish` (a task queue, one at a time) checks the
   compute-unit guard against `usage/mapbox-YYYY-MM` with a reservation, streams the COG to an MTS tileset source,
   writes the recipe, publishes, polls, smoke-tests the tiles and finalizes the layer (manifest rebuilt by M2's triggers).
   Over budget: the free Studio upload, next month, or pay about $X.
7. **USGS harvest and ranking** (§3): `imagery.search` searches `corona2`, `declassii` and `declassiii` over the city's
   bounds, stores `usgsScenes` documents with the camera, footprint, coverage, cloud, resolution and download
   availability, and ranks them on a 0–100 score whose parts the admin reads in plain words; browse images are copied
   server-side into our bucket (no USGS address ever reaches the browser).
8. **Uploads, links and the address guard** (§8): a GeoTIFF upload creates its own job (the upload id); a link is probed
   server-side through `RemoteFiles`, which refuses private, loopback and metadata addresses and redirects.
9. **Admin screens** (§10): the Imagery area (`#/imagery`), the georeferencer (`#/georef/<version>`) and the layer
   editor's Replace, Re-georeference and Crop, each in its own lazy chunk with its own budget.
10. **Ownership** (§12): four workstreams, the shared files' marked sections, the order of work and the one-at-a-time
    rule for split stages on the NUC.

Done by this contract (CR-M3-1): the shared schemas and constants, the API schemas and error codes, the M3 ports, the
`awaiting_gcps` status with its Jobs page text, the imagery catalogue's skeleton, the golden pipeline documents, the
scenario rows, the tour inventory's section, and the stricter dependency-cruiser rule (`DECISIONS-for-review.md` §46).

## 1. The happy path and the minimum input

```text
Imagery (opens) ── harvest when older than 30 days ──► ranked scenes, free first
   └─ Import (1 click) ─► imagery.import ─► job usgs-import + layer version (layer id reserved)
        └─ imagery.onJobWrite ─► Cloud Run raster-pipeline: fetch → extract → stitch → locate → reference → georef → warp → export → register
             └─ version awaiting_approval ─► policy: checkpoint RMSE ≤ city threshold and auto-publish on?
                  ├─ yes ─► approved by system:imagery ─► imagery.publish: guard → upload → publish → tiles → finalize ─► layer published, manifest rebuilt
                  └─ no ──► the approval card: Approve (1 click) ─► same publish
             └─ too few matches ─► job awaiting_gcps ─► georeferencer (fallback) ─► Save ─► the same job continues from georef
```

| Flow | Admin input (counted by the e2e input-budget fixture, `CONTENT_INPUT_BUDGETS`) |
| --- | --- |
| `importScene`: a free scene under the threshold | 1 (Import; the search runs when the page opens and the harvest is stale, or 1 more for Search) |
| `approveVersion` | 1 (Approve) |
| `uploadGeotiff` (georeferenced) | 3 (Upload, choose the file, Approve) |
| `chooseStudio` (over budget) | 3 (Free: Studio, Download, I uploaded it) plus the upload in Mapbox Studio |
| `georeferencePair` | 2 per pair (a click on the scan, a click on the map) |
| `cropLayer` | the polygon's clicks plus Save |

The Bucharest frames M3 targets (PLAN: likely scanned already, so free) are the city's target years
(`cities/{city}.imagery.targetYears`, written by the legacy Bucharest import, CR-M3-8): 1966 (1966-07-12, KH-4A),
1976 (1976-02-20), 1977 (1977-09-13), 1978 (1978-03-30, KH-9 mapping camera) and 1980 (1980-07-16, KH-9). The e2e

### 2.2 Layer versions and layers

- A version's id is its job's id; `layerId` is the layer it renders: an existing layer (Replace image, Re-georeference,
  Crop) or an id **reserved** at Import or upload (`freeOverlayId` of the label, clear of the layers', the categories',
  `photos` and every unfinished version's `layerId`).
- States (`LAYER_VERSION_STATES`) and who moves them:

| From → to | By | When |
| --- | --- | --- |
| (new) → `processing` | `imagery.import`, `imagery.onRasterUpload`, `imagery.saveGcps`, `imagery.crop` | the job is created |
| `processing` → `needs_gcps` | pipeline (`georef` with too few matches, `inspect` of an upload without georeference) | the scan and reference are written |
| `needs_gcps` → `processing` | `imagery.saveGcps` | the admin's points are saved; the same job continues |
| `processing` → `awaiting_approval` | pipeline (`register`) | the output files exist |
| `awaiting_approval` → `approved` | `imagery.onJobWrite` (policy, `approval.auto`) or `imagery.approve` | under the threshold, or Approve |
| `approved` → `publishing` → `published` | `imagery.publish` | guard within (or a choice made), MTS success, smoke test |
| `published` (older) → `superseded` | `imagery.publish` (finalize) | a newer version of the layer is published |
| any unfinished → `rejected` / `cancelled` / `failed` | `imagery.reject` / cancel / the step that failed | |

- The layer document is created by the finalize step of the layer's first published version (stamped `system:imagery`):
  the version's label, year, date, sensor, `kind: 'satellite'` (USGS) or `'map'` (an upload whose name says plan or map;
  else `'aerial'`, the admin edits it), `attribution` (`USGS_ATTRIBUTION`, or the upload's original name until the admin
  writes one), the output's bounds and zooms, `order` on top, `opacity: 1`, `defaultVisible: false`, `published: true`
  (auto-publish means the public map), `status: 'ready'`, `provenance` (`usgsEntityId`, `usgsDataset`, `georef.method`,
  `gcpCount`, `checkpointRmseM`), `mapbox` and `currentVersion`.
- A later version of the same layer sets `layer.pendingVersion` while it is unfinished (the layer editor's chip "New
  version awaiting approval"); its publish replaces the tiles of the same tileset, moves `currentVersion`, clears
  `pendingVersion`, updates `mapbox.publishedSourceSha`, `provenance`, `bounds`, `minzoom`, `maxzoom`, and leaves every
  presentation field the admin set. `LAYER_STATUSES` keep their M2 meaning for the layer's own tiles (`ready`); the
  version carries the work in progress.

### 2.3 Jobs: who writes which field

| Field | Written by |
| --- | --- |
| `type`, `params` (`JOB_PARAMS_SCHEMAS[type]`), `createdBy`, `createdAt`, `layerId`, `versionId`, `status: 'queued'` | the callable or trigger that creates the job (one transaction with its version) |
| `status` `queued` → `starting`, `dispatchAt`, `executionName`, `machine`, `attempt` + 1, `waitReason` `capacity` / `guard` | the dispatcher (`imagery.onJobWrite`, `imagery.tick`) |
| `status` `starting` → `running`, `lease`, `step`, `progress`, `steps.<pipeline step>`, `startedAt` | the pipeline |
| `status` `waiting_usgs` + `retryAt` + `waitReason` `usgs-preparing` / `usgs-maintenance` / `rate-limited` | the pipeline |
| `status` `awaiting_gcps` (`waitReason: 'gcps'`), `awaiting_approval` (`waitReason: 'approval'`) | the pipeline |
| `waitReason` `compute-units` / `deferred`, `status` `mts_processing`, `mapboxJobId`, `steps.<publish step>` | the publisher |
| `status` `succeeded` / `failed` / `cancelled`, `finishedAt`, `error {code, message, params}` | whichever actor ends it |
| `cancelRequested` | an admin (Firestore SDK, the rules of M2) |

- `error.code` is an `apiError.*` code (§9.1's list) and `message` the redacted technical detail; `error.params` fills the
  code's message. Logs (`jobs/{id}/logs`, at most 500, redacted) are written by the pipeline and the publisher.
- `JOB_STEPS[type]` (done) names a job's steps in order: `usgs-import` runs `fetch`, `extract`, `stitch`, `locate`,
  `reference`, `georef`, `warp`, `export`, `register`, then the publisher's `guard`, `upload`, `publish`, `tiles`,
  `finalize`; `geotiff-import` starts with `inspect`, `reference`; `regeoref` with `georef`; `republish` is the publisher's
  five; `layer-delete` is `delete`. `runsOnPipeline(type)` tells the dispatcher which go to Cloud Run.

### 2.4 The job state machine

| Status | Meaning | Next |
| --- | --- | --- |
| `queued` | created, retried, resumed after SIGTERM, or points saved | `starting` (dispatched), `cancelled` |
| `starting` | an execution was requested | `running`; back to `queued` when the run call failed (`retryAt`); re-dispatched by the tick after `STARTING_STALE_MINUTES` without `executionName` |
| `running` | the pipeline holds the lease | `waiting_usgs`, `awaiting_gcps`, `awaiting_approval`, `failed`, `cancelled`, `queued` (SIGTERM) |
| `waiting_usgs` | USGS prepares the download, is in maintenance, or rate-limits (`retryAt`) | `queued` by the tick at `retryAt` |
| `awaiting_gcps` | the scan waits for the admin's points | `queued` (`imagery.saveGcps`), `cancelled` |
| `awaiting_approval` | rendered; waits for Approve, a compute-unit choice, or the 1st of next month | `mts_processing` (publish), `cancelled` (reject or cancel) |
| `mts_processing` | Mapbox processes the tileset (cannot be cancelled: `apiError.imagery.mapboxFinishing` in the log) | `succeeded`, `failed` |
| `succeeded`, `failed`, `cancelled` | ended (`FINISHED_JOB_STATUSES`) | `queued` again only through `imagery.retry` from `failed` |

Limits (`packages/shared/src/api/imagery.ts`, done): `JOBS_PER_DAY` 10 raster jobs a day per project, `RUNNING_JOBS_MAX`
2 at once, `JOB_MAX_ATTEMPTS` 3, `LEASE_SECONDS` 600 renewed every `HEARTBEAT_SECONDS` 60, `STARTING_STALE_MINUTES` 10,
`USGS_BACKOFF_MINUTES` 30 → 720.

## 3. USGS harvest and ranking (fn-imagery)

### 3.1 The search

`imagery.search` (admin) and the harvest of `imagery.tick`:

1. `setup/status.usgs` must be `ok` or `pending` (search works before USGS approves downloads), else
   `apiError.usgs.notConfigured`; the credentials come from Secret Manager (`usgs-username`, `usgs-app-token`) at run
   time; `UsgsApi.login` → the API key (never logged).
2. For each requested dataset (all three by default): `UsgsScenes.search` = M2M `scene-search` with `datasetName`,
   `sceneFilter.spatialFilter` `{filterType: 'mbr', lowerLeft, upperRight}` = the city's bounds,
   `acquisitionFilter` from the request's window, `metadataType: 'full'`, `maxResults` 100, paging with
   `startingNumber` until `totalHits` (at most 500 scenes per dataset). A dataset that fails (maintenance, 5xx) is
   listed in `failedDatasets`; the others are harvested (`S-A11-BAD-PARTIAL-DATASETS`).
3. `UsgsApi.logout` in a `finally`.
4. Each record is mapped (§3.2), ranked (§3.3) and written with `system:imagery` (`harvestedAt` = now; an existing
   document keeps the admin's `status` and `note`, its `layerId`, and its browse copy when the source address did not
   change). The response counts `found`, `added`, `updated`.
5. The best `BROWSE_PREFETCH` (20) scenes without a copy get one (§3.4), each isolated.

### 3.2 What a scene keeps

| Field | From the `scene-search` result |
| --- | --- |
| `entityId`, `displayId` | `entityId`, `displayId` (an entity id outside `ID_PATTERN` is skipped and logged) |
| `acquisitionDate` | `temporalCoverage.startDate`'s date |
| `footprint` | `spatialCoverage`'s outer ring, `[lng, lat]` turned into `{lat, lng}`, open, at most 64 vertices (simplified) |
| `corners` | the full metadata's corner fields when present (**UNVERIFIED** names: `NW Corner Lat dec`, `NW Corner Long dec`, …; the fixtures define them), else absent (the pipeline then uses the footprint) |
| `cloudCover` | `cloudCover`, absent when `-1` |
| `downloadAvailable` | `options.download` (already scanned); `imagery.import` confirms it with `download-options` |
| `sensor` | the camera field of the full metadata (**UNVERIFIED** name, `Camera Type`): `KH-4B`, `KH-4A`, `KH-4` for `corona2`; `KH-7` or `KH-9-mapping` for `declassii`; `KH-9-pan` for `declassiii`; without it, the dataset's default (`KH-4A`, `KH-9-mapping`, `KH-9-pan`) |
| `resolutionM` | `SENSOR_SPECS[sensor].resolutionM` (a metadata resolution, when present, wins) |
| `coverage` | the share of the city's bounds inside the footprint (the footprint clipped to the bounds, areas in an equal-area approximation: longitudes times the cosine of the bounds' middle latitude) |
| `browse.sourceUrl` | the first `browse[].browsePath` when it passes `usgsBrowseUrlSchema` (`ims.cr.usgs.gov`, a browse or thumbnail path, no query, no `..`) |

### 3.3 The ranking

`rankScene(scene, context)` in `packages/shared/src/imagery/ranking.ts` (fn-imagery; shared, so the admin can re-rank
live when a filter or a layer changes) returns `{score, reasons, version: RANKING_VERSION}`. Each part is 0 to 1; the
score is the rounded sum of `RANKING_WEIGHTS` (done: free 30, coverage 25, target year 15, new year 10, cloud 10,
resolution 10) times its part:

| Part | Value | Reason (`adminContent.imagery.reason.*`, done) |
| --- | --- | --- |
| free | 1 when `downloadAvailable`, else 0 | `free`, or `needsOrder` |
| coverage | `coverage` | `coverage {percent}` (whole percent) |
| target year | 1 when the year is one of `targetYears`, 0.5 within one year of one, else 0 | `targetYear {year}`, `nearTargetYear {year}` |
| new year | 0 when a layer (or an unfinished version) has the same year, else the distance in years to the nearest one over 10, at most 1 (1 when the city has none) | `sameYear {year}`, or `newYear {years}` |
| cloud | unknown 0.5; else `1 − cloudCover / 50`, at least 0 | `cloudUnknown`, or `cloud {percent}` |
| resolution | `1 − (resolutionM − 1) / 8`, between 0.2 and 1 | `resolution {metres}` (one decimal) |

- `reasons` lists the parts in the order of their weighted contribution, largest first; `needsOrder`, `sameYear` and a
  coverage under 50 % are always listed (they explain a low rank). The screen shows the first three and the rest on
  demand. The list sorts free scenes first, then by `rank.score`, then by `acquisitionDate`.
- A change of weights or parts bumps `RANKING_VERSION`; the harvest re-ranks every document of an older version, and the
  layer list's changes are reflected the next time the area opens (the admin re-ranks in the page meanwhile).

### 3.4 The browse proxy

The browser never requests a USGS address (the admin's CSP does not allow one, and the e2e firewall fails it):

- `imagery.browse` (admin) `{cityId, entityId}` → `{path, contentType}`: when `browse.state` is not `copied`, it fetches
  `browse.sourceUrl` through `RemoteFiles.get` (`allowedHosts: ['ims.cr.usgs.gov']`, `BROWSE_MAX_BYTES`, 10 s), checks the
  JPEG or PNG magic bytes, writes `RASTER_PATHS.browse(dataset, entityId)` (create-only), and records `browse.state`,
  `path`, `checkedAt`; a failure records `state: 'failed'` with `apiError.imagery.browseUnavailable` and answers that code
  (retryable: the card's Try again). The admin reads the copy with the Storage SDK (`getBlob` → a `blob:` URL), which is
  also the admin map's image source for the footprint preview (§10.2).
- No browse address is signed; download addresses are, and they never leave the pipeline (§5.3).

### 3.5 When the harvest runs

- The first time the Imagery area opens for a city whose newest `usgsScenes.harvestedAt` is older than `HARVEST_EVERY_DAYS`
  (30) or missing, the page calls `imagery.search` once and shows its progress; the admin can search again any time.
- `imagery.tick` harvests again, once a month, a city already harvested whose newest `harvestedAt` is older than
  `HARVEST_EVERY_DAYS`, only while `setup/status.usgs` is `ok` or `pending`; a city never harvested, or whose area holds
  no frame, waits for the Imagery area's first visit (CR-M3-44: otherwise every tick would search USGS for it).

### 4.2 The dispatcher: `imagery.onJobWrite`

A Firestore trigger on `cities/{city}/jobs/{job}` (`fn-events@`), at least once, acting on transitions only (before and
after compared), each in a transaction that re-reads the job:

- **`queued`** (created, or back to queued), `dispatchAt` absent or past: a `runsOnPipeline` type with `ops/guard` green
  and fewer than `RUNNING_JOBS_MAX` jobs holding an execution (`starting`, or `running` with its lease held; a lapsed
  lease is a lost run the tick recovers, CR-M3-45) → `starting` with `dispatchAt` = now, `machine` (`xl` for
  `SENSOR_SPECS[sensor].machine === 'xl'` or after an out-of-memory exit, else `std`), `attempt + 1`; then
  `CloudRunJobs.run(CLOUD_RUN_JOBS[machine], {JOB_ID, CITY_ID}, {args: PIPELINE_RUN_ARGS})` and `executionName`. A failed
  run call puts the job back to `queued` with `retryAt` + 1 minute and a log line. Capacity or the guard leave it
  `queued` with `waitReason` `capacity` / `guard` (the tick tries again). `republish` enqueues the publish task instead;
  `layer-delete` waits for the tick.
- **`cancelRequested` turned true**: `running` / `starting` → `CloudRunJobs.cancel(executionName)` (the pipeline's
  SIGTERM handler finishes the cancellation, §4.5; when no heartbeat follows within a lease the tick marks it
  `cancelled`); `queued`, `waiting_usgs`, `awaiting_gcps`, `awaiting_approval` → `cancelled` at once, the version
  `cancelled`, its reservation released, `layer.pendingVersion` cleared, the scene back to `candidate` for an import;
  `mts_processing` → a log line `apiError.imagery.mapboxFinishing`, nothing else.
- **`awaiting_approval`** reached: computes `estimate` (`estimateComputeUnits(output.areaKm2, output.maxzoom)`), applies the
  approval policy (§7.1) and, when approved, enqueues the publish task.
- Every write stamps `system:imagery`. A redelivered event finds the job already moved and does nothing
  (`S-A12-HAPPY-DISPATCH`).

### 4.3 `CloudRunJobs` and its adapters

The port (done, `functions/src/ports/cloud-run-jobs.ts`): `run(job, env, {args?, timeoutSeconds?})` → `{name}`,
`cancel(execution)`, `get(execution)` → `{state, failure?, exitCode?}` (`failure: 'oom'` for exit 137 or Cloud Run's
"Memory limit exceeded").

- **REST adapter** (`functions/src/adapters/cloud-run.ts`, fn-imagery): Cloud Run Admin API v2,
  `POST https://run.googleapis.com/v2/projects/{p}/locations/us-central1/jobs/{job}:run` with
  `overrides.containerOverrides[0].{env, args}` and `overrides.taskCount: 1`; the long-running operation's `metadata.name`
  is the execution; `POST .../executions/{id}:cancel`; `GET .../executions/{id}` (`succeededCount`, `failedCount`,
  `cancelledCount`, `conditions[]` for the reason). Tokens from `TokenProvider`; failures `UpstreamError('cloud-run', …)`.
  The fixtures exist (`packages/test-support/src/api-fixtures/cloud-run/`).
- **Fake** (done): `createFakeCloudRunJobs()` of `functions/test/support/platform.ts` records runs with their options and
  answers scripted statuses.
- **The emulator's runner** (e2e-fakes): in the Functions emulator the REST adapter reaches the fake Google upstream
  (`createEmulatorFetch`), whose Cloud Run route hands the request to the e2e world's runner: `standin` (a TypeScript
  stand-in that plays a scripted run against the Firestore and Storage emulators: steps, progress, logs, the version's
  output files as small generated images; the admin tier) or `python` (the real pipeline,
  `/opt/hcm/pipeline-venv/bin/python -m hcm_pipeline run` with `FIRESTORE_EMULATOR_HOST`, `STORAGE_EMULATOR_HOST` and the
  mock servers' loopback addresses; the pipeline tier). A spec picks the runner; the stand-in's script names the outcome
  (success under or over the threshold, too few matches, maintenance, failure at a step).

Cloud Run job definitions (deployed by CI, ask first; never in M3): `raster-pipeline` (4 vCPU, 16 GiB) and
`raster-pipeline-xl` (8 vCPU, 32 GiB), service account `job-raster@`, task timeout 6 hours, `--max-retries 0` (retries
belong to the dispatcher and the lease, so an execution never races its own retry), the image from Artifact Registry
`pipeline` by digest, the variables `GOOGLE_CLOUD_PROJECT`, `HCM_PRIVATE_BUCKET`, `HCM_PUBLIC_BUCKET`; per execution
`JOB_ID`, `CITY_ID` and the args `run`.

### 4.4 Progress, heartbeat and logs

- **Lease**: the pipeline's first transaction takes the lease (`owner` = `CLOUD_RUN_EXECUTION/CLOUD_RUN_TASK_ATTEMPT`,
  `until` = now + `LEASE_SECONDS`) when it is absent, lapsed or its own, sets `running` and `startedAt`; a lease held by
  another live owner → exit 0 untouched (`S-P01-BAD-DUPLICATE-EXECUTION`).
- **Heartbeat** every `HEARTBEAT_SECONDS`: extends `lease.until` when still the owner, writes `step` and `progress`, and
  reads `cancelRequested` (true → the step stops at its next checkpoint and the job is cancelled, §4.5).
- **Progress**: the done steps' weights (`usgs-import`: fetch 0.25, extract 0.05, stitch 0.10, locate 0.05, reference
  0.05, georef 0.20, warp 0.15, export 0.10, register 0.05; other types scale their steps' weights to 1); a long step adds
  its own fraction (fetch's bytes, warp's GDAL progress).
- **Logs**: one line per step start and end, every wait and failure, at most 500 per job, `seq` zero-padded,
  redacted by the pipeline's logger (signed URLs, tokens, keys, e-mail addresses, URL queries) before they are written;
  the same redaction applies to Cloud Logging. The publisher logs its steps the same way.

### 4.5 Retry, cancel, SIGTERM and out-of-memory

- **Retry** (`imagery.retry`, admin): only a `failed` job of a pipeline or publish type with `attempt <
  JOB_MAX_ATTEMPTS`; it becomes `queued` with the failed step `pending`; finished steps are skipped by their recorded
  outputs (§5.2). A failure at a publish step goes back to the publisher, not to Cloud Run.
- **Cancel**: §4.2. The pipeline checks `cancelRequested` at every heartbeat and at its own checkpoints.
- **SIGTERM** (Cloud Run's cancel, a task timeout): the handler sets a flag; the running step stops at its next
  checkpoint (fetch: every 64 MiB chunk; GDAL calls through their progress callback, which returns 0 to abort); within
  the ~10 seconds Cloud Run allows, with one transaction: when `cancelRequested` → `cancelled`, the version `cancelled`,
  the job's `work/` objects listed and deleted, local temporary files removed (`S-P01-BAD-SIGTERM`); else → the step
  `pending` with its checkpoint kept (`work/{city}/{job}/fetch.checkpoint.json`: the resumable upload session and the
  offset), the lease released, the job `queued` with `retryAt` + 1 minute (`S-P01-BAD-SIGTERM-RESUME`). Exit 0 either way.
- **Out of memory** (exit 137, no handler runs): the lease lapses; `imagery.tick` asks `CloudRunJobs.get` and, for
  `failure: 'oom'` on `std`, dispatches it again on `xl` (`attempt + 1`); on `xl`, or past `JOB_MAX_ATTEMPTS`, the job
  fails with `apiError.imagery.outOfMemory` or `apiError.imagery.attemptsExhausted {attempts}`
  (`S-A12-BAD-LOST-EXECUTION`).

### 4.6 `imagery.tick`

Every 5 minutes (`IMAGERY_TICK_SCHEDULE`, `fn-events@`, one instance), each part isolated and logged, nothing when
`ops/guard` is red except cancellations:

1. **Dispatch**: `queued` jobs whose `retryAt` / `dispatchAt` passed (capacity permitting); `waiting_usgs` past `retryAt`
   → `queued`; `starting` without `executionName` after `STARTING_STALE_MINUTES` → `queued`.
2. **Lost executions**: `running` with a lapsed lease → `CloudRunJobs.get` → OOM, failure or cancellation handled (§4.5);
   still running (a slow heartbeat) → left alone for one more lease.
3. **Mapbox**: `mts_processing` jobs whose last poll is older than its backoff → a publish task `phase: 'poll'` (the
   safety net of the task's own polling).
4. **Deferred publishes**: versions with `guard.deferUntil` passed → the publish task (the guard runs again).
5. **Layer deletions** (CR-M2c-13): `layer-delete` jobs past `dispatchAt` → the layer exists again → `cancelled`; else
   `MapboxTilesets.deleteTileset` and `deleteSource` (a missing one is fine; a failure retries on the next tick, at most
   `JOB_MAX_ATTEMPTS` times, then `failed`), the layer's `rasters/{city}/{layer}/` objects deleted, `succeeded`
   (`S-A33-HAPPY-TILESET-DELETED`).
6. **Sweep**: the files of versions ended (rejected, cancelled, failed, superseded) more than 30 days ago.
7. **Harvest**: §3.5.

`ops.tick`'s `jobs` and `mts` steps (M2) stay no-ops that report `ok` (`OPS_STEPS` unchanged, so a stored
`ops/guard.lastTick` keeps validating); `imagery.tick` supersedes them (CR-M3-13).

### 5.2 `run` and the step protocol

- `run` loads `Config`, takes the lease (§4.4), validates the job with its `JOB_PARAMS_SCHEMAS` twin in `model.py` (an
  invalid job fails with `apiError.invalidRequest` and exits 1: Cloud Run must not retry it), then walks
  `JOB_STEPS[type]`'s pipeline steps in order.
- A step is skipped when `steps.<name>.status` is `done` and its recorded output (`gcsPath`, `generation`) still exists;
  `skipped` is recorded for a step the job does not need (an upload with its own georeference skips `reference`).
- A step's inputs are staged into the instance's memory-backed `/tmp/hcm/<job>/` through `ObjectStore`; GDAL works on
  local files; outputs are uploaded create-only (`if_generation_match=0`) and recorded with their generation and
  SHA-256 before the step is marked `done`. Settings: `GDAL_NUM_THREADS=ALL_CPUS` (1 in tests), `GDAL_CACHEMAX` 4096,
  `gdalwarp -wm 2048 -multi`, `CPL_VSIL_USE_TEMP_FILE_FOR_RANDOM_WRITE=YES`.
- A step returns `DONE`, `WAITING` (the job then waits, the run exits 0) or raises `StepError(code, params)` with an
  `apiError.*` code (the job fails, exit 1 for a failure Cloud Run may not retry anyway: retries are the dispatcher's).

### 5.4 The corner guess (`locate`)

- The scene's `corners` (else the footprint's four extreme vertices) give the frame's four geographic corners. The film's
  first pixel row may lie at any of them (forward or aft camera, the flight's direction), so the step scores the eight
  assignments (four rotations, each mirrored or not) by the normalized correlation of the frame, warped at 60 m with each
  assignment's projective transform, against the Sentinel-2 reference at 60 m, and keeps the best (`S-P01-HAPPY` asserts
  the synthetic scene's rotation and mirror are recovered).
- The kept transform maps the city window (the city's bounds plus 10 %) back into frame pixels; the crop is `scan.tif`.
  Four GCPs at the crop's corners, `origin: 'corner'`, start the georeferencing (and the georeferencer when matching
  fails).

### 5.5 The references

- **Sentinel-2 L2A** (`stac.py`): `POST {HCM_STAC_URL}/search` (default Element 84's Earth Search,
  `https://earth-search.aws.element84.com/v1`, **UNVERIFIED** availability) with `collections: ['sentinel-2-l2a']`, the
  window's bbox, the last three years, `eo:cloud_cover < 20`, sorted by cloud cover; the first item that covers the window
  (else up to four of one date, mosaicked); its `visual` asset (an 8-bit true-colour COG) read through
  `/vsicurl/` for the window only, warped to EPSG:3857 at 10 m, cached as `reference/{city}/s2/{key}.tif` (the key: FNV-1a of
  the window and the item id). Attribution in the georeferencer: "Contains modified Copernicus Sentinel data {year}".
- **OSM** (`osm.py`): one Overpass query (`HCM_OVERPASS_URL`, default `https://overpass-api.de/api/interpreter`,
  **UNVERIFIED** policy limits) for the window's highways down to residential, railways, waterways and water areas,
  cached as GeoJSON (`reference/{city}/osm/{key}.geojson`), rasterized at 10 m for matching and drawn for the
  georeferencer. Attribution: "© OpenStreetMap contributors (ODbL)".
- **Never** Mapbox Satellite, a Mapbox raster tileset or any `fostulbucuresti` resource; `config.py` refuses a reference
  address on a Mapbox host (`S-P01-BAD-NO-REFERENCE`'s sibling unit test).

### 5.6 Automatic GCPs (`georef`)

1. Pre-warp the scan with the corner transform onto the reference grid (10 m), so scale and rotation are mostly gone.
2. Enhance both with CLAHE; the OSM raster is blurred into a distance field.
3. Coarse to fine over three levels (1/4, 1/2, 1): the pre-warped scan is cut into an 8 × 8 grid; per cell, SIFT
   features matched against the reference within a search window (± 400 m at the coarsest level, halved per level) with
   Lowe's ratio 0.75; normalized cross-correlation of the cell as the fallback.
4. RANSAC (`cv2.estimateAffine2D`, threshold 3 px, confidence 0.999, 5,000 iterations, seeded by the job id) keeps the
   inliers; at most two pairs per cell, so the pairs spread.
5. Each kept pair goes back to scan pixels through the pre-warp's inverse: a GCP with `origin: 'auto'` and `score`
   (the ratio margin times the inlier support).
6. Transform: `poly2` from 12 well-spread pairs, else `affine` from 6; the thin-plate spline is never chosen
   automatically. Fewer than 6 → the job waits for points (§5.3).
7. Errors: `fitRmseM` over the enabled pairs; `checkpointRmseM` by leave-one-out over them (the disabled pairs, when the
   admin set some, are true checkpoints instead); `checkpointCount`.

Determinism in tests: `GDAL_NUM_THREADS=1`, `cv2.setNumThreads(1)`, `cv2.setRNGSeed(seed)`, seeded numpy.

### 5.9 As built (CR-M3-19, folded in by the integrator, 2026-10-24)

- `locate` fetches the Sentinel-2 window (the corner guess scores against it) and `reference` reuses the cached copy,

- `export` writes the version's `output`; `register` checks it and moves `state`.
- Cloud Storage is spoken over its JSON API with httpx (resumable sessions with their offsets); `google-cloud-storage`
  stays in the lock unused until a later lock change drops it. Firestore writes are compare-and-set on the read's update
  time (`write_option(last_update_time=…)`, five tries) instead of `transaction()`.

## 6. Georeferencing mathematics (admin-imagery: TypeScript; pipeline: numpy)

### 6.1 Conventions (done: the schema; the golden cases)

- A GCP pairs a **full-resolution scan pixel** (origin at the top-left corner of `scan.tif`, x right, y down; the preview
  shows `pixel × previewScale`) with a **WGS84 place** `{lat, lng}`.
- Fits run from pixels to **EPSG:3857 metres** (spherical Web Mercator, R = 6,378,137 m), the warp's target.
- Residuals and RMSE are **ground metres**: the EPSG:3857 distance times the cosine of the pair's latitude.
- `affine`: 6 unknowns by least squares; `poly2`: 12 (x², xy, y² terms); `tps`: an exact thin-plate spline through the
  enabled pairs with an affine part. A fit is **degenerate** when the enabled pixels (or places) are collinear or
  coincident: the condition number of the design matrix over 1e12, or the area of their convex hull under 1 % of the
  bounding box's.
- `fitRmseM` over the enabled pairs; `checkpointRmseM` over the disabled pairs when there are any, else leave-one-out
  over the enabled ones; `residualM` of an enabled pair is its leave-one-out residual.

### 6.2 The TypeScript module

`packages/shared/src/georef/` (admin-imagery), exported from `@hcm/shared`:

```ts
export interface PixelPoint { readonly x: number; readonly y: number }
export interface FittedTransform {
    readonly kind: GeorefTransform;
    /** Scan pixel → WGS84. */
    toGeo(pixel: PixelPoint): { readonly lat: number; readonly lng: number };
    /** WGS84 → scan pixel (the inverse fit, for the warped preview's mesh). */
    toPixel(geo: { readonly lat: number; readonly lng: number }): PixelPoint;
}
export type FitRefusal = 'too-few' | 'degenerate';
export type FitResult =
    | { readonly ok: true; readonly transform: FittedTransform; readonly residuals: ReadonlyMap<string, number>;
        readonly fitRmseM: number; readonly checkpointRmseM: number | null; readonly checkpointCount: number }
    | { readonly ok: false; readonly reason: FitRefusal };
export function fitTransform(kind: GeorefTransform, gcps: readonly Gcp[]): FitResult;
/** A grid of `cells × cells` quads of the output bounds with their scan pixels: the warped preview's texture mesh. */
export function previewMesh(transform: FittedTransform, bounds: BBox, cells: number): readonly MeshQuad[];
```

- Pure, DOM-free, under complexity 5 per function; the fit of 300 pairs with leave-one-out runs under 50 ms in Chromium
  (the georeferencer refits on every move, coalesced per animation frame).
- `imagery.saveGcps` refits server-side with the same module before it accepts the points.

### 6.3 Golden cases (done)

`pipeline/tests/contracts/georef-cases.json`: exact affine pairs (residuals 0 within 0.01 m) fitted as `affine` and as
`poly2`, a held-out checkpoint, collinear pairs (`degenerate`), five pairs for `poly2` and two enabled for `affine`
(`too-few`). The TypeScript and the Python modules each run every case; the georef owners add noisy cases with
tolerances through a change request (both sides must pass them).

### 6.4 Re-georeference and crop

- **Re-georeference** (P02): the georeferencer opens a version (the layer's `currentVersion`, a `needs_gcps` version, or
  any awaiting one) with its scan, its reference images and its points; Save calls `imagery.saveGcps` (§4.1).
- **Crop**: a polygon drawn over the layer with `MapDrawPort` (`draw-polygon`, the M2c tools, the vertex list for the
  keyboard); the page refuses one that does not intersect the layer's bounds (`apiError.imagery.cropOutsideLayer`) or
  breaks the drawing rules (self-intersection, 500 vertices); Save calls `imagery.crop`, which checks the same and starts a
  `regeoref` with the current points and the ring.

## 7. Publishing (fn-imagery)

### 7.1 The approval policy

When a version reaches `awaiting_approval`, `imagery.onJobWrite` approves it automatically (`approval: {auto: true, by:
'system:imagery', checkpointRmseM, thresholdM}`) when **all** hold: the city's `autoPublish` (default true); the
georeference was measured (`method` is not `embedded`: an upload's own georeference waits, `S-A17-BAD-EMBEDDED-GEOREF`);
`checkpointRmseM ≤ rmseThresholdM` (default `DEFAULT_RMSE_THRESHOLD_M`, 15 m) with `checkpointCount ≥ 3`. Otherwise the
version waits for `imagery.approve` (admin; any state but `awaiting_approval` → `apiError.imagery.versionState`) or
`imagery.reject` (the version `rejected`, the job `cancelled`, the reserved id free again, `pendingVersion` cleared).

### 7.2 The compute-unit guard (done: the functions; the transaction: fn-imagery)

The publish task's `guard` step, in one transaction on `usage/mapbox-{usageMonth(now)}` (created with
`computeUnitBudget: MAPBOX_FREE_COMPUTE_UNITS` when missing):

1. `guardVerdict({estimate, usage, tilesets, versionId})`: `tilesets` = the city account's layers with a
   `mapbox.tilesetId` other than this version's layer. `tileset-limit` (24) → the version's `guard` records it, the job
   waits (`compute-units`), the card shows `apiError.imagery.tilesetLimit {limit}` without a Pay choice.
2. `within` → `reservations[versionId] = {computeUnits: estimate, at}` and the publish continues.
3. `over` → the version's `guard: {verdict: 'over', available, overageUsd, checkedAt}`, the job waits
   (`waitReason: 'compute-units'`); nothing reaches Mapbox (`S-A42-BAD-OVER-BUDGET`). The admin's `imagery.choose`:
   - `studio` → §7.5;
   - `defer` → `guard.deferUntil = nextMonthStart(now)`, `waitReason: 'deferred'`; the tick publishes it then, the guard
     running again (`S-A42-HAPPY-DEFER`);
   - `pay` (App Check `consume`, the owner or an admin) → `overageComputeUnits += estimate − available` and the
     reservation, in one transaction; the publish continues. The card says the cost ("about {usd} USD") before the click.
4. After the MTS job: success → `computeUnits += estimate` (or the measured value once the calibration is verified),
   `publishes + 1`, `uploadedMb += cogBytes / 1e6`, the reservation removed; failure → the reservation removed.
   Two approvals at once never both fit the last units: the reservations are in the transaction
   (`S-A42-BAD-RACING-PUBLISHES`).

The numbers are **UNVERIFIED** (Mapbox's raster MTS precisions and their price per km²): `KM2_PER_COMPUTE_UNIT` and
`USD_PER_COMPUTE_UNIT` are conservative constants; each publish records `mapbox.precisions` (the MTS job's
`tileset_precisions`) for the calibration a later change makes (§14).

### 7.3 The MTS publish

`imagery.publish` (task queue `IMAGERY_PUBLISH_QUEUE`, `maxConcurrentDispatches: 1`, at most two dispatches a minute,
retries 5 with backoff, timeout 1,800 s, 1 GiB, `fn-events@`), payload `publishTaskSchema` `{cityId, jobId, phase, poll}`:

| Step | Does |
| --- | --- |
| `guard` | §7.2; the version `publishing`, the job `mts_processing` once the guard passes |
| `upload` | `tilesetName(cityId, layerId)` is both the source id and the tileset's name (`tilesetIdFor(user, …)`, deterministic: a retry never makes a second tileset); `MapboxTilesets.uploadSource(user, token, sourceId, file)` streams `cog.tif` from the private bucket (`BlobReader.open`, never held in memory); skipped when `layer.mapbox.publishedSourceSha` equals `output.cogSha256` and the source exists |
| `publish` | `upsertTileset(token, tilesetId, {name, recipe: rasterRecipe(user, sourceId, minzoom, maxzoom)})` then `publish(token, tilesetId)` → `mapboxJobId` |
| `tiles` | `job(token, tilesetId, jobId)` after `PUBLISH_POLL_SECONDS` (60, 120, 300, then 900; a task `phase: 'poll'` each); `success` → `tileJson` must answer the zoom range (the smoke test); `failed` with an internal error → published once more; a recipe error → the job `failed` with `apiError.imagery.mtsRefused` (`S-P01-BAD-MTS-FAILURE`) |
| `finalize` | one transaction: the layer created (first version, §2.2) or updated (`mapbox {tilesetId, sourceId, publishedSourceSha, origin: 'mts'}`, `currentVersion`, `pendingVersion` cleared, bounds and zooms, `provenance`), the previous current version `superseded`, this one `published` with `mapbox.publishedAt` and `precisions`, the job `succeeded`, the counters (§7.2 step 4); the manifest is rebuilt by M2's `publish.onLayerWrite` |

The token is `mapbox-sk-tiles` (Secret Manager, run-time read); the Mapbox user is `setup/status.mapbox.user`
(`apiError.mapbox.notConfigured` without it). A source over Mapbox's limit fails with `apiError.imagery.sourceTooLarge
{megabytes}` (**UNVERIFIED** limit; the Studio path stays offered).

### 7.4 The tiles while a new version is made

The layer's tileset is only republished after approval, so the old tiles serve until the new MTS job succeeds
(**UNVERIFIED** that Mapbox serves the previous tiles during processing; if not, the fallback of
`DECISIONS-for-review.md` §46d is two alternating tilesets per layer). The admin is told that cached tiles can take up to

### 7.5 The free Studio path

`imagery.choose {choice: 'studio'}` → `{state, studioPath}`; the card shows three steps: **Download the file** (the

## 8. Uploads, links and the address guard

### 8.1 Upload a GeoTIFF (A14)

1. The page reads the file's first 8 bytes: TIFF (`II*\0`, `MM\0*`) or BigTIFF (`II+\0`, `MM\0+`), else
   `apiError.imagery.notTiff` at once, nothing uploaded (`S-A14-BAD-NON-TIFF`); over `RASTER_UPLOAD_MAX_BYTES` refused too.
2. A new upload id (`ContentStore.newId()`), then the Firebase Storage SDK's resumable upload (`uploadBytesResumable`) to
   `RASTER_PATHS.upload(city, uid, uploadId, '<nonce>.tif')` with the metadata `rasterUploadMetadataSchema`
   (`originalName`, `year`, and `layerId` for Replace image); the SDK resumes after a network drop within the page
   (`S-A14-BAD-LARGE-RESUMABLE`); the page watches `jobs/{uploadId}`.
3. `imagery.onRasterUpload` (Storage finalize, `fn-events@`, 512 MiB): `parseRasterUploadPath` (anything else ignored);
   the first 16 bytes through `BlobReader.range`; not TIFF → the job created `failed` with `apiError.imagery.notTiff`, the
   upload deleted (`S-A14-BAD-SNIFFED-NOT-TIFF`); a replacement whose layer is gone or busy → `failed` with
   `apiError.notFound` / `apiError.layers.busy`; else the `geotiff-import` job and its version (§4.1).
4. The pipeline's `inspect` decides: georeferenced → `warp`, `export`, `register` (the approval card, never automatic);
   a scan → `reference`, then the job waits for points (`S-A14-BAD-NOT-GEOREFERENCED`).

### 8.2 Link a tileset or XYZ (A15)

M2c's Link a layer dialog and `layers.link` stay (done). M3 adds **Check**: `imagery.probeTiles {cityId, source}` runs
`layerSourceRefusal` first (the city's own account, no key in the address), then asks one tile at the bounds' centre at
`minzoom` (a Mapbox tileset: its TileJSON with the tiles token, then the tile); 200 with PNG, JPEG or WebP magic bytes →
`{contentType, tile}`; 404 → `apiError.imagery.tilesNotFound`; another type → `tilesNotImage`; timeout or 5xx →
`tilesUnreachable`. A Mapbox tileset then previews on the admin map; an XYZ server's preview needs its origin in the
admin's CSP, which stays a manual step (M2c's note).

### 8.3 The address guard (`RemoteFiles`)

Every server-side fetch of an address that came from data goes through `RemoteFiles.get(url, {maxBytes, timeoutMs,
allowedHosts?})` (done: the port; the adapter: fn-imagery, `functions/src/adapters/remote-files.ts`):

- `https:` only, port 443 only, no user information, no IP literal;
- the host resolved once (`dns.lookup` with `all: true`) and refused when any address is loopback, private (RFC 1918,
  `fc00::/7`), link-local (`169.254.0.0/16`, `fe80::/10`, the metadata server), CGNAT, multicast or unspecified; the
  connection then goes to the checked address (no second resolution);
- no redirect followed (a 3xx is `forbidden`); `allowedHosts`, when given, must contain the host;
- at most `maxBytes` read, `timeoutMs` in all, no cookie, no credential, `User-Agent: historic-city-map`;
- a refusal is `UpstreamError('remote', 'forbidden')` → `apiError.imagery.addressRefused` (`S-A15-BAD-PRIVATE-ADDRESS`).

In the Functions emulator the adapter's addresses go to the fake upstreams (`createEmulatorFetch`), and its tests drive
the DNS check with an injected resolver.
