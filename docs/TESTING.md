# Testing

How **Historic City Map** is tested: the tiers, the fakes and seams, the emulators, the scenario registry and the per-file coverage gate. The agent-facing rules are in [.agent/skills/quality/testing_strategy_skill.md](../.agent/skills/quality/testing_strategy_skill.md) and [.agent/skills/quality/e2e_scenario_matrix_skill.md](../.agent/skills/quality/e2e_scenario_matrix_skill.md); the design behind them is [research/design-review-testability.md](research/design-review-testability.md).

Every tier runs **inside the quality image** (`hcm-quality:local`), never on the host: Node 24, JDK 21 for the emulators, Chromium, Firefox and WebKit for Playwright, GDAL for the pipeline.

## Running the tests

```bash
PIPELINE_STAGE=tests bash scripts/ci/run-all-checks.sh     # Vitest (all projects, under the emulators) + rule coverage + pytest, with coverage
PIPELINE_STAGE=e2e bash scripts/ci/run-all-checks.sh       # the scenario registry check, then every Playwright spec
```

One project or file while iterating:

```bash
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp/hcm-home -v "$PWD:$PWD" -w "$PWD" hcm-quality:local \
  bash -c 'mkdir -p $HOME && npx vitest run --project ui'
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp/hcm-home -v "$PWD:$PWD" -w "$PWD" hcm-quality:local \
  bash -c 'mkdir -p $HOME && python3 -m pytest scripts/ci/tests/test_pipeline.py'
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp/hcm-home -v "$PWD:$PWD" -w "$PWD" hcm-quality:local \
  bash -c 'mkdir -p $HOME && cd e2e && npx playwright test --grep @S-V00-HAPPY'
```

Vitest projects are declared in `vitest.config.ts` (one row per workspace): shared, ui (Chromium), engine, admin, functions, functions-deps (the composition root's test, `functions/test/deps.test.ts`, alone because it uses `vi.mock`), rules, e2e-support (Chromium: the e2e suite's own logic) and tools. The empty `engine-browser` project went on 2026-10-18 (`DECISIONS-for-review.md` §34a: its one test moved to `ui` with the map). `npm test` runs them all under `firebase emulators:exec` (the `rules` and `functions` projects need the emulators), whose JVMs get `JAVA_TOOL_OPTIONS=-XX:CICompilerCount=2` (two JIT compiler threads instead of twelve: a run this short paid more for compiling than it got back); `npm run test:unit` runs Vitest alone, which is enough for one project such as `--project ui`. `scripts/ci/run-emulated-tests.sh` sets `METADATA_SERVER_DETECTION=none`, so firebase-admin's Google clients never probe the GCE metadata server (a network call that also pushed emulator tests past their hook timeouts), and fetches the rule-coverage report's JSON and HTML at once (each takes the emulator seconds to build). The `shared`, `engine`, `admin` and `functions` projects share one module graph per worker (`SHARED_MODULE_GRAPH`), so their tests restore what they change and never `vi.mock`; both functions projects give every test and hook 60 s (`EMULATOR_TIMEOUTS`), and the rules world sets the same for its files. pytest runs the CI tooling tests on at most four pytest-xdist workers (`pytest.ini`; `-n 0` for one process). The functions project alone:

```bash
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/tmp/hcm-home -v "$PWD:$PWD" -w "$PWD" hcm-quality:local \
  bash -c 'mkdir -p $HOME && npx firebase emulators:exec --project demo-hcm --only auth,firestore,storage \
  "METADATA_SERVER_DETECTION=none npx vitest run --project functions --project functions-deps"'
```

## Fakes and seams

Only external boundaries are faked; owned modules are never mocked.

- **Map**: the engine core talks to a `MapPort`; tests use a recording `FakeMap` from `@hcm/test-support`. The admin's drawing tools are tested against the real Terra Draw in Chromium on a structural Mapbox map with real pointer events (`packages/ui/test/map/draw/terra-draw-real.test.ts`), and on the real Mapbox GL of the admin tier (`e2e/admin/specs/pois/dragging.spec.ts`). Only the Mapbox adapter touches `mapbox-gl`, and it is tested in Chromium with a local minimal style (slot layers) and solid-colour synthetic tiles, telemetry and token checks off.
- **HTTP**: a unit test injects a recording fake `fetch` (the engine's manifest loader and telemetry, the functions' adapters), and the e2e tier answers every mocked host from the mock APIs (`e2e/mock-apis/`). The upstream answers (Google Cloud, Mapbox, USGS M2M, Nominatim) are JSON fixtures in `@hcm/test-support/api-fixtures`, served by the fake upstreams of `@hcm/test-support/fakes` in process and over HTTP: see [Fake upstreams](#fake-upstreams) ([research/M2-interfaces.md](research/M2-interfaces.md) §7).
- **Google Cloud**: Cloud Run Admin, Secret Manager, Resource Manager, IAM, Cloud Billing, Service Usage, Firebase Management, Cloud Tasks and Error Reporting are called over REST, so a fake `fetch` covers them; credentials come from a `TokenProvider` port (the owner claim uses the caller's own token). The functions' handlers get in-memory port fakes (`functions/test/support/`).
- **Ports**: every outside service of the functions is a port (`functions/src/ports/`: `DocumentStore`, `AuthAdmin`, `SecretStore`, `GoogleIam`, `FirebaseManagement`, `ErrorReporter`, `TaskQueue`, `BlobStore`, `ImageProcessor`, `MapboxApi`, `UsgsApi`, `CloudRunJobs`, `Clock`) with an in-memory fake passed in by dependency injection ([Fake upstreams](#fake-upstreams)).
- **Time**: an injected clock, Vitest fake timers, Playwright `page.clock`; no sleeps, no wall clock.
- **The admin's ports**: the shell's node fakes (`packages/admin/test/app/fakes.ts`: auth, callables, documents, storage, clock, stores, location), the Setup controller's harness (`packages/admin/test/setup/harness.ts`: the Cloud, backend, Google and import ports as `vi.fn` with defaults), the provisioner's world over the fake upstreams (`packages/admin/test/provision/world.ts`), and for the elements a fake app (`packages/ui/test/admin/shell/fake-app.ts`) and a recording Setup port (`packages/ui/test/admin/setup/fixtures.ts`).
- **Python**: a fake USGS M2M server on `127.0.0.1:0` with scenario state; synthetic GeoTIFFs per test in `tmp_path`; `monkeypatch.setattr`.
- **Test credentials encode the scenario** (`GOOGLE_TOKENS`, `MAPBOX_TOKENS` and `USGS_CREDENTIALS` of `@hcm/test-support/fakes`: `sk.e2e-bootstrap-all-scopes`, `sk.e2e-bootstrap-trial-account`, USGS `e2e-ok` and `e2e-m2m-pending`, the viewer's `pk.e2e-fake-token`): generated values, never real tokens, not JWT-shaped; a value shaped like a Google key or access token (`AIza…`, `ya29.…`) is assembled at run time, never written in a file.

## Fake upstreams

One set of answers for every tier: the adapter tests, the handler tests, the Playwright admin tier and, later, the Python tests read the same fixtures ([research/M2-interfaces.md](research/M2-interfaces.md) §7).

- **Fixtures** (`packages/test-support/src/api-fixtures/`, import `@hcm/test-support/api-fixtures`): one JSON file per upstream call and outcome, named `<service>/<operation>.<outcome>.json` (`mapbox/tokens.create.demo-account`, `usgs/login-token.html-403`, `google/error.service-disabled`). Each file is an envelope `{call, note?, status, headers?, body? | text?}`: `call` documents the request it answers, `body` is a JSON body, `text` a raw one (USGS's HTML error pages), neither for a 204. Strings may hold `{{name}}` placeholders, filled from `values.json` and the caller's values; `apiKey` is assembled at run time (`"AI" + "za" + "E2eFakeKey"` padded with `0` to 35 characters). `fixture(name, values)`, `fixtureBody(name, values)` and `fixtureResponse(name, {values, merge, body, status, headers})` read them; `FIXTURE_NAMES` lists them. A new file also gets its import and its entry in `catalog.ts`; `functions/test/support/api-fixtures.test.ts` fails when the catalogue misses a file, a placeholder stays unfilled, or a file holds a credential-shaped value.
- **Fake `fetch`** (`@hcm/test-support/fakes`): `createFakeFetch(handler)` records every call (`calls`, `callsTo('mapbox.tokens')`) and rejects a request no handler answers like a network failure (listed in `unhandled`), so an adapter that calls the wrong URL fails its test; `routeTable([route('POST', 'https://api.mapbox.com/tokens/v2/{user}', 'mapbox.tokens.create', answer)])` builds a handler (`{name}` is one path segment, so a Google custom verb such as `{service}:enable` still splits; `{name*}` takes the rest of the path); `jsonResponse` and `fixtureResponse` build the answers.
- **Fake upstreams** (`createUpstreamFakes()`): Google OAuth tokeninfo, Resource Manager (v1 and v3, a project without a parent unless a scenario puts it in an organisation), IAM (service accounts, Workload Identity Federation), Cloud Billing, Billing Budgets, Service Usage, Firebase Management (and Identity Toolkit's Google sign-in client), Secret Manager, Cloud Run Admin v2, Cloud Tasks, the Cloud Storage bucket API, Error Reporting, and for the admin's provisioner (M2b) Cloud Functions v2, Cloud Scheduler, Pub/Sub, Org Policy, the Firebase Storage default bucket, reCAPTCHA Enterprise, App Check, Monitoring, API Keys and Analytics Admin, Mapbox (Tokens v2, Tilesets v1, styles), USGS M2M (login, permissions, scene search, downloads), Nominatim reverse, Vertex AI and FCM (M4, below), with state. A new world is a fresh Spark project (one open billing account, not linked; Spark APIs; one web app without Analytics; nothing provisioned), the Mapbox accounts of `MAPBOX_TOKENS` (a paid one, a demo one that cannot mint, one blocked on its billing information) and the USGS users of `USGS_CREDENTIALS`; Google APIs answer 401 without a bearer token, and enabling a billed API without billing answers Google's `UREQ_PROJECT_BILLING_NOT_FOUND`. A test changes the world with `scenario(name)` (`cloud-billing.enabled`, `cloud-billing.noAccount`, `cloud-billing.accountOpen`, `cloud-billing.severalAccounts`, `cloud-billing.quotaExceeded`, `billing-budgets.budgetForbidden`, `cloud-functions.none`, `.partial`, `.deployed`, `.failed`, the preset `google.deployed`, `resource-manager.inOrganization`, `org-policy.noDefaultGrants`, `org-policy.publicAccessPrevented`, `cloud-storage.publicBucketTaken`, `cloud-storage.legacyRolesRefused`, `iam.poolDeleted`, `usgs.m2mApproved`, `mapbox.upgraded`, `firebase-management.analyticsLinked`, `firebase-management.googleSignInOff`, `error-reporting.twoGroups`, `google.provisioned`, ...; `scenarioNames` lists them), with `fail(service, mode)` (`unavailable`, `rateLimited`, `unauthorized`, `forbidden`, `apiDisabled`, `maintenance`; `null` clears) or through `state`, and asserts with `calls`, `snapshot()` and `secretValue(secretId)`.
- **Over HTTP** (`@hcm/test-support/fakes/http`, Node only): `startUpstreamServer({port, setup})` serves the same fakes on `127.0.0.1` for the Functions emulator or the Python tests, and `createUpstreamExtension()` plugs them into the e2e mock APIs (`e2e/mock-apis/main.ts`), which answer the extension's routes first and fall back to their own. A request arrives as `/h/<host><path>`; its `x-hcm-test` header picks the test's own world, so parallel tests never share state. Control endpoints take `?test=<id>`: `GET /__upstream/calls[&operation=]`, `POST /__upstream/scenario` `{"name"}`, `POST /__upstream/fail` `{"service", "mode"}`, `GET /__upstream/snapshot`, `GET /__upstream/scenarios`, `POST /__upstream/reset`. The browser firewall forwards only the viewer's hosts in the viewer projects; the admin projects (`forwardUpstreams`) add every host of `upstreamHosts()` and the `authorization` header, so a viewer spec that reached Google is still blocked. `E2E_PROJECT_CONFIG` of `@hcm/test-support/fakes` is the e2e world's `infra/project.json` (`demo-hcm`, generated GitHub ids).
- **M3 imagery** (CR-M3-10, [research/M3-interfaces.md](research/M3-interfaces.md) §13): the USGS catalogue's scene search over the three declassified datasets (`packages/test-support/src/fakes/usgs-catalogue.ts`: the five Bucharest target frames, a free 1968 frame and two to order, filtered by the request's `mbr`, acquisition window and paging), the download flow and its delivery host (`usgs-downloads.ts`: download requests by label with signed addresses, Range, a fresh address on 403 or 410), the browse host (`usgs-browse.ts`), Earth Search's STAC and its Sentinel-2 COG (`stac.ts`), Overpass (`overpass.ts`), MTS sources, recipes, publish jobs and the published tiles in the tileset's own colour (`mapbox-sources.ts`, `mapbox-tiles.ts`), Cloud Run jobs whose runs a `runner` plays, and the `imagery.ready` preset (USGS approved, `mapbox-sk-tiles` in the fake Secret Manager). The functions tests use `functions/test/support/imagery-fakes.ts` and the golden documents of `pipeline/tests/contracts/` (`functions/test/imagery/world.ts`); the e2e admin tier runs the same fakes in the server's world, whose Cloud Run hands every run to the imagery runner (`e2e/admin/support/imagery-runner.ts`: the scripted stand-in, or the real `python -m hcm_pipeline run` of the quality image against the emulators and the mock APIs, which `POST /__imagery/synthetic?dir=` points at a synthetic scene a spec generated). The e2e tile host `tiles.e2e.test` answers the Link dialog's Check, broken layers included (`e2e/mock-apis/imagery.ts`).
- **M4 assists and notifications** ([research/M4-interfaces.md](research/M4-interfaces.md) §4, §5, §8; server-only hosts, so a page that reached one fails its test): Nominatim reverse (`packages/test-support/src/fakes/nominatim.ts`: Ateneul Român with its English name, the Cotroceni quarter with no named object, a road anywhere else in Romania, nothing over the sea; `fail('nominatim', 'rateLimited' | 'unavailable')`), Vertex AI's `generateContent` and `countTokens` (`vertex-ai.ts`: the answer is the admin's text and `(English draft)` or `(ciornă în română)`, every request recorded; the outcomes `markup`, `empty` and `safety`) and FCM HTTP v1 (`fcm.ts`: a message whose target is a well-formed `fid` is recorded, a `validate_only` dry run is answered only, an unregistered registration answers 404 `UNREGISTERED`; the scenario `fcm.tokensGone`). The functions tests use them through `functions/test/support/m4-upstreams.ts`; the admin tier's `e2e/admin/specs/{assists,notify}/` reach them in the server's world through the Functions emulator, under the admin tier's lock (DECISIONS-for-review.md §54h), and the `e2e` build's push registrar hands out a fixed registration per `?test=` with the browser's real permission (headless Chromium starts with notifications denied; Playwright grants them, the DevTools Protocol denies them).
- **How the function tests use them**: the fn-admin tests run the real Firestore and Auth adapters on the emulators with a fresh named database per test (`functions/test/admin/world.ts`); the `setup.*` tests run the real REST adapters over `createUpstreamFakes()` with a per-test `intercept` (`functions/test/setup/world.ts`); the photos, publish and ops tests use in-memory documents, blobs and tasks with a movable clock (`functions/test/{photos,publish,ops}/`), real sharp on generated images (hand-made PNG headers for the pixel limit and for broken pixels), and the Storage adapter on the Storage emulator.
- **Port fakes** (`functions/test/support/`): `createFakeDocumentStore` (validates every read and write with its schema, `create` conflicts, queries with `where`/`orderBy`/`limit` that split valid from invalid documents, transactions that commit at once and refuse a read after a write, `contend(n)` to rerun `work`), `createFakeAuthAdmin`, `createFakeBlobStore` (create-only writes conflict), `createFakeTaskQueue` (an id is queued once), `createFakeSecretStore`, `createFakeCloudRunJobs`, `createFakeImageProcessor` with `fakeImage({...})` bytes, `createFakeGoogleIam`, `createFakeFirebaseManagement`, `createFakeErrorReporter`, `createFakeMapboxApi`, `createFakeUsgsApi` (the same scenario credentials) and `testRuntimeConfig()`. Each records its calls in a `PortRecorder` and fails on demand with `recorder.failNext(method, new UpstreamError(...))`.

## Network isolation

- pytest blocks every non-loopback socket (`scripts/ci/tests/conftest.py`).
- Chromium starts with host-resolver rules that resolve only loopback.
- Playwright decides every request of the browser context (`e2e/support/network.ts`, automatic in every spec): loopback passes; a mocked host (`api.mapbox.com`, `events.mapbox.com`, the GA4 and Firebase hosts, `cdn.jsdelivr.net`, `tiles.e2e.test`, `telemetry.e2e.test`) is forwarded to the mock APIs on `127.0.0.1:4311`, which serve Mapbox GL JS and its CSS from the pinned `mapbox-gl` package, a local style, generated tiles and glyphs, and count `events.mapbox.com` and analytics beacons; anything else is aborted, recorded and fails the test at teardown, WebSockets included. This proves the viewer never calls Firestore and never reaches real Mapbox or Google.

## Emulators

- firebase-tools 15.33.0 on JDK 21; the emulator JARs are in the image (`FIREBASE_EMULATORS_PATH`).
- Project **`demo-hcm`**: the `demo-` prefix guarantees no real resource is touched and no login is needed.
- `firebase emulators:exec --project demo-hcm --only <services> "<command>"` wraps a test run; e2e uses auth, firestore, storage, functions (from the `functions/dist` artifact), pubsub and tasks; the admin's `e2e` build is served by the e2e admin server with `firebase.json`'s headers minus `upgrade-insecure-requests` (which would upgrade the http emulators) and plus the emulator origins, not by the Hosting emulator ([research/M2b-interfaces.md](research/M2b-interfaces.md) §6.2). **Always name the project**: `.firebaserc`'s `default` is the real `bucurestiul-disparut`, so a command without `--project demo-hcm` would start the emulators for it; `firebase/rules-tests/test/firebase-config.test.ts` fails when an npm script starts the emulators without it.
- In the Functions emulator (`FUNCTIONS_EMULATOR=true`) the composition root (`functions/src/deps.ts`) keeps secrets in the fake Secret Manager of the fake upstreams (every function runs in its own worker process; in memory when `HCM_UPSTREAM_BASE` is unset), names the task queue's service account (no metadata server lookup), enqueues manifest tasks without an id (the Cloud Tasks emulator dispatches at once) and gives every REST adapter a `fetch` that reaches only the fake upstreams: `https://<host><path>` of Mapbox, USGS M2M or a `*.googleapis.com` API goes to `<HCM_UPSTREAM_BASE>/h/<host><path>` (`functions/src/adapters/emulator-fetch.ts`; a loopback base only), and everything else, or everything while `HCM_UPSTREAM_BASE` is unset, fails like a network error. Its Google token is a placeholder (the fakes accept any bearer token). The `x-hcm-test` partition of a callable's request is not forwarded yet: those calls share the partition `''` (CR-M2-22, CR-M2b-3), which the admin tier empties before each test and calls the server's world.
- Tests isolate data per test (city id `e2e-w{worker}-{test}`, unique Auth users) and seed through the Admin SDK.

## Scenario registry

`e2e/scenarios.json` lists every behaviour (viewer V, admin A, pipeline P) and, for each, at least one happy and one bad scenario with its id (`S-V01-HAPPY`, `S-V01-BAD-MANIFEST404`), what it asserts, its tier and milestone, and its status (`planned` until the tagged test is green, then `exists`). Playwright tests carry the id as a tag (`@S-...`), pytest tests a `Scenarios: S-...` docstring line. The `e2e-matrix` static gate (`scripts/ci/check_e2e_matrix.py check`) cross-checks rows and tests in both directions and fails when `docs/E2E_SCENARIOS.md` is out of date; `python3 scripts/ci/check_e2e_matrix.py write` regenerates it. Its `## Counts` section is the only place that states test counts.

## E2E today

- Workspace `e2e/` (`@hcm/e2e`: `@playwright/test@1.64.0`, `@axe-core/playwright@4.13.0`, `mapbox-gl@3.32.0` for the mock APIs, `sharp` for the tiles), config `e2e/playwright.config.ts`, projects `e2e/projects.ts`. The `e2e` stage runs `e2e-matrix`, then `e2e-build` (`scripts/ci/e2e_build.py` around `npm run build:site:e2e`: the engine, then `dist/e2e-site/bucharest` with the e2e fixture manifest and `dist/e2e-site/starter-kit`; skipped while its stamp shows no input changed and no output was touched), then `playwright` (`npm run test:e2e`). The `tour-matrix` stage (in `all` and nightly) runs the same build and the rest of the tour.
- Two servers start first (`webServer`, `e2e/mock-apis/main.ts`, run by Node from TypeScript): the built sites on `http://127.0.0.1:4310` as GitHub Pages serves them, and the mock APIs on `http://127.0.0.1:4311` (`GET /__calls?test=<id>&host=<host>`, `POST /__reset`, `GET /__health`).

## The tour's checkers

The user's request of 2026-10-12 ("in the phone screens the menu button sometimes overlaps with other elements. we should have tests for overlapping elements!!! also for accessibility!!"): two generic checkers run on every state of the tour, the viewer's and the admin's, independent of hand-placed markers (`e2e/support/state-check.ts` → `expectStateSound`). Every check is a soft assertion, so one run reports every state; each violation names its elements (accessible name, a readable selector through the shadow hosts, the box), goes into `layout-a11y-violations.jsonl` in the test's output folder, and the state's screenshot with the elements outlined is attached to the test (`e2e/support/report.ts`). The in-page probes are small `function` declarations installed in the page once per load as a library and called there by name (`e2e/support/page-script.ts`; the page's CSP does not govern a DevTools evaluation), the rules are pure functions; both are unit-tested (`e2e/test/`).

**`assertLayoutSound(page, state)`** (`e2e/support/layout.ts`, probe `layout-probe.ts`, rules `layout-rules.ts`), once the page has stopped moving (no finite animation or transition left, then two rendered frames, so a ResizeObserver's work such as the map's canvas following its box has happened):

- (a) **Occlusion**: every visible interactive element (native controls, the ARIA widget roles, anything in the Tab order, the kit's controls inside their shadow roots) is hit at its centre and four points 20 % in from its corners by a deep `elementFromPoint`, those inside its own shape (a rounded border's corners left out: a round control scrolled to a strip, `docs/LESSONS.md` 123); a larger surface (the map's canvas) at its centre. With a modal surface open (a `<dialog>` in the top layer, or an `aria-modal` box on top), every element outside it must be inert, `aria-hidden` or out of the Tab order instead. Not counted: points under the open FAB menu (sanctioned below), content scrolled under a fixed bar while it can scroll out (the focused element is checked by *focus obscured*), and a sliver of at most 5 px of a control at the edge of what scrolls (`scrolledToASliver`: Chromium hit-tests the last fraction of a pixel at a scroller's clip as the element beyond it, CR-M2c-29; the scroll sweep below checks the control whole at another position).
- (b) **Overlap**: no two pieces of usable floating chrome overlap by more than 1 px: the FAB and its open menu, toolbars and the timeline, chips, snackbars, banners, sheets, the admin's navigation and top bar, Mapbox's logo, attribution and controls, and anything marked `data-layout-check` (`FLOATING_CHROME`; an element that contains other chrome is represented by its parts). On compact and medium windows, floating touch targets of different components keep 8 px apart (sheets, bars and rails are surfaces, not targets).
- (c) **Edges**: nothing usable or readable is partly outside the viewport unless a scroll container brings it into view on that axis, nothing is cut off by an ancestor that hides its overflow without scrolling, and the page never scrolls sideways, nor does any box inside it (`sideways-scroll`, WCAG 1.4.10: a box that scrolls only downwards scrolls sideways too once its content is wider; the message names what sticks out). The visual audit of 2026-10-17 found a dialog's segmented button running past its edge at 320 and 360 px, which the edge check had let through because the dialog could scroll to it.
- (d) **Mapbox legal**: with a map on the page, exactly one Mapbox logo and one attribution (Mapbox's own controls, or the viewer's copy) are visible where the visible part of the map reaches them, never two, and all five sampled points of each reach them.
- (e) **Text**: no label cuts its text (an ellipsis included), and no visible text runs over another (a text shows through anything transparent above it).

Sanctioned stackings (`SANCTIONED_STACKINGS`, minimal): the **open FAB menu** may cover the map and what is drawn on it (`content`: the points it covers are not counted by the occlusion check), a transient popup until it closes, and the two docks it is designed to grow over on a short phone, the consent banner and the toast; it must keep clear of every other piece of floating chrome (the timeline, the chip, Mapbox's controls), and its own items must be on top and on screen. Until the visual audit of 2026-10-17 it might cover any chrome, and its last item lay on the timeline's thumb at 768 px. A modal surface needs no entry: what it covers must be inert. The legal line beside a modal sheet stays usable by design (V18) and is checked for occlusion instead.

**`assertAccessible(page, state)`** (`e2e/support/a11y.ts`, probe `a11y-probe.ts`, rules `a11y-rules.ts`, recorder `live-regions.ts`):

- axe with `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and `best-practice` (the map's canvas excluded, `css-orientation-lock` off under the page's CSP; on a page of one frame axe is injected once per document and run in place, a quarter of `AxeBuilder`'s per-frame run with its blank merge page);
- target sizes: WCAG 2.5.8 everywhere (24 × 24 CSS px, or spaced so a 24 px circle on the target meets no other target; a target lying on a larger one, as a control on the map, is not crowded by it; inline links exempt), M3's 48 × 48 on compact and medium (Mapbox's own controls aside, as before). A control's target is its box, or the kit's centred 48 px `touch-target` ring as far as a pointer reaches it: each side of the ring beyond the box is hit-tested at its middle, 1 px inside its edge (`targetSizeOf`), because the ring's computed size stays 48 px when an `overflow: hidden` cuts it (the kit's state layer once did, LA-6 of `docs/research/layout-a11y-findings.md`);
- one full **Tab round** from where the focus is, recorded press by press (a `focusin` listener on the document misses moves inside one shadow root): every expected stop reached exactly once, never climbing back up inside one component, each with a focus ring (outline or focus shadow on `:focus-visible`) of 3:1 against the colour around it, not cut off by an ancestor that hides its overflow (the outline's box, grown by its offset and width; since the visual audit of 2026-10-17, which found the drag handle's ring cut by the sheet and then the map canvas's cut away whole), not hidden under other content (WCAG 2.4.11), no trap (the focus never sticks), and with a modal open never out of it; the focus then goes back where it was;
- **non-text contrast** (WCAG 1.4.11) of switches, sliders, check boxes and radios (track, handle, border), fields (border) and icon-only buttons (the glyph) against what is around them, in the page's scheme and again under `prefers-contrast: more` (the kit's high-contrast scheme); controls identified by their text need no boundary, and over the map's imagery nothing can be measured;
- **landmarks**: navigation, complementary, region, form and search landmarks carry a name, and no two of one role share a name;
- **announcements** the state expects (a toast, an alert, an overlay's new opacity) were made by a live region that existed before the text (or an alert);
- the layout checks again under the WCAG 1.4.12 **text spacing** (line height 1.5, letters 0.12 em, words 0.16 em, paragraphs 2 em, through a constructable stylesheet in every shadow root) and, on a phone held upright, **reflowed at 320 CSS px** (WCAG 1.4.10; the 320 px projects of the matrix check it natively), reporting only what the variant adds.

**The scroll sweep** (`e2e/support/scroll-sweep.ts`, in-page `scroll-probe.ts`; since 2026-10-18, lesson 84): the checks above measure what is scrolled into view, so after them every box a visitor scrolls vertically (the page, a pane, a sheet, a dialog's content; with a modal open only what scrolls inside it; never a text area) is scrolled through its content three quarters of its height at a time, from the top to the end (at most 24 positions; an inner scroller out of view is first brought into view), and at each position the checks that depend on what is in view run again: the layout checker, the target sizes, the non-text contrast in the page's scheme and in high contrast, and axe's `color-contrast`. A violation the state already had, or that an earlier position found, is not reported again (`violationShape`: the same check and message with its numbers left out); a new one is reported under `<state>, <scroller> scrolled to <n> px` with its outlined screenshot. Every scroller is then put back where it was, and the test's annotations name what each state swept (`scroll sweep`: the scrollers and their number of positions, or "nothing scrolls"). The Tab round, the landmarks, the announcements and the text-spacing and reflow variants do not depend on the scroll position and run once.

`assertEscapeCloses` presses Esc in a popup state: the popup on top closes and the focus returns to the control that opened it. Forced colours and reduced motion run in their own projects (`e2e/a11y/`), with the layout checker.

## Coverage gate

- **90 % or more per file**, lines and branches, for every language; Vitest also enforces functions and statements (`perFile: true`, 90/90/90/90). Python uses branch coverage with `fail_under = 90` (`.coveragerc`).
- Scored the Sonar way: `(covered lines + covered conditions) / (lines + conditions)`. The `coverage` gate (`scripts/ci/check_coverage.py`, after Vitest and pytest in the `tests` stage) reads its scope from `sonar-project.properties`, fails on any file below the bar, a measured file missing from the reports, or a stale entry, and writes `reports/coverage/summary.md` and the coverage and branches badges in `.github/badges/`.
- Exclusions only for generated files or files without runtime behaviour; never to pass. Re-export-only `index.ts` files have no statements and count as covered.

## Conventions

- Tests live in `test/` beside `src/` (never colocated), so Sonar sources and tests stay disjoint.
- Names: `happyPath_…` / `badPath_…` in TypeScript, `test_happy_path_…` / `test_bad_path_…` in Python.
- Assert what the user sees (text, ARIA, a pixel probe, a recorded request), never only "no crash".
- No `.only`, `.skip`, `xfail` or skip markers; the suppression gate rejects them.
- A bug a test finds goes into [LESSONS.md](LESSONS.md).
