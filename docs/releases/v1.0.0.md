# Release v1.0.0 - The historic map engine, for every city

The first release of **Historic City Map**: the viewer engine that draws București dispărut, published so that any city can host its own historical map from three files, with the engine served by jsDelivr from this release's tag and pinned with Subresource Integrity. Version 1.0.0 is the v1 baseline of [the engine's public contract](../ENGINE_API.md): every 1.x release reads what this one reads.

## Highlights

- **A city in three files.** The starter kit (`templates/starter-kit/`: `index.html`, `city.json`, `README.md`) loads Mapbox GL JS 3.34.1 from api.mapbox.com and the engine from this release's jsDelivr folder, each with its integrity, under a strict Content Security Policy; `city.json` is the whole configuration. The page's own note stays visible when the engine cannot load, so a wrong version or integrity is visible, not silent.
- **The engine on jsDelivr.** The release commit holds the built engine in `cdn/engine/` with `release.json`, the size and SHA-384 integrity of every file; the GitHub Release body lists the pinned addresses and the tags to paste. `@1` follows the 1.x line for a page that does not pin integrity.
- **Starting a city with `create-historic-city`.** `npm create historic-city@1.0.0` scaffolds a city's folder with minimum input (`theme` recolours it from one colour, `upgrade` moves it to a later engine and keeps its own policy sources); its `self-host` command, experimental in this release, walks a city owner through a Firebase project of their own by running their own `firebase` and `gcloud`, one consent per step, and never sees a credential.
- **Many cities, one admin.** The admin manages several cities in one project, each closed to the admins of the others, with a guided New city (a name, a rectangle on the map, Create), a switch that publishes a city when it is ready, per-city admins and per-city shares of the budgets. A project's public map is served by Firebase Hosting at its root, with the admin at `/admin/`; GitHub Pages stays an option (each city at `/<city>/`, Bucharest at the root).
- **Setup with no terminal.** The admin's Setup Assistant takes a city owner from an empty Firebase project to a published map with buttons: Google billing and the budget, Provision (the APIs, service accounts, buckets and roles), Mapbox, USGS (or later), then **Install the server** and **Update the map**, which build and deploy the server, the imagery pipeline and the public map on the project's own Cloud Build.
- **Historical imagery, as free as possible.** Declassified USGS frames are found, ranked, bought or imported, georeferenced and published from the admin; each job runs on the owner's own computer (**Use this computer**: a starter file, no copy and paste) or on Cloud Run within its free tier, the raw delivery is deleted once the city crop exists, and a layer is published through Mapbox's free Uploads allowance when it fits.
- **The static export.** A city owner downloads the published city as a zip that runs from any static host: the kit's page with the engine beside it, `city.json`, the photos, a README and the rights of every photo licensed for this map only.

## The engine (v1)

- **The viewer** `<hcm-map-viewer>`: the map with the historical layers, photos placed with the direction the camera faced, points of interest in categories, a live opacity for every layer, the photos and each category, About, credits and privacy, Romanian (default) and English, light and dark themes, Material 3 Expressive on every window size from a phone to a wide desktop.
- **Swipe compare**: the map beside the same map with another historical layer, or with today's, split by a divider for the pointer and the keyboard; the second map exists only while comparing.
- **The JavaScript API** (`window.HistoricCityMap` from the IIFE, the same names from the module build): `ENGINE_VERSION`, `MAPBOX_GL_VERSION`, `mount`, `defineElements`, and the controller (`ready`, `setYear`, `toggleLayer`, `setOverlayOpacity`, `openPhoto`, `openPoi`, `setLang`, `openCompare`, `setComparePosition`, `closeCompare`, `setMapLabels`, `destroy`).
- **Map labels**: a visitor turns the basemap's street names and points of interest off and on in the Layers panel, live and with no new map load; a shared link keeps the choice (`labels=`), swipe compare follows it on both sides, and `setMapLabels` does the same from a page. A custom basemap without these properties offers no switch. A city's default is its `basemap.config` (`showRoadLabels`, `showPointOfInterestLabels`); the city's own place categories keep their own switches.
- **Events**: `hcm-ready`, `hcm-error`, `hcm-layer-change`, `hcm-overlay-change`, `hcm-photo-open`, `hcm-poi-open`, `hcm-compare-change`, `hcm-map-labels-change`.
- **`config.js`** (`manifestUrl` or an inline `manifest`, `cityId`, `container`, `lang`, `engineBase`), the element's attributes, the **URL hash v1** (view, layers, per-overlay opacity, compare, photo, language; the 2015–2022 site's links still open the same view) and the **City Manifest v1** with photos, layers, POI categories and POIs.
- **Errors a city owner can act on**: an invalid configuration or manifest shows its first problem with the field to fix; an engine older than a manifest's `city.engine.minVersion` says which engine the map needs.
- **Privacy**: no cookie and no analytics request before the visitor's consent; analytics and crash reports load only after it.

## The admin and the server

- **Setup Assistant**: Google sign-in, the billing account and a budget whose alarm pauses the imagery pipeline (never the site), Provision with a per-item doctor and Retry, the Mapbox secret token (the public tokens are minted from it), the USGS app token or **Do it later**, Analytics with its reports, push notifications; every step re-checkable.
- **Installing and updating from the admin**: the install bundle (server, pipeline, public map, the legacy photos) is built on the project's Cloud Build by its own installer account; **Update the map** appears once the admin is newer than what is installed and also brings Provision's changed items up to date.
- **Imagery**: the monthly USGS harvest and ranking, buying a scan with the order watch and its automatic import, the pipeline's steps (fetch, locate and crop, georeference with automatic suggestions against OpenStreetMap and Sentinel-2, warp, export) on three Cloud Run jobs sized to the step, the georeferencer, approval and publishing behind the compute-unit guard. A frame waiting for points can **Locate again** with no new import or download, and the Imagery list decodes USGS's huge browse images small.
- **Run on my computer**: the same pinned pipeline image in a `worker` mode, kept running by a service of the owner's user (systemd, a LaunchAgent or a Scheduled Task) that follows the installed image; the admin pairs it by itself and the raw scans never leave the computer.
- **Cheap cloud defaults**: this month's Cloud Run free-tier use is shown and a cloud run that would cross it waits for the owner's OK; the raw delivery is deleted after the crop (seven days at most).
- **Content**: photos, points of interest and layers editable with history and one-click revert; Nominatim and AI (Vertex AI Gemini) drafts of titles and translations; notifications in the admin and as web push.
- **Field measurements**: after consent only, the Core Web Vitals and the app's own timings and events of the viewer and the admin go to Google Analytics, each event checked against its app's strict list (no coordinates, addresses or identifiers), with the project's reports created by Setup; crashes go to Cloud Error Reporting.

## For city owners

- **Pin an exact version with integrity.** Copy the tags from the GitHub Release body (or `release.json`): the stylesheet and the deferred script of Mapbox GL JS 3.34.1, then the engine's `engine.css` and deferred `engine.iife.js` from `https://cdn.jsdelivr.net/gh/ventura8/bucurestiuldisparut.github.io@v1.0.0/cdn/engine/`, each with `integrity` and `crossorigin="anonymous"`. The IIFE carries swipe compare and the consented analytics inline, so the page needs no other script; the fonts come from the same folder.
- **Or follow 1.x** with `@1` instead of `@v1.0.0`, without integrity (the files change under it with every 1.x release).
- **Upgrading later**: a patch or minor release changes only the pinned folder and the two integrity values (`npx create-historic-city@<version> upgrade` rewrites them); a manifest that uses a field added after 1.0.0 names the engine it needs in `city.engine.minVersion`.

## Known limitations

- The self-hosted admin's Setup Assistant still expects the GitHub deploy settings that this repository's own project names in its `project.json`; for a project deployed from the owner's terminal with `create-historic-city`, the admin's Setup follows in a 1.x release (CR-M5-7). Without Setup's Provision the server's functions have no service accounts to run as, so `create-historic-city self-host` and `deploy` refuse unless `--experimental` is given, and even then stop being useful after step 6 (the static kit and the export are unaffected).
- A city's public site is a repository change (`npm run site:add`), committed and pushed by the repository's owner: the admin holds no GitHub credential.

## Breaking changes and migration

None: this is the first release of the engine, and every city starts at 1.0.0. București dispărut moves to Firebase Hosting (`https://bucurestiul-disparut.web.app/`, the admin at `/admin/`) and its 2015–2022 links still open the same view there; the GitHub Pages site can keep serving the map or be replaced by a tree of redirects to the same views on Hosting (`npm run build:site -- --pages-redirect`), the owner's choice.

## Security

- No HTML is rendered from data: Lit templates and `textContent` only; the manifest is validated strictly, and only https addresses and the URL-restricted Mapbox public token reach the page (a secret `sk.` token cannot pass the schema).
- The kit's page has a meta Content Security Policy with no inline script or style; every cross-origin script and stylesheet it loads is pinned with Subresource Integrity, and `release.json` holds the integrity of every released file.
- The release itself: the tag, every version, the released engine (rebuilt from the tagged sources and compared byte for byte), the kit's pins and this release's notes are checked by the read-only `release` stage before the GitHub Release is created by a job that runs no repository code.

## Verification

The release commit passes the full pipeline (`all`, split with the second machine) and, before the tag, `python3 scripts/ci/check_release.py --tag v1.0.0` and `npm run release:cdn -- --check`; the verdict lines of those runs are recorded here on the release commit, before the tag is pushed. On the tag, CI's `release` stage repeats the checks and rebuilds the engine.
