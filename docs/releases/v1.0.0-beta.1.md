# Historic City Map Maker v1.0.0-beta.1

The first beta of **Historic City Map Maker**, the engine rewrite: a data-driven historical map engine and a "do-everything" admin for any city. Old photographs sit on today's map with the direction the camera faced, beside vanished places, stories and historical imagery that is georeferenced and published as layers to compare with today's city. Example: **[București dispărut](https://bucurestiul-disparut.web.app/)** (Bucharest), the first map made with it, runs this code.

A beta is a pre-release. The engine's public contract ([../ENGINE_API.md](../ENGINE_API.md)) is the one v1.0.0 will ship, but it may still change in a breaking way before then. jsDelivr serves the engine only at this exact version (`@v1.0.0-beta.1`); no major line such as `@1` resolves to a pre-release. The GitHub Release is marked as a pre-release and never as the latest release. When `create-historic-city` is published to npm, a pre-release goes out under the dist-tag `beta`, never `latest`.

## What this beta contains

### The public viewer (`@hcm/engine`)

- `<hcm-map-viewer>` on Mapbox GL JS 3.34.1, which loads from api.mapbox.com and is never bundled, exposed as `window.HistoricCityMap` (IIFE) and as an ES module. It shows historical layers with a live opacity, photos placed with the camera's direction, points of interest in categories, a timeline that follows the layers and photos, stories, swipe compare (the second map exists only while comparing), map labels on or off, Show my location, zoom buttons, Romanian (default) and English, and light and dark themes. Material 3 Expressive adapts from a phone held upright to a wide desktop.
- The viewer reads a static `manifest.json` and the photos' WebP files, and never reads Firestore. Analytics and crash reports load only after the visitor's consent.
- `config.js`, the element's attributes, the URL hash v1 (the 2015–2022 links still open the same view) and the City Manifest v1, with errors a city owner can act on (the first invalid field, or "this map needs engine X").

### The admin and the Setup Assistant (`@hcm/admin`)

- The Setup Assistant takes a city owner from an empty Firebase project to a published map using buttons only: Google sign-in, billing and a budget whose alarm pauses the imagery pipeline (never the site), Provision (APIs, service accounts, buckets and roles, each with a doctor and Retry), Mapbox (the secret token is pasted once, and the public tokens are minted from it), USGS now or later, Analytics, and notifications.
- **No terminal**: **Install the server** and **Update the map** build and deploy the server, the imagery pipeline and the public map on the project's own Cloud Build. The public map is served at the root of Firebase Hosting and the admin at `/admin/`.
- Editors for photos, places, layers, stories, settings, history (with one-click revert), jobs and admins. Nominatim and local or Vertex AI drafts suggest titles and translations. Notifications appear in the admin and as web push.

### The backend (`@hcm/functions`, the security rules)

- Cloud Functions v2 written as pure handlers behind ports. Firestore and Storage rules deny by default and have an allow and deny matrix for every role. The server builds a manifest per city, and the public bucket serves it.

### Historical imagery

- **USGS**: the monthly harvest of declassified frames (KH-4 Corona strips searched along their length, KH-7, KH-9 mapping and panoramic) and their ranking, buying a scan with the order watch and its automatic import, and Landsat imported on its own for each year you want.
- **The raster pipeline** (Python and GDAL) fetches, locates and crops, georeferences against OpenStreetMap and open Sentinel-2 (never Mapbox Satellite), warps, and exports COGs and the project's own PMTiles. A KH-9 panoramic frame seen off nadir is fitted over the Copernicus DEM. A layer is published after approval, within the compute-unit guard.
- **The georeferencer**: automatic point suggestions, linked views of the scan and the map, markers identical on both sides, a second-order polynomial and a joint solve with the accepted frames a new frame overlaps. **Help calibrate** is a shared queue that every importer falls back to.
- **Calibration anywhere on Earth**: a frame is found and proved with no landmark, using votes, a proof and its gates. Frames that pass approve on their own.
- **Joins**: one date's frames are joined into a whole-city layer (`align`, `merge`, the date plan and the target years), and published frames can be joined too.
- **Seeing what you approve**: a layer's tiles come from the project's own bucket, so a version can be checked before and after approval. A published layer can be recalibrated, and a version that never reached the map can be deleted.

### Import of local files

- An archive of scanned maps on the owner's computer (zip, folders, PDF pages, atlases, pieces, grids) is imported and calibrated there. Pieces are chained by their overlaps and, when the archive holds a smaller-scale overview of the same year, they are laid on that overview first (**overview stitching**). The overview mosaic keeps a colour series in colour and a line-art series as line art on opaque white paper. Anything that cannot be placed waits in Help calibrate.

### Starting a map

- **The landing page** on GitHub Pages (<https://ventura8.github.io/historic-city-map-maker/>, in English and Romanian) says what Historic City Map Maker is. It links the start page, the terminal road at this release and the example map, and it sets no cookie and loads no script.
- **The start page** creates a new owner's map from a browser with Google sign-in: one consent, its own Google Cloud project, the map and its admin installed there, then the Setup Assistant. It handles failure and can resume.
- **The starter kit** is three files (`templates/starter-kit/`: `index.html`, `city.json`, `README.md`). It pins the engine from this release's jsDelivr folder with Subresource Integrity under a strict Content Security Policy.
- **`create-historic-city`** scaffolds a city with minimum input and has `theme`, `upgrade` and the experimental `self-host`. It runs only the owner's own `firebase` and `gcloud`, with a yes or no for each step.

### Many cities, roles and review

- Many cities live in one project, each closed to the other cities' admins. A city is created with three inputs (a name, a rectangle on the map, Create) and published when it is ready, with per-city admins and budgets.
- Roles: owner, editor, uploader and moderator. The review queue holds held pictures and the uploaders' stories, the Contribute page lets a visitor ask for a role, and the public can suggest a change to any photo.
- **The static export**: a city owner downloads the published city as a zip that runs from any static host without Firebase. It contains the kit's page with the engine, `city.json`, the photos, a README and the rights of every photo licensed for that map only.

### Run on my computer

- **The local worker** is the same pinned pipeline image in a `worker` mode. A service of the owner's user keeps it running, and the admin pairs it by itself. Raw scans never leave the computer, and jobs use the local GPU first, then the CPU. In the cloud, Cloud Run stays within its free tier unless the owner says OK. The raw delivery is deleted after the crop, and the daily cap counts only jobs that may run in the cloud.

## The engine on jsDelivr

The release commit holds the built engine in `cdn/engine/` with `release.json`, which lists the size and SHA-384 integrity of every file. jsDelivr serves it at `https://cdn.jsdelivr.net/gh/ventura8/historic-city-map-maker@v1.0.0-beta.1/cdn/engine/`. The GitHub Release body lists the pinned addresses and the tags to paste. The released engine writes lit-html's whitespace class with escapes instead of a raw tab and line break, so it holds no trailing whitespace. The string's value is unchanged ([../research/DECISIONS-for-review.md](../research/DECISIONS-for-review.md) §160).

## Breaking changes and migration

None. This is the first release of the rewrite, and every city starts at 1.0.0-beta.1. The legacy site is retired. The 2015–2022 hand-written page that `master` served on GitHub Pages is removed by this release, and the live map is <https://bucurestiul-disparut.web.app/> (Firebase Hosting, with the admin at `/admin/`), where the old links still open the same view.

The repository is now `ventura8/historic-city-map-maker` (it was `ventura8/bucurestiuldisparut.github.io`), and the product is named **Historic City Map Maker**. The npm names (`historic-city-map`, `@hcm/*`, `create-historic-city`), the `HistoricCityMap` global and the custom elements keep their names ([../research/DECISIONS-for-review.md](../research/DECISIONS-for-review.md) §161).

## Known limitations

- **This is a beta.** The engine's contract may still change before v1.0.0, and a page that pins `@v1.0.0-beta.1` keeps exactly this engine until it is moved to a later version (`npx create-historic-city@<version> upgrade`).
- **`create-historic-city` is not on npm yet.** The guides name `create-historic-city@1.0.0-beta.1`, which works only once the owner publishes the package (under the dist-tag `beta`). Until then, copy `templates/starter-kit/`. The start page's terminal road prints `npx create-historic-city@1 self-host`, and npm does not resolve a major line to a pre-release.
- **`self-host` is experimental.** The Setup Assistant cannot run yet in a Firebase project the CLI set up (CR-M5-7, [../SELF_HOST.md](../SELF_HOST.md)).
- **Not in this release yet**: the starter kit's GitHub template repository, the SonarQube gate of the tagged commit, `release.json` and the CLI's package attached to the GitHub Release, and the purge of jsDelivr's `@1` alias. Each waits for the owner (§58c, §58e, §58f).
- **Thresholds on real frames**: some calibration, join and seam thresholds were set on synthetic frames and a few real rehearsals. A frame that does not prove itself waits in Help calibrate rather than being published wrongly.
- A city's GitHub Pages site is a repository change (`npm run site:add`), committed and pushed by the repository's owner, because the admin holds no GitHub credential.

## Security

- No HTML is rendered from data: Lit templates and `textContent` only. The manifest is validated strictly, and only https addresses and the URL-restricted Mapbox public token reach the page (a secret `sk.` token cannot pass the schema).
- The kit's page has a meta Content Security Policy with no inline script or style. Every cross-origin script and stylesheet it loads is pinned with Subresource Integrity.
- Secrets are read at runtime from Secret Manager. Claude never types a credential, and the owner pastes each token into the Setup Assistant.
- The release itself: the tag, every version, the released engine (rebuilt from the tagged sources and compared byte for byte), the kit's pins and these notes are checked by the read-only `release` stage. Only after that does a job that runs no repository code create the GitHub Release.

## Verification

Before the tag, the release commit passes `python3 scripts/ci/check_release.py --tag v1.0.0-beta.1`, `npm run release:cdn -- --check` and the full pipeline (`all`, split with the second machine). On the tag, CI's `release` stage repeats the checks and rebuilds the engine.
